# Google Sheets — структурные таблицы (матрицы, критерии, оценки)

Как строить содержательные таблицы в Google Sheets через API (Sheets API v4 + urllib), когда стандартного `google-workspace` CLI недостаточно (например, RU-лист зовётся «Лист1», нужны примечания-notes к ячейкам, batch-форматирование). Это НЕ замена навыка `google-workspace` (там базовые get/update), а слой для структурных/матричных таблиц. Триггеры: «внеси в таблицу», «баллы по критериям», «критерии в гугл», матрица критерии×респонденты.

> Полные тексты питфоллов, моделей и примеров — `references/details.md`. Здесь — сжатые сути + рабоче-необходимый код.

## Прежде всего — доступ (OAuth)

```bash
GSETUP="python ${HERMES_HOME:-$HOME/.hermes}/skills/productivity/google-workspace/scripts/setup.py"
$GSETUP --check   # → AUTHENTICATED | TOKEN_REVOKED | REFRESH_FAILED
```

**`--auth-url` вызывать БЕЗ аргументов** — на this setup.py флаги `--services <..> --format json` дают `usage error: unrecognized arguments`. Просто `$GSETUP --auth-url` и отдать юзеру ссылку одной строкой.

Если `TOKEN_REVOKED`/`REFRESH_FAILED` — переподключить:
1. `$GSETUP --auth-url` → выслать юзеру ссылку одной строкой.
2. Юзер входит, копирует полный redirected URL (`http://localhost:1/?state=...&code=...` — показанная в браузере ошибка `localhost` НОРМАЛЬНА, токен не ломает).
3. `$GSETUP --auth-code "<полный URL/link>"` → `OK: Authenticated`.
4. Снова `$GSETUP --check`.

### ⚠️ КРИТИЧЕСКИЙ питфолл реавторизации — не перегенерировать ссылку
Pending OAuth-состояние (state + code_verifier) хранится в `~/.hermes/google_oauth_pending.json`; **каждый `--auth-url` перезаписывает его новым verifier**. Если вы снова запустили `--auth-url` ДО обмена уже присланного кода — старый `code` перестаёт совпадать с verifier, и `--auth-code` падает `ERROR: Token exchange failed: (invalid_grant) Invalid code verifier.` **Генерируй ссылку ОДИН раз → жди код → обменивай немедленно.** Если verifier уже сломан — свежая ссылка, юзер проходит заново (старый код мёртв).

### Когда доступ нужен, а OAuth зациклился — пусть юзер пришлёт файл напрямую
Если Google-токен протух, реавторизация ходит по кругу (код истёк / invalid verifier / сетевой SSL-обрыв), а нужен просто контент приватной таблицы/дока — **не блокируй задачу на Google**: попроси юзера прислать файл (xlsx/docx) прямо в чат. Он отправит вложение → читать через `openpyxl` (xlsx, `data_only=True`, каждый лист) или `pandoc -t plain` (docx). Это быстрее и надёжнее, чем ещё один круг OAuth. Таблицы из docx пандоком рвутся по колонкам — восстанавливать содержимое по смыслу.

## Токен
`~/.hermes/google_token.json` — `{"token": ...}` (или `access_token`). Для прямого API-запроса:
```python
token = json.load(open('/home/USER/.hermes/google_token.json'))
tok = token.get('token') or token.get('access_token')
```

## Имя листа — НЕ «Sheet1» на русских аккаунтах
В русскоязычном Google Sheet таб по умолчанию — **«Лист1»**, не «Sheet1»; `values/Sheet1!A1:Z100` → `400 Unable to parse range`. Всегда сначала получить имя листа:
```python
d = api("GET", f"https://sheets.googleapis.com/v4/spreadsheets/{SID}")
for s in d['sheets']: print(s['properties']['title'], s['properties']['sheetId'])
```
Подставлять реальное имя (url-encode через `urllib.parse.quote`).

## Прямой API (без google-workspace CLI) — urllib pattern

```python
def api(method, url, body=None):
    data = json.dumps(body).encode() if body is not None else None
    req = urllib.request.Request(url, data=data, method=method,
        headers={"Authorization": f"Bearer {tok}", "Content-Type": "application/json"})
    return json.load(urllib.request.urlopen(req))
```

### Записать двумерный массив в диапазон (overwrite)
```python
rng = f"{SID}/values/{urllib.parse.quote('Лист1!A1:G21')}?valueInputOption=RAW"
api("PUT", f"https://sheets.googleapis.com/v4/spreadsheets/{rng}",
    {"range": "Лист1!A1:G21", "values": rows})   # rows = list[list[str]]
```

### Примечание к ячейке (note) — описание «для справки», строка компактная
Реализуется через `batchUpdate` → `updateCells` с полем `note` (не трогая значения):
```python
req = {
  "sheetId": 0,  # из GET метаданных
  "startRowIndex": row-1, "endRowIndex": row,
  "startColumnIndex": 0, "endColumnIndex": 1,
  "rows": [{"values":[{"note": note_text}]}],
  "fields": "note"
}
api("POST", f"https://sheets.googleapis.com/v4/spreadsheets/{SID}:batchUpdate", {"requests":[req]})
```
Примечание — при наведении на ячейку; хорошо для «что именно оценивается / шкала».

### Форматирование в одном batchUpdate
- Жирный + заливка раздела: `repeatCell` с `fields: "userEnteredFormat.textFormat.bold,userEnteredFormat.backgroundColor"`.
- Ширины колонок: `updateDimensionProperties` (`dimension":"COLUMNS"`, `pixelSize`).
- Все форматы/примечания объединяй в ОДИН `batchUpdate` с массивом `requests`.

### ⚠️ batchUpdate форм-фактура (питфоллы)
`values().batchUpdate` НЕ существует → 400; `updateCells.range` — GridRange-объект (sheetId из `get()`, 0-based), не A1-строка; RGB — дробью (`217/255`), не целым; пустая ячейка фона читается через `rd.get('values',[{}])`. Полный текст + код построчной раскраски — `references/details.md`.

## Питфоллы
- **Русская локаль (ru_RU): разделитель аргументов формул — `;`, десятичная запятая — НЕ точка.** `=IF(1>0,"a","b")` → `#ERROR!`; `1.7` в USER_ENTERED парсится как дата (~46204) и взрывает расчёт. Формулы с `;`, десятичные с `,`. Проверять локаль: `GET /spreadsheets/{SID}?fields=properties.locale`. Полный текст — `references/details.md`.
- **После записи сетки формул читать ОБРАТНО контрольные ячейки** (первая строка, итог/окупаемость) и сверять с ожиданием — сдвиг блока параметров молча ломает `$B$9..`. Записал → прочитай 2-3 ячейки → отчитывайся.
- **Большие/кириллические массивы — через urllib PUT, НЕ `sheets update --values '<JSON>'`** (bash-склейка ломается на кавычках/длине). Сетку 100+ строк — **ОДНИМ PUT, не построчно** (иначе HTTP 429 посреди записи). Построчно — только для локализации виновной при 400.
- **Новый документ создавать явно:** `google_api.py sheets create --title "..." --sheet-name "Активные"` (имя таба известно заранее, не гадать «Лист1»).
- «Попадает в релиз» в выгрузке Jira = `fixVersions`, не customfield.
- **Доступ на корп. не-Google адрес (`@tutu.tech`) — только с `--notify`** (`$GAPI drive share <SHEET_ID> --email ... --role writer --notify`), иначе 400 «установите флажок Оповестить». Полный текст — `references/details.md`.
- **НЕ переиспользовать `i` цикла для вычисляемых ячеек** при сборке `rows` — `i` затирается и в `str(i)` уходит формула → `#REF!`, колонки смещаются. Использовать `mi` для месяца и `icol/jcol/kcol/lcol` для формул. Полный текст — `references/details.md`.
- **Заголовок таблицы и блок параметров — на РАЗНЫЕ строки** с явной пустой строкой; перекрытие → `#REF!` и битый MATCH. Параметры 1..N, таблица с N+3.
- **`.xlsx`-вложение не нативная Google-таблица** → `400 ... must not be an Office file`. Распознать по `mimeType` (`drive get`), скачать `drive download` + парсить zip (stdlib zipfile+ElementTree). Полный текст — `references/details.md`.

## Сводная таблица с декомпозицией (оценки работ) — формат Саши

Триггер: «собери оценки по подразделениям», «декомпозируй оценки», «сведи в таблицу и вышли ссылку». Проверено на Trisigma (02.09.2026): источники — Confluence-детализация + JIRA-задачи/комментарии + Loop-треды, сверху сводная страница с итогами по подразделениям.

**Правила формата (по исправлениям Саши):**
- **Отдельный лист** для декомпозиции (не расширять сводную вправо).
- **Каждая задача/блок = отдельная строка** (не сжимать подразделение с подстроками в одной ячейке).
- Колонки: `Подразделение | Задача | Оценка (дни) | Комментарий` — для переноса в Project как «Наименование — оценка в днях — комментарий».
- Под подразделением — жирное **ИТОГО** (сумма задач vs сводная из мастер-страницы): 🟥 «НЕ СХОДИТСЯ» / 🟢 «Сходится»; непокрытое помечать «не оценено», не выдумывать; частичное покрытие подсвечивать и объяснять в комментарии.

**Маппинг источников:** Confluence (`?expand=body.storage`) · Jira тело + **комментарии** (`/issue/{key}/comment`, оценка часто там) · Loop-тред: `pl/{post_id}` → `GET /api/v4/posts/{id}` → посты канала → восстановить по `root_id`/`parent_id`.

**Реализация подсветки (один batchUpdate):** найти строки `ИТОГО <подразделение>` по префиксу колонки B → по комментарию (`НЕ СХОДИТСЯ` vs `Сходится`) `repeatCell` с `backgroundColor`; шапки — строка, где заполнена только A; `row[i]` — с защитой от IndexError. Полный текст — `references/details.md`.

## Роадмап (GS) → план MS Project в GS (формат Саши)

Триггер: роадмап в GS (Инициатива | Описание | Статус (Internal/SaaS) | Ожидаемый релиз SaaS | Ожидаемый релиз On premise (VPC) | Комментарий на дату) → план для MS Project в GS по шаблону (`read-mpp`). Маппинг колонок (09.2026):

| Колонка плана | Из роадмапа |
|---|---|
| Название задачи | Инициатива |
| Дата начала | Ожидаемый релиз SaaS |
| Дата окончания | Ожидаемый релиз On premise (VPC) |
| % выполнения | Статус: Done→100, In progress→50, Backlog→0 |
| Текст1 | Описание |
| Текст2 | Комментарий |
| Ресурсы / Предшественники | пусто (роадмап не содержит) |

Структура **плоская** (длительность MS Project считает сам из дат). Колонки итога: `No | Название | % выполнения | Длительность | Ресурсы | Текст1 | Текст2 | Начало | Окончание | Предшественники`. Выдача — **новый GS-документ** (права на @tutu.ru и гугл-адрес, вернуть ссылку).

**Квартальные метки → даты:** без модификатора → 1-е/последний день квартала; `early`→конец 1-го месяца, `mid`→середина, `end`→последний день; диапазон `end Q3 - early Q4` → начало=конец Q3, конец=конец early Q4; `-`→пусто; **Deprioritized → самая поздняя дата плана** и в начало и в окончание (не пусто!). **Workflow-питфолл:** вопросы Саше — строго по одному за раз (OQ), не склеивать. Полный текст — `references/details.md`.

## Модель окупаемости / сравнение затрат (формат Саши)

Триггер: «помесячный план окупаемости», «сравни два сценария затрат», «когда окупится платформа/внедрение» → таблица с входными параметрами, помесячным расчётом и блоком чувствительности.

- **Обязательный первый шаг — не строить, пока семантика затрат не подтверждена:** собрать полную семантику по обоим сценариям (что разово/ежегодно/включено/параллельно), пересказать по-человечески, получить «да». Просьба Саши «повтори, как поняла» — сигнал к подтверждению, не к записи.
- **Ячейки-параметры + формулы:** вводные — отдельные изменяемые ячейки, производные — формула от них (B7=B4*B5*B6), чтобы пересчёт жил при смене вводных. Стоимость содержания = ставка×часы×FTE×12, не хардкод.
- **Структура:** блок параметров → блок результата (месяц+лет формулой `INDEX(MATCH("ОКУПАЕМОСТЬ"))`) → помесячная таблица (~15 лет: затраты А/Б, накопленно, разница, столбец-статус `=IF(AND(...);"ОКУПАЕМОСТЬ";"")`) → блок чувствительности по ключевому параметру → условное форматирование строки статуса зелёным.
- **Разовые суммы (внедрение вендора И доработку своей) — симметрично, блоком на месяцы**, не прятать в смешанной колонке (Саша спросит, какие столбцы сложить).
- **Crossover TCO ≠ «окупаемость вложений»** — подписывать честно, объяснять, что закрыто к месяцу.
- **Прожарка архитектором — критический шаг, не опция**; после правок вводных — тот же `--resume`, не перегенерировать.
- **Оформление на ОДНОМ листе** (комментарии-расшифровки ниже таблицы, не отдельным листом «Комментарии»); два варианта — на отдельных вкладках, вводные — на отдельном листе «не трогать» (не изменять, проверять метаданные).

Полная модель с цифрами (примеры 1 152 000/4 млн/18 705 000/6 342 000, декомпозиция по ролям, COUNTIF первого пересечения, «не окупается за 15 лет») — `references/details.md`.
