Bootstrap на 501 реальной встрече показал 197 unclear (39.3%).

## Вывод A: баг в b_router.py — НЕТ

Код содержит «расширенный Шаг 1» (строки 233–249):
```python
# real_n ≤ 1 и есть ≥1 алиас → route=project
if real_n <= 1 and n_proj >= 1:
    pkg.route = Route.PROJECT
```

Выполняется ДО Route.UNCLEAR. Прогон по 501 встрече: `UNCLEAR with alias and real_n<=1: 0`.

Ложное впечатление о баге возникло из-за `explain_unclear()` в bootstrap.py,
которая перечисляла ВСЕ применимые причины, а не одну решающую.

|---|---|---|

## Вывод C: проблемы по модулям

### БЛОКЕРЫ

**A: ff_parser теряет участников**
- `participants_raw=[]` для большинства встреч из NewMeetings
- Секция «Участники» в реальных FF summary: нестабильна, часто пустая
- Это реальная причина 197 unclear (не баг роутера)
- Решение: улучшить парсинг ff_parser + fallback даты из имени файла

**B: Таблица имён не реализована**
- ТЗ B описывает хардкод «Кирилл→kkrivorotov, Илья→isereda» из брифа 21.06
- В коде: grep по kkrivorotov, hierarchy_hint, reports_to → 0 совпадений
- Без этого все «1-1 Кирилл» теряются (unclear вместо route=1on1)
- Решение: реализовать через tutu-contacts.md aliases (чище чем хардкод в B)

### ВАЖНЫЕ

**B: negative_keywords блокирует весь проект**
- Текущее: любое слово из negative_keywords → весь проект выкидывается
- Должно быть: negative блокирует конкретный алиас, не весь проект
- Риск: «антибиотик» в списке negative → antibot никогда не матчится

**B→TZ: route_project_slug не заполняется**
- ТЗ B описывает парсинг «1-1 Кирилл / antibot» → route_project_slug=antibot
- В b_router: ни на одном пути 1on1 поле не выставляется

**B: pre_classify (Шаг 1.5) — в ТЗ есть, в коде нет**
- ТЗ описывает вызов C.pre_classify() между Шагами 1 и 2
- c_extractors.py имеет pre_classify (строка 174), но из B не вызывается
- Решение: либо реализовать в F после B при low confidence, либо пометить «Фаза 9»

**F: дата в unclear_queue пустая**
- explain_unclear() не извлекает дату встречи
- Решение: fallback на первые 10 символов имени файла (YYYY-MM-DD)
