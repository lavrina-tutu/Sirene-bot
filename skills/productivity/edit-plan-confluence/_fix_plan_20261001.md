## ROOT CAUSE

### Баг 1 (критический) — план не отображается в gantt-chart-planner («No records to display»)

**Файл:** `scripts/mpp_convert.py`, функция `build_event_tree`, строки 64–89.

**Механизм.** Фильтр входных строк отсекает только пустой `id` и `id == "0"`:

```python
rows = [r for r in tasks if r.get("id") and r["id"] != "0"]
```

Дальше стек собирает дерево по `outline_level`. Если `stack` пуст — текущий узел становится `root` (строки 85–88).

Выход MS Project / `read_mpp.py` может содержать **служебную строку-шапку** с `outline_level=0` и **настоящим id** (не `"0"`). На воспроизведении: `id=217`, `outline_level=0`. Она проходит фильтр.

Два порядка в CSV дают два видимых симптома:

1. **Шапка первая** (воспроизведено на синтетике поверх фикстуры 080926): `stack` пуст → шапка = `eventsData[0]`; реальный корень `id=1` (`outline_level=1`) становится её единственным ребёнком. `count_tasks` = 34 вместо 33. Плагин видит корень-шапку, не дерево плана.
2. **Шапка не первая:** при обработке `outline_level=0` стек полностью выталкивается (`while stack and stack[-1][0] >= 0`), `root` **перезаписывается** шапкой, уже собранное дерево остаётся на прежнем объекте и **не попадает** в `eventsData[0]`. Корень — шапка **без детей** → «No records to display» / `eventsData[0]` фактически пуст.

Фикстура `tests/fixtures/ab_080926_пункт12__tasks.csv` баг **не ловит**: шапка там `id=0, outline_level=0`, её уже отсекает `id != "0"`. Тесты `root["id"] == 1` / `count_tasks == 33` зелёные на этой фикстуре и красные не будут, пока нет строки с `outline_level=0` и `id != "0"`.

**Асимметрия с «Итого».** `compute_itogo_from_csv` (`itogo.py:39`) уже ищет `outline_level == "1"` и `id != "0"` — даты/N блока «Итого» с шапки не берутся. Фильтра `outline_level > 0` нет только в сборке дерева.

**Где фильтровать: дерево vs `rows`.** `build_event_tree` возвращает `(root, rows)`. `rows` в `convert_mpp_csv` идут в:

- `max_used = max([int(r["id"]) for r in rows] + …)` (`mpp_convert.py:266–271`);
- `build_dependencies(rows, flat, …)` (`mpp_convert.py:272`).

`build_assignments` смотрит `assignments.csv` × `flat` (дерево), не `rows`.

Решение: **фильтровать в одном месте — при сборке `rows`** (`outline_level > 0` вместе с `id`/`id != "0"`). Тогда:

- служебная строка не становится `root` и не попадает в `children`;
- `flat` не содержит её id → `build_dependencies` не создаст связь `from`/`to` на шапку (сейчас при `predecessors` у шапки и шапке-в-дереве связь **создалась бы**: `p in flat and tid in flat`);
- назначение на `task_id` шапки и так отсекается `eid not in flat` **после** исключения из дерева; держать шапку в `rows` незачем;
- `max_used` не раздувается служебным id (безвредно, но лишнее).

Фильтровать «только стек, а `rows` оставить» — хуже: один источник правды ломается, ложная зависимость возможна, пока шапка в дереве; после исключения из дерева `flat`-гейт зависимости почти спасает, но это второй слой, не причина.

`cli.py` / `pipeline.py` в баг 1 не входят: оба зовут `convert_mpp_csv` → `build_event_tree`.

### Баг 2 — строка «Трудозатраты: N человек-часа» в блоке «Итого»

**Файлы:** `scripts/itogo.py` — `build_itogo_html` (72–75), `patch_itogo` (78–93), `apply_itogo` (100–106).

**Механизм.** Канон кода и master-ТЗ §9 сейчас — **две** жирные строки. `build_itogo_html` всегда пишет line2. `patch_itogo` при наличии обеих строк **обновляет** Трудозатраты через `ITOGO_LINE2_RE`, а не удаляет. `apply_itogo` при наличии `ITOGO_LINE1_RE` делегирует в `patch_itogo` (старая line2 живёт); при отсутствии line1 вставляет полный двухстрочный HTML.

Требование пакета: над макросом **только**  
`Итого: с DD.MM.YY по DD.MM.YY - N рабочих дней`.  
Строку Трудозатраты не создавать и **удалять из storage**, если уже есть.

`m_hours` из `compute_itogo_from_*` можно оставить в кортеже и в сигнатурах (гейт-дифф `gate_diff.py:52` показывает `{m} ч-ч` — это текст гейта, не storage; в этот пакет не входит).

**Да, `apply_itogo` / `patch_itogo` должны удалять старую строку Трудозатраты.** Иначе повторный `apply` на живой странице с двухстрочным блоком оставит millениум-строку навечно. Удаление — часть фикса, не follow-up.

Дополнительный дефект текущего `patch_itogo`: ветка патча срабатывает только если **есть и line1, и line2**. Есть только line1 → функция **препендит** новый блок → дубликат «Итого:». После фикса: line1 обновлять всегда, если есть; line2 всегда вырезать.

- есть непустой `id`;
- `id != "0"`;

Парс уровня — безопасный (`int(float(raw))`, пустое/мусор → 0 → отброс), чтобы `int("1.0")` / пустой `outline_level` не роняли конвертер.

Не менять сигнатуру `build_event_tree`. Не фильтровать отдельно во втором проходе стека: достаточно узкого `rows`.

## Риски / edge cases

| Риск | Что делать |
|---|---|
| Не все MPP дают шапку `outline_level=0` | Фильтр идемпотентен: фикстура 080926 (`id=0`) и файлы без шапки не меняют дерево |
| Шапка с **ненулевым** id (217 и аналоги) | Собственно баг 1; закрывается тестом П.2 |
| Шапка не первая в CSV | `root = node` перезаписывает корень → пустой гант; тот же фильтр; желателен второй assert в П.2 |
| Нет ни одного `outline_level>=1` | Уже `ValueError`; не глотать, не подставлять шапку как корень |
| `outline_level` пустой / `"0.0"` / нечисло | Парс → 0 → отброс; не `int("")` |
| Несколько узлов `outline_level=1` | Поведение стека как сейчас (не этот баг): первый level=1 = корень, следующие level=1 выталкивают стек и **перезаписывают** `root`. Не расширять скоуп |
| Предшественник на id шапки | После фильтра `p not in flat` → связь не создаётся (верно: в дереве нет узла) |
| Назначение на `task_id` шапки | `eid not in flat` → skip; `effort` шапки в JSON не нужен. Сумма work в `compute_itogo_*` по всем assignments **не меняется** (строка M из HTML уходит) |
| Трудозатраты без `<strong>` / без `<p>` / «человеко-часов» / NBSP | Расширить вырез; минимальный контракт — канон `<p><strong>Трудозатраты: N человек-часа</strong></p>` |
| Только line1, без line2 | Обновить line1, ничего не добавлять |
| Только line2, без line1 | Вырезать line2, вставить line1 над макросом |
| Хвост 70% | По-прежнему не трогать (уже в `test_patch_existing_itogo`) |
| `m_hours` unused | Оставить аргумент; не плодить `_m_hours` в call-site |
| `count_tasks` в диффе | После фикса считает 33, не 34 — гейт станет правдивее без правки `gate_diff.py` |
