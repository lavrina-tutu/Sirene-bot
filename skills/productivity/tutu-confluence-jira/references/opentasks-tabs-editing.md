# Правка дашборда задач OpenTasks (tabs-group / tasks-report-macro)

Страница: OpenTasks, pageId=492610494 (`/display/~tkachenkoav/OpenTasks`, space `~tkachenkoav`).
Проверено на кейсе 11.11.2026 (переименование «Саша А»→«Леня», удаление вкладок Trisigma и Опер.Аналитики, «Техблок»→«Прочие» с фильтром «все пользователи», перемещение в конец).

## Структура

- Весь дашборд — один макрос `<ac:structured-macro ac:name="tabs-group">` (параметр `disposition=horizontal`).
- Внутри — вкладки `<ac:structured-macro ac:name="tab-pane">`: параметры `anchor` (стабильный числовой id вкладки) и `name` (заголовок вкладки).
- Внутри каждой вкладки 1–2 макроса `<ac:structured-macro ac:name="tasks-report-macro">` (нативный Confluence Server Reporting Plugin, **не Jira**):
  - `spaces` — области через запятую (`DPAN,PMO,analytics`);
  - `labels` — метка (везде `_aid`);
  - `assignees` — исполнители: один или несколько `<ri:user ri:userkey="..."/>`; **отсутствие параметра = все пользователи** (проверено 11.11.2026);
  - `status=complete` — второй макрос (DONE); без параметра — только активные;
  - `pages` — опционально, конкретная страница-источник.
- Надписи «ACTIVE»/«DONE» внутри вкладки — обычные `<p>`, не параметры.

## Парсинг вкладок

- `tab-pane` содержит вложенные `tasks-report-macro` → конец макроса искать **счётчиком глубины** `<ac:structured-macro>` / `</ac:structured-macro>`, НЕ по первому `</ac:structured-macro>` (он принадлежит вложенному макросу).
- Значения параметров могут содержать вложенную разметку (`assignees` = `<ri:user .../>`) → содержимое параметра брать до `</ac:parameter>`, не regex `[^<]*`.
- Вкладку идентифицировать по `name` (или macro-id); `anchor` — стабильный id.

## Алгоритм правки

1. GET `?expand=body.storage,version` — свежая версия (страницу регулярно правят руками).
2. Границы tabs-group: start = `<ac:structured-macro ac:name="tabs-group"`, end — счётчиком глубины.
3. Разобрать все tab-pane (start/end каждого).
4. Операции:
   - **Переименовать:** заменить `<ac:parameter ac:name="name">Старое</ac:parameter>` → новое.
   - **Сменить исполнителя:** заменить `ri:userkey` внутри `assignees`. Резолв userkey: `GET /rest/api/user?key=` (обратный — по userkey), поиск по ФИО — CQL `user.fullname~"Фамилия"` (кириллица через `--data-urlencode`).
   - **Удалить вкладку:** вырезать pane целиком (от `<ac:structured-macro ac:name="tab-pane"` до конца по глубине) вместе с разделителем.
   - **«Все пользователи»:** удалить параметр `<ac:parameter ac:name="assignees">...</ac:parameter>` целиком.
   - **Переместить в конец:** вырезать `pane_text`; вставить ПОСЛЕ последней панели внутри группы, ПЕРЕД хвостом (закрывающим `</ac:rich-text-body></ac:structured-macro>` группы):
     `body_new = b[:last_inside_end] + pane_text + b[last_inside_end:ps] + b[pe:]`
     где `ps..pe` — позиции вырезанной панели, `last_inside_end` — конец последней панели внутри группы.
5. PUT: `title` + `type:page` + `version.number+1` + `body` (без `space`).

## Питфоллы

- **Перемещение в конец: НЕ вставлять после хвоста.** Ошибка 11.11.2026: `b[:last_inside_end] + pane_text + b[pe:]` — панель оказалась ПОСЛЕ закрытия tabs-group, PUT вернул ok, но рендер сломался (контент отдельным блоком под вкладками). Хвост (закрытие группы) лежит в сегменте между последней панелью и внешней панелью — его нельзя выбрасывать.
- **`body.view` рендерит только активную (первую) вкладку** — неактивные грузятся JS, проверить их рендер через REST нельзя. Проверять структуру повторным GET: все tab-pane внутри границ tabs-group (outside == []), порядок, параметры.
- **Браузер с ВМ упирается в SSO keycloak** (keycloak.tutu.ru) — глазами из сессии не проверить; итоговую живую проверку делает Саша (открывает страницу, кликает вкладки).
- **Слово в body.view ≠ вкладка:** «Trisigma» в рендере может быть названием задач внутри таблиц — проверять вкладки по storage, не по view.
- displayName может быть «Неизвестный пользователь (login)» (уволенные/архивные) — login в скобках валиден для замены assignees.
