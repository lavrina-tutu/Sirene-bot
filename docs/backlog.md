## 🚀 Быстрая постановка задачи через TG (высокий приоритет)

**Схема:**
```
Ты наговариваешь задачу голосом/текстом
→ Я показываю: кому / что / срок
→ Задаю два вопроса:
   1. К какой цели департамента относится? (OKRAID)
   2. К какому проекту? (OKRS)
→ Ты подтверждаешь или правишь
→ Публикую в Jira
```

**Важно:** диалог нативный — я задаю вопросы по одному, ты отвечаешь голосом. Быстрее чем писать в Confluence.

**Источники целей:**

### Решения принятые в диалоге (22 мая 2026)
- **Actions.md не качать** — дублирует Action Items из summary, нулевая доп. ценность
- **Качать только: summary + transcript**
  - Summary — основной рабочий материал (структурирован, компактный, ФИО полные)

- **Обработку summary → сущности делаем своими моделями** (Opus), не FF

## Главные цели системы (зафиксированы 22 мая 2026)

### Цель 1 — Задача доходит правильно
Чёткая формулировка + правильный исполнитель + срок.
**Лучше уточнить чем опубликовать неправильно.**

### Цель 2 — Риски выявляются рано
Из реальных данных, до того как стало поздно. PMBOK-подход.

### Принцип публикации (ЖЕЛЕЗНОЕ ПРАВИЛО)
Система **никогда не публикует задачи автономно** в Jira, мессенджеры и публичные каналы.
Только через человека:
1. Система нашла задачу → пишет в TG для подтверждения
2. Пользователь подтверждает или правит (в т.ч. резолвит сущности)
3. Только после подтверждения → публикация

Это же решает проблему ambiguous сущностей — не нужны флаги в YAML, человек смотрит сам перед публикацией.

## Финальная цель системы — управление рисками на основе реальных данных

После того как сбор и структурирование информации по проектам заработает автономно:
- Подключить методологию PMBOK (реестр рисков, триггеры, ответные меры)
- Система выявляет риски **автоматически** из реальных данных — не придуманные на старте, а сигналы из потока информации
- Источники сигналов: просроченные задачи (Jira), напряжённость в коммуникациях (Zulip), изменения в повестке встреч (FF), паттерны в почте (Exchange)
- На выходе: реестр рисков с ранними триггерами + предложения по мерам предотвращения
- **Риски оперативные** — сегодняшнего дня, не долгосрочное прогнозирование
- **Возможности = риски со знаком плюс** — подсвечивать наравне с угрозами
