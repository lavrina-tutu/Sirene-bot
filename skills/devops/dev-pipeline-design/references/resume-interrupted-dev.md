# Resume прерванной разработки (архив ветки + сохранённый каркас)

Как восстановить разработку инструмента, ветка которого была заархивирована (например, при остановке теневой/параллельной ветки).

## Контекст (кейс 08.09)
Инструмент «обогащение контактов из Exchange» (`exchange-contact-upsert`) остановлен 07.09: ветка заархивирована, но ценное уже сделано (каркас ТЗ архитектором). Люди/модели часто НЕ фиксируют мастер-ТЗ на диск — держат в сессии. Поэтому при «продолжим разработку X» — процедура восстановления.

## Процедура
1. **Собери факты из канбана** (`~/.hermes/kanban.db`): карточки по title (`where title like '%X%'`), их статусы (archived/done), и `task_runs.summary` ключевых фаз (что реально сделано — compress/analyze/architect/plan).
2. **Проверь диск**: есть ли master-ТЗ (`TZ/<Tool>/<Tool>_TZ.md`), версии; есть ли сохранённые `appendix_*.md` с каркасом; нет ли «утечки» кода (черновики на диске от теневой ветки).
3. **Уточни классификацию по новому канону** (GLOSSARY §2): это часто **CHANGE** (доработка существующего), а не DEV. Один корень на весь контракт, не дробись.
4. **Отдай архитектору** (cursor-grok-4.6-high) задачу: проанализировать этап + предложить план продолжения по новому процессу (кейс, цепочка блоков, шаги по порядку, риски).
   - Ключевые вопросы архитектору: что есть/чего нет на диске; мастер-ТЗ версии; бриф нужен полный или достаточно appendix; включать ревизора; one-pass ли.
5. **Разверни ТЗ на диск** (`TZ-WRITE`): секции v0.3.0 в master-файлы + bump версии + инвентарь. Код НЕ трогать.
6. **Гейт «берём в работу»** — явный, перед кодом, даже в one-pass.

## Pitfalls при resume
- **Черновики на диске от теневой ветки ≠ готовый код.** store.py/тесты с сырой логикой — «заменить целиком», не принимать за реализацию, не пропускать ТЗ/план.
- **Не воскрешать архивные карточки** с устаревшими фазами (TZ:analyze/TZ:architect). Создавать НОВЫЙ граф по канону.
- **Не финализировать только один инструмент** из двух, если контракт общий — разъедется.
- **Проверять на диске, не self-report** — архитектор/исполнитель часто говорят «сделано», а мастер-ТЗ так и не записан.
- Ветка останавливалась «до TZ:finalize» — каркас есть, записи нет: восстанавливать каркас из appendix, не гадать.

## Полезные команды
```bash
# факты из канбана по инструменту
python3 -c "import sqlite3;c=sqlite3.connect('~/.hermes/kanban.db'.replace('~','$HOME'));cur=c.cursor();[print(x) for x in cur.execute(\"select id,title,status from tasks where title like '%X%'\")]"
# версии мастер-ТЗ
grep -E '^version|Exchange upsert' TZ/<Tool>/<Tool>_TZ.md
```
