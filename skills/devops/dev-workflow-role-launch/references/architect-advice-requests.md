# Запрос рекомендаций/вердикта у архитектора (точечно, вне канбана)

Класс задач: развилка или вопрос, требующий решения Саши, — рекомендации берутся у
архитектора, а не придумываются оркестратором. Также: адресная правка нормы по вердикту.

## Правило владельца (Саша, 15.11.2026)

«Рекомендации архитектора: если ко мне вопросы, сирень не дает рекомендации, а только
запрашивает их у архитектора, передавая полный контекст».

- По развилкам, требующим решения Саши, рекомендации НЕ давать самому — запросить у
  архитектора с полным контекстом и показать Саше рекомендации архитектора.
- Это отдельное правило от «оркестратор не занимается исследованиями»: здесь не
  исследование, а авторитет рекомендации для решения владельца.
- Свои вердикты/предпочтения в материал, показываемый Саше, не подмешивать.

## Механика запроса ADVICE (поезд вне канбана, direct codex)

1. Собрать промпт-файл `/tmp/arch-<tema>.md`: что готово/осталось, вердикты
   PREP/ADVICE, пути к логам, формулировки вариантов, обязательный формат выхода
   (план по шагам + «вопросы к Саше с рекомендацией»). Пометить задачу read-only.
2. Запустить фоново:
   ```bash
   codex exec -C <D> -m gpt-6-astra -c 'model_reasoning_effort="high"' \
     --skip-git-repo-check --json --sandbox danger-full-access -- "$(cat /tmp/arch-<tema>.md)" \
     > evidence/ARCH-<TEMA>.arch.log 2>&1
   ```
   С tool-полями `background=true, notify=true, persist_on_release=true`.
   Рабочая директория — каталог поезда, чтобы архитектору были доступны относительные
   пути к `out/`/`evidence/`. Модель/effort брать из `tools.dev_workflow.roles`
   (architect = gpt-6-astra; effort high, thick xhigh).
3. После notify распарсить JSONL-лог: строки `item.completed` с
   `item.type == "agent_message"` собирают текст вердикта; `turn.completed` — конец.
   Не читать весь лог глазами — фильтровать по типу в коде.
4. Сохранить человекочитаемый вердикт в `out/ARCH-<TEMA>.md` (по механикам поезда —
   это out-артефакт, не evidence; evidence = сырой лог).
5. Показать Саше кратко по пунктам с рекомендациями архитектора, ссылку на out-файл.

## Адресная правка контракта после вердикта (когда кандидат уже реализовал новую версию)

Ситуация: вердикт архитектора меняет формат контракта (напр. receipt `/1.0:` → `/1.1|`),
кандидат уже на новой версии, а норма поезда (`out/HF-plan-*.md`) осталась на старой.
Саша выбрал «поправить контракт» — тогда:

- Править норму во ВСЕХ местах сразу: тип/структура, строка формата, regex (grep по
  старой сигнатуре — их обычно 3, легко пропустить regex отдельно).
- Бампнуть `version` во frontmatter + строка об адресной редакции (что именно изменено,
  чей вердикт, решение Саши).
- Синхронизировать таблицы допуска, где зашит enum (напр. PREP-01-ADMISSION.md) —
  иначе допуск разойдётся с нормой.
- Написать evidence-файл (CONTRACT-PATCH-*.md): что изменено, что кандидат не менялся,
  живой прогон поднабора тестов, список остатков старой версии = 0.
- Кандидат не трогается, если уже соответствует вердикту; старые версии формата
  остаются историей, не переписываются.
- Проверить поиском, что в норме не осталось старых упоминаний (`receipt/1.0` → 0).
