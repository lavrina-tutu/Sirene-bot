## Вопрос 1 — Старшинство PM Notes vs свежая встреча

**Решение PM:** хронология побеждает. Более свежий срез (новая встреча) перекрывает более раннюю PM Note. Если контекст из новой встречи неверен — PM переопределит через PM Notes нового среза.

**Алгоритм:**
- Обработка идёт от старого к новому (хронология)
- PM Note среза N применяется к карточке
- Если срез N+1 содержит информацию, противоречащую PM Note среза N — победитель срез N+1 (он свежее)
- Конфликт-пометки НЕ вводим — PM сам перепишет в новом PM Notes если надо

## Вопрос 2 — Архитектура Шага 1

**Решение PM:** Вариант B — отдельный модуль `pm_notes_reconciler`, вызывается F-оркестратором первым шагом. Плюс возможность ручного запуска по конкретной встрече/проекту.

**Ключевое уточнение:** обрабатывать только те блоки карточки, в которых PM Notes **реально изменился** с последнего применения. Если изменений нет — no-op (без LLM-вызовов, без записи). За 5 дней может быть полностью нулевая работа агента.

**Алгоритм:**
- `pm_notes_reconciler` проходит по срезам в окне N дней (от старого к новому)
- Для каждого среза: сравнивает хэш блока PM Notes с ранее применённым хэшем из `state.json`
- Хэш не изменился → skip (no agent work)
- Хэш изменился → Haiku читает обновлённый PM Notes + текущий контент блока карточки → применяет изменения → сохраняет новый хэш в `state.json`
- Ручной запуск: `--only-pm-notes <snapshot_file | slug>` — без ограничения окна

## Вопрос 3 — Детект изменений PM Notes (гранулярность хэша)

**Решение PM:** хэшировать каждый блок `<!-- pm: -->…<!-- /pm -->` отдельно, привязка к `(snapshot_path, block_index)`.

**Структура в state.json:**
```json
"pm_notes_hashes": {
  "Projects/trisigma/snapshots/trisigma-snapshot-2026-01-01.md": {
    "0": "sha256:abc...",
    "1": "sha256:def..."
  }
}
```

**Следствие:** один изменённый блок → обработка только соответствующего раздела карточки. Правка соседней секции среза (не PM Notes) — не триггерит агента.

**PD:** PD-051

## Вопрос 5 — Полномочия PM Notes (операции над карточкой)

**Решение PM:** четыре типа объектов (задачи, решения, риски, комментарий), для каждого из первых трёх — полный CRUD.

**Матрица операций:**

| Объект | Создать | Изменить | Отменить/удалить |
|--------|---------|----------|-----------------|
| Задача | + (текст, owner, срок) | + (owner, срок, суть) | + |
| Решение | + (текст) | + (уточнение/исправление) | + (зачёркивание) |
| Риск | + (текст) | + | + (закрыть/смягчить) |
| Комментарий | + | — | — |

**Примеры формулировок в PM Notes:**
- «добавить задачу: Кирилл готовит спецификацию к 15.07»
- «задача X — сдвинуть срок на 20.07, ответственный Юрий»
- «задача X — отменить»
- «решение про Y — неактуально»
- «добавить риск: вендор задерживает поставку»
- «риск Z — снят»
- «контекст: встреча была формальной, сигналы не учитывать»

**Что Haiku делает с непонятным:** логирует в дайджест PM, не применяет молча.

**PD:** PD-052

## Вопрос 6 — Гранулярность применения PM Notes к карточке
