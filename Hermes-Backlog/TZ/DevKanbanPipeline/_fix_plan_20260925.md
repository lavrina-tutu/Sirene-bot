## 1. Вердикт

Не баг ядра канбана, диспетчера и воркера. Не «агент сделал работу, но не закрыл run».

**Root cause:** на фазах архитектора/ревизора в `model_override` записан slug **нативной
модели Cursor CLI**. Диспетчер честно передаёт его как модель **самого Hermes-воркера**
(`hermes chat -m …`). Tutu-шлюз (OpenRouter-совместимый) отвечает HTTP 400 non-retryable
→ воркер abort на 1-м LLM-вызове (0 tool calls) → `rc=0` без terminal-вызова → диспетчер
классифицирует `protocol_violation` и ретраит до `gave_up`/`blocked`.

Лечить на постановке (канон + скиллы + операторка живых карточек). Ядро `~/hermes-agent`
в этом цикле **не** менять.

## 3. Что исключено

- Ядро/диспетчер/протокол complete — нет: воркер умер до 1-го tool call.
- «Агент сделал работу и забыл закрыть» — нет: 0 tool calls.
- Контекст/таймаут — нет: 8–9s.
- Cursor CLI как рантайм воркера — нет: спавн native `hermes chat`; `agent` не вызывался.
- Конфликт диспетчера — нет: `protocol_violation` истинный.
- «Добавить cursor-grok в allowlist tutu» / «смапить на `x-ai/grok-4.6`» — **запрещено**: другой продукт (Cursor-подписка vs OpenRouter grok), семантика роли сломается.
