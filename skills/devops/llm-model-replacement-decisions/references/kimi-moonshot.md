# Kimi / Moonshot для агентного контура (справка по моделям и трекам)

Разбор 11.2026. Два разных трека — не смешивать ключи (401/403 при перепутывании).

## Два трека

1. **Kimi Platform (Developer API, pay-as-you-go)** — `api.moonshot.ai/v1`, ключ `MOONSHOT_API_KEY`, OpenAI-compatible. Оплата за токены. Ключи с платформы НЕ работают в подписке.
2. **Kimi Code (membership-подписка)** — для терминальных кодинг-агентов. Свои ключи, свои лимиты. Эндпоинты OpenAI `api.kimi.com/coding/v1` и Anthropic `api.kimi.com/coding/`. Модели: `k3`, `k3-256k`, `kimi-for-coding`, `kimi-for-coding-highspeed` (+ на новых планах `k3.1-pro`, `k3.1-pro-highspeed`).

## Модели (актуально на 11.2026)

Platform, OpenAI-compatible, все с tool-calling/streaming/JSON/reasoning_effort (low/high/max):
- `kimi-k3.1-pro` — флагман, контекст 1M, $2/(вх) $10/(вых) прямого Moonshot API. Поддерживает reasoning_effort.
- `kimi-k3.1-pro-highspeed` — скорость, ~вдвое больше квоты/расхода.
- `kimi-k3` — пред. флагман, 1M, $3/$15.
- `kimi-k2.6` — general 256K.
- `kimi-k2.7-code` — **закрыт для новых пользователей Platform, отключение конца декабря 2026** — для новых архитектур исключить.

Цены OpenRouter (= НЕ тариф прямого Moonshot API, только сравнение): k3.1-pro $0.24/$8.4, k3 $0.19/$16, k2.7-code $0.6/$3 за 1M.

## Ключевое ограничение подписки (решающее для Hermes)

Подписка Kimi — **личное интерактивное использование только** (Community Guidelines). Запрет касается НЕ только cron: самостоятельные пакетные запуски, неинтерактивные цепочки (DevWorkflow, фоновые фазы) тоже подпадают. Успешный запрос после подмены User-Agent НЕ доказывает допустимость. Ни Pro, ни Max это не снимают.

- Kimi официально подключает Hermes (есть инструкция в доках) — так что «Hermes точно получит 403» НЕВЕРНО.
- Pro даёт до 1M контекста, но пропускная способность («2x credits») не переводится в известное число задач.
- Общая месячная квота на клиентов/устройства/ключи — несколько ролей + веб-UI расходуют один пул; Extra Usage может тихо продолжить работу за деньги после исчерпания.

## Как назначать на роли (если вето Саши не запретило)

Распределение усилий, не доказанный рейтинг качества. arch≥rev≥exec соблюдается уровнем `reasoning_effort`, не требуя трёх разных имён:
- Архитектор: `kimi-k3.1-pro` / `k3.1-pro` `max`.
- Ревизор: `kimi-k3.1-pro` / `k3.1-pro` `high`.
- Исполнитель: `kimi-k3.1-pro` `low`, или `k3-256k` `high` на подписке.

Platform дефолтит `reasoning_effort=max` — если адаптер потеряет настройку `low`, исполнитель станет дороже ожидаемого. Reasoning оплачивается и тянет контекст в последующие запросы.

## Выводы

- Подписка PRO/Max как общий бэкенд автоматического Hermes — нерегламентна (неинтерактивная автоматизация вне правил).
- Platform API — решает вопрос допустимости автоматизации, но возвращает оплату токенов (исходная цель «дешёвая подписка вместо токенов» не выполняется).
- 1M-контекст НЕ уникален перед OpenAI GPT-6.1 Sol / GPT-6 Astra (~1.05M) — не продавать как эксклюзив.
- Kimi ценен как дополнительный сильный рецензент/архитектор для задач большого контекста при сохранении текущего контура.
