# Шаблоны вывода

Файл делится на две части:

- **Часть 1. Описание процесса** — итог проверки транскрипта и форматы описания (А/Б/В). **Формат А** — основной для выдачи в чат.
- **Часть 2. Матрица ИИ-зации** — таблицы матрицы, сводки и схема файла данных `spec.json`.

Правила статусов и полноты — в `SKILL.md`; список вопросов — в `questions.md`;
методология матрицы — в `reference.md`.

**Имена:** во всех шаблонах ниже — **полные имена** (официальная форма), не
уменьшительные и не разговорные формы из записи. Уменьшительные и разговорные
формы — **только в прямых цитатах**. С фамилией и ролью при первом упоминании,
если известны из расшифровки; дальше — полное имя или фамилия. Если полное имя
не названо — не выдумывай; пометка «в записи — …» или открытый вопрос. Speaker N
→ полное имя, если идентифицирован. То же — в полях `owner`, `executor`, `actor`
в `spec.json` и листе «Контекст» Excel. Подробнее — § «Имена участников» в
`SKILL.md`.

**Какой формат когда:**

| Ситуация | Формат вывода в чат |
|---|---|
| Описание + матрица (режим 3, по умолчанию) | итог проверки + **А** + сводка матрицы |
| Только описание | итог проверки + **А** |
| Только матрица | итог проверки + сводка матрицы (без описания) |
| Нарратив / регламент по шагам | **Б** по запросу |
| Таблица этапов / карта нагрузки | **В** по запросу |

# Часть 1. Описание процесса

## Итог проверки транскрипта

### Вариант компактный (всегда в чате; перед описанием или сводкой матрицы)

```markdown
## Итог проверки транскрипта

| Показатель | Значение |
|---|---|
| Раскрыто | X из 40 |
| Частично | X из 40 |
| Не раскрыто | X из 40 |
| Не применимо | X из 40 |
| **Обязательные (О1–О12)** | **X из 12** |

**Пробелы (не блокируют работу):** [краткий список через «;»]

**Рекомендация:** [что уточнить у владельца — 1–2 предложения; если есть стадии с `[оценка]` — уточнить длительность по этапам]
```

### Вариант полный (для черновика / по запросу «развернуть проверку»)

```markdown
# Итог проверки транскрипта

## Полнота покрытия
- Раскрыто: X из 40
- Частично: X из 40
- Не раскрыто: X из 40
- Не применимо: X из 40
- Обязательные вопросы закрыты: X из 12
- Вывод: <можно собирать описание / пока нельзя — не хватает обязательных сведений>

## Что раскрыто
- [блок / вопрос]: [краткое резюме ответа]

## Чего не хватает
- [блок / вопрос]: [какой именно детали не хватает]

## Какие вопросы задать владельцу процесса
1. [конкретный уточняющий вопрос]
2. [конкретный уточняющий вопрос]
3. [конкретный уточняющий вопрос]
```

Сразу после итога — либо предупреждение о неполноте, либо описание процесса.

## Предупреждение, если данных недостаточно

```text
Описание процесса пока неполное (раскрыто X из 40, обязательных закрыто X из 12).
Чтобы завершить, не хватает:
- [блок]: [деталь]
- [блок]: [деталь]

Донесите эти детали в любой момент — пришлите текст, ответы или новую расшифровку,
и я обновлю проверку. Текущий прогресс по вопросам сохранён.
```

## Выбор формата описания

Спроси одним вопросом, если формат не указан:

```text
В каком виде собрать описание процесса?
- А — структурно по 8 блокам (по умолчанию)
- Б — нарративный пошаговый регламент
- В — таблицей по этапам
Можно выбрать один, несколько или «все». По умолчанию — **А**.
```

Подсказки по триггерам: «структурно / по блокам» → **А**;
«пошагово / регламент / нарративом» → **Б**;
«таблицей / карта этапов / по нагрузке» → **В**; «все / полностью» → А+Б+В.
Молчание / «решай сам» → **А**.

## Формат А — описание по 8 блокам

```markdown
# Описание процесса: [название]

## 1. Обзор
- Бизнес-цель:
- Владелец / заказчик:
- Частота и что запускает:
- Объём / масштаб (кейсов за период, пики):
- Ключевые метрики (KPI):

## 2. Входы и выходы
- Что запускает процесс (триггер):
- Входные данные / документы:
- Источники данных:
- Формат и качество входных данных:
- Результат процесса и его форма:
- Кто получает результат и как использует:

## 3. Этапы процесса
| № | Этап | Ответственный | Длительность | Артефакты | Узкие места |
|---|------|---------------|--------------|-----------|-------------|
| 1 | … | … | … | … | … |

**Правило колонки «Длительность»:**
- Длительность названа в интервью → записать как есть: `2 ч`, `1–3 дня`.
- Длительность не упоминалась → расчётная оценка с маркером: `~2 ч [оценка]`.
  Основание — в колонке «Узкие места»: `~2 ч [оценка: ручная сверка ~30 строк, 1 цикл правок]`.
  Стадию вынести в «Открытые вопросы»: `Уточнить длительность стадии «…» (расчётная оценка ~X).`

- Обработка исключений и вариаций сценария:

## 4. Действия и решения
- Ключевые действия по этапам:
- Какие решения принимаются и кто их принимает:
- Правила / критерии решений:
- Где хранится экспертное знание (регламенты / в головах сотрудников):
- Где нужна экспертиза / критическое мышление:
- Что делается вручную, а что автоматизировано:

## 5. Коммуникации
- Кто с кем взаимодействует:
- Каналы:
- Задержки из-за коммуникаций:

## 6. Риски и ограничения
- Риски:
- Цена ошибки и кто страдает при сбое:
- Безопасность / конфиденциальность / соответствие требованиям:
- Что нельзя полностью отдавать ИИ и почему:

## 7. Инструменты и автоматизация
- Системы и инструменты:
- Что уже автоматизировано:
- Что хотят автоматизировать и что мешает:
- Планы по улучшению:

## 8. Метрики и контроль качества
- Как контролируется качество:
- Метрики времени / качества / затрат:
- Частые проблемы и отклонения:

## Открытые вопросы
- [если что-то осталось неуточнённым — перечислить, иначе «нет»]
```

## Структура вывода в чат (блоки 1–3)

Блоки **не путать** с форматами **А / Б / В**: блоки — **что** выводим; форматы А/Б/В —
**как** оформлен блок 2 (описание процесса).

| Блок | Содержание | Когда включать |
|---|---|---|
| **1. Итог проверки** | компактная таблица покрытия + пробелы + рекомендация | **всегда** |
| **2. Описание процесса** | формат **А**, **Б** или **В** (см. ниже) | режим «описание» и «оба»; в режиме «только матрица» — **по запросу** |
| **3. Сводка матрицы** | стадии, TO BE, AS IS→TO BE, что не отдаём ИИ | режим «матрица» и «оба» |

Полные клетки AS IS / TO BE **не выводить в чат** — только в Excel (`.xlsx`).

**Правило длительности (блок 2 и таблица стадий в блоке 3):**

- срок **назван в интервью** → пиши как есть;
- срок **не назван** → `~X [оценка]`; никогда не выдавай оценку за факт;
- в блоке 3 (таблица стадий): `{из встречи или «не уточнялось»} | ~X [оценка]`;
- стадии с `[оценка]` → в **Рекомендация** блока 1: «уточнить длительность по этапам у …».

## Формат Б — нарративный пошаговый регламент (альтернатива формату А)

**Назначение:** блок 2 — **по запросу** или когда выбран формат **Б** вместо **А**.
Только нарратив (участники, шаги, ветвления, TO BE); блоки 1 и 3 — по таблице выше.

**Стандарт полноты (обязательно).** Нарратив — это **полноценное описание процесса**,
как регламент для нового сотрудника, а не краткое резюме. Пользователь ожидает
**все детали из интервью**, разложенные прозой. **Запрещено:** однострочные шаги
через `;`, «шпаргалка на полэкрана», урезание «для краткости чата», пропуск
участников/инструментов/ветвлений, если они звучали в транскрипте.

**Обязательная структура блока 2 (формат Б):**

1. **Назначение процесса** — 1–2 абзаца: зачем процесс, кому результат, частота,
   что считается успешным результатом (из интервью).
2. **Участники и роли** — список: кто исполнитель, заказчик, руководитель; доли
   нагрузки / частота обращений, если названы.
3. **Инструменты процесса** — абзац или список систем и артефактов из интервью.
4. **Шаг 1 … Шаг N** — каждый шаг **отдельным заголовком** и **несколькими
   абзацами** (см. содержание шага ниже).
5. **Ветвления** — маркированный список «если … → …» (срочный / плановый /
   невыполнимый / нетипичный и т. п.).
6. **Договорённости и ограничения** — лимиты, SLA, качество, что не уточнено.
7. **Длительность (из встречи)** — общий срок процесса; явно отделить от `[оценка]` по шагам.
8. **Наиболее трудоёмкие стадии / узкие места** — если звучало или следует из интервью.
9. **Что принципиально остаётся за человеком** — решения и ревью, которые нельзя
   отдать ИИ (из интервью и блока рисков).
10. **Целевое состояние (TO BE)** — развёрнуто, если звучало в интервью.
11. **Открытые вопросы** — нумерованный список пробелов.

**Содержание каждого шага (минимум):**

- **кто** инициирует / **кто** выполняет;
- **что** происходит по сути (не одним предложением-ярлыком);
- **инструменты** и **системы** на этом шаге;
- **решения** и **критерии** (кто принимает, на основании чего);
- **экспертные нюансы** из интервью (ошибки, исключения, «подводные камни»);
- **артефакт** на выходе и **где хранится**;
- в конце шага курсивом: `*Из встречи: …; ~X [оценка].*` — по правилу длительности.

Ориентир объёма: **типичный процесс из 5–8 стадий** — нарратив **не менее ~1,5–3
тысяч слов** при достаточном транскрипте; каждый шаг — **минимум 2–4 предложения**,
часто больше, если в интервью много деталей.

**Правила оформления блока 2 (формат Б):**

- **без названий видов деятельности и методологических ремарок** — никаких «Виды
  деятельности: …», «это Анализ данных», «это не анализ, а исполнение», «здесь два
  разных вида». Классификация работы по видам — только в матрице; в нарративе её нет;
- нарратив — **абзацы** `**Шаг N. [Название].** …`, не однострочные пункты через `;`;
- в каждом шаге: кто, что делает, артефакт, инструменты, ветвления «если … то …»;
- **сроки** — по правилу длительности выше; в конце шага — курсивом `*Из встречи: …; ~X [оценка].*`;
- ветвления — отдельным маркированным списком **Ветвления:** после всех шагов;
- после шагов — **Длительность (из встречи):** для всего процесса + пометка, что разбивка по шагам — **[оценка]**;
- **Целевое состояние (TO BE):** — если звучало в интервью;
- блок 2 — проза, без таблиц (таблицы допустимы в блоках 1 и 3).

**Пример полной выдачи формата Б** (блок 1 + блок 2 + при матрице блок 3):

```markdown
## Итог проверки транскрипта

| Показатель | Значение |
|---|---|
| Раскрыто | X из 40 |
| Частично | X из 40 |
| Не раскрыто | X из 40 |
| Не применимо | X из 40 |
| **Обязательные (О1–О12)** | **X из 12** |

**Пробелы (не блокируют работу):** [краткий список через «;»]

**Рекомендация:** [что уточнить у владельца — 1–2 предложения; включая длительность по этапам, если есть [оценка]]

---

## Нарративное описание процесса

**Участники:** [роли и имена из транскрипта]

**Шаг 1. [Название этапа].** [Кто инициирует / кто выполняет; что происходит; артефакт; инструменты; условия.] *Из встречи: [факт или «не уточнялось»]; ~X [оценка].*

**Шаг 2. [Название этапа].** …

**Шаг N. [Название этапа].** … *…*

**Ветвления:**
- **[Условие 1]** → [действие / срок]
- **[Условие 2]** → [действие]

**Длительность (из встречи):** [общий срок процесса — только факты из интервью]. Разбивка по шагам — **[оценка]**, [рекомендация уточнить у владельца].

**Целевое состояние (TO BE):** [1–3 предложения из интервью — если звучало]

### Стадии (столбцы)

| № | Стадия | Длительность | Критическая |
|---|---|---|---|
| 1 | … | не уточнялось \| ~X [оценка] | |
| 3 | ⚠️ … | [из встречи] \| ~X [оценка] | да |

### Сводка TO BE: кто отвечает

| Стадия | Ответственный | Комментарий |
|---|---|---|
| … | AI + ревью человека / AI-агент / Человек | … |

### Ключевые изменения AS IS → TO BE

| Стадия | Сейчас | С ИИ |
|---|---|---|
| … | … | … |

### Что не отдаём ИИ

| Этап | Что остаётся за человеком | Почему |
|---|---|---|
| … | … | … |

---

**Файлы:** `[путь].xlsx`, `[путь].spec.json`, `[путь]-process.md`
```

**Чек-лист выдачи (блоки 1–3; для формата Б — стандарт полноты):**

- [ ] Блок 1 — компактная таблица, не простыня по 40 вопросам.
- [ ] Блок 2 (формат Б) — **назначение**, **роли**, **инструменты**; шаги **абзацами**, не одна строка на шаг.
- [ ] Каждый **Шаг N.** — кто, что, инструменты, решения, артефакт, нюансы; срок курсивом в конце.
- [ ] После шагов — **ветвления**, **длительность процесса**, **что за человеком**, **TO BE**, **открытые вопросы**.
- [ ] Нарратив **не сжат** «для краткости»; нет телеграфа через `;`.
- [ ] У каждого шага с неизвестным сроком — *~X [оценка]*; общий срок процесса отделён от оценок по шагам.
- [ ] Ветвления — отдельным списком; TO BE — если было в интервью.
- [ ] Блок 3 (если есть матрица) — только сводки; полные клетки — в Excel.
- [ ] В Excel и `spec.json` — тот же формат длительности, что в таблице «Стадии».

## Формат В — таблица этапов с типом нагрузки

```markdown
| № | Этап | Участники | Тип нагрузки | Комментарий | Длительность |
|---|------|-----------|--------------|-------------|--------------|
```

Правила:

- строки в порядке выполнения; под-этапы нумеруй `7.1`, `7.2`;
- **тип нагрузки** — один из: `Асинхронная`, `Коммуникационная`, `Управленческая`, `Креативная`, `Аналитическая`, `Ручная работа`, `Контрольная`, `Автоматизированная (ИИ)`, `Ожидание + правки`;
- **длительность**: если названа в интервью — записать как есть; если нет — расчётная оценка `~X [оценка]`, основание — в колонке «Комментарий»; стадию вынести в «Открытые вопросы»;
- в комментарии: суть шага, инструменты, условия / исключения.

# Часть 2. Матрица ИИ-зации

## Заголовок и контекст

```markdown
# Матрица ИИ-зации: <название процесса>

**Владелец:** <роль / команда>
**Цель процесса:** <одна строка>
**Частота:** <раз в день / неделю / по триггеру>
**KPI:** <ключевые метрики>
**Дата формирования:** <YYYY-MM-DD>
**Версия:** v<n>

> **Статус:** Рекомендация — итоговые назначения «человек / AI-агент / AI + ревью»
> требуют обсуждения с владельцем процесса и стейкхолдерами перед запуском работ.
```

## Легенда (дословно)

```markdown
## Легенда

| Тип | Описание |
|---|---|
| Ассистентский ИИ | Автоматизация рутинных задач, помощь в поиске информации, подготовка отчётов, документирование. |
| Агентный ИИ | Выполнение сложных аналитических задач, моделирование, поиск закономерностей, сценарный анализ. |
| Сотрудничество с человеком | Интерактивная работа (аналитические платформы, дискуссии), требуется критическое мышление человека. |
| Нет применимости | Требуется высокая креативность, критическое суждение, человеческая интуиция — остаётся за человеком. |
| ⚠️ КРИТИЧЕСКОЕ | Самые трудозатратные или блокирующие стадии (узкие места). |
```

## Матрица «как сейчас» (AS IS)

```markdown
## Матрица «как сейчас» — <название процесса>

| Вид деятельности \ Стадии | <Стадия 1> | <Стадия 2> | ⚠️ КРИТИЧЕСКОЕ: <Стадия 3> | <Стадия 4> |
|---|---|---|---|---|
| <Вид А> | Вручную: <...>. Артефакт: <...>. | Вручную: <...>. Артефакт: <...>. | Нет | Вручную: <...>. Артефакт: <...>. |
| <Вид Б> | Нет | Вручную: <...>. Артефакт: <...>. | Вручную: <...>. Артефакт: <...>. | Нет |
```

Пример клетки «как сейчас»:

```
Вручную: руководитель CRM ищет недостающие материалы по чек-листу, запрашивает уточнения у заказчика.
Артефакт: статус Backlog + список вопросов/ответов + отметка готовности (Jira).
```

## Матрица «как будет» (TO BE)

Формат клетки — строго по `reference.md` § «Формат клетки»: **тип ИИ + что делает
ИИ + что делает человек + сценарий взаимодействия + артефакт**. Голое «частично»
без расшифровки запрещено.

```markdown
## Матрица «как будет» — <название процесса>

| Вид деятельности \ Стадии | <Стадия 1> | <Стадия 2> | <Стадия 3> | <Стадия 4> |
|---|---|---|---|---|
| <Вид А> | <тип ИИ>: <что делает ИИ>. Человек: <что делает человек>. Сценарий: <агент запрашивает … → человек … → агент возвращает …>. Артефакт: <...>. | … | … | Нет. Артефакт: <...>. |
```

Пример клетки «как будет» (с явным разделением труда и сценарием):

```
Ассистентский ИИ: ищет дубли задач и похожие кампании по базе кейсов (корпоративный LLM + Jira/Confluence).
Человек: формулирует исходный запрос, оценивает релевантность найденного, отбирает применимые кейсы.
Сценарий: агент запрашивает тему и цель задачи → человек даёт формулировку → агент возвращает список похожих кейсов с ссылками → человек отмечает применимые.
Артефакт: тикет Jira с ТЗ + сводка похожих кейсов.
```

Пример клетки для вида «Создание кода / генерация запросов» (нестандартный вид):

```
Ассистентский ИИ: генерирует SQL/Jupyter-ноутбук по описанию задачи (Claude).
Человек: ревьюит сгенерированный код, дописывает правки (например, toString при несовпадении типов), запускает.
Сценарий: агент запрашивает структуру данных и цель выгрузки → человек указывает таблицы и условия → агент возвращает черновик запроса → человек проверяет логику и правит → агент по правкам обновляет код.
Артефакт: SQL-запрос / Jupyter Notebook (репозиторий аналитики).
```

## Сводка по стадиям

```markdown
## Сводка: человек / ИИ по стадиям

| № | Стадия | Ответственный в состоянии «как будет» | Комментарий |
|---|---|---|---|
| 1 | <Стадия 1> | Человек | Принципиально не отдаём (ценностное решение). |
| 2 | <Стадия 2> | AI-агент | Полностью автоматизируется. |
| 3 | <Стадия 3> | AI + ревью человека | Агент готовит, человек подтверждает. |
```

Допустимые значения столбца «Ответственный»: `Человек`, `AI-агент`, `AI + ревью человека`.

## Что не отдаём ИИ

```markdown
## Что не отдаём ИИ

| Этап процесса | Что не отдаём ИИ | Почему |
|---|---|---|
| <Стадия N — название как в матрице> | <что именно остаётся за человеком> | <обоснование: ценностное / репутационное / юридическое> |
```

Имя этапа — дословно как в матрице. Один этап = одна строка.

## Чек-лист готовности матрицы

- [ ] У всех клеток «как сейчас» есть артефакт.
- [ ] У всех клеток «как будет» с ИИ заполнены тип ИИ и инструмент.
- [ ] **В каждой клетке «как будет» с ИИ явно разделён труд: что делает ИИ, что — человек** (нет голого «частично»).
- [ ] **У каждой клетки «как будет» с ИИ есть сценарий взаимодействия** (агент запрашивает → человек даёт → агент возвращает).
- [ ] Использованы только 4 типа ИИ из легенды.
- [ ] **Каждый вид деятельности проверен по триггерам из `reference.md`** (не отнесён ошибочно: «запуск ноутбука» ≠ «анализ данных»).
- [ ] **Нестандартные виды из процесса добавлены** (например, «Создание кода / генерация запросов»), а не втиснуты в 8 якорей.
- [ ] Маркеры ⚠️ КРИТИЧЕСКОЕ проставлены и обоснованы.
- [ ] Сводка «человек / ИИ» собрана.
- [ ] Сводка «что не отдаём ИИ» собрана с причинами.
- [ ] Столбцы идут в хронологическом порядке.
- [ ] Строки-виды деятельности не дублируют друг друга.

## Файл данных spec.json (источник правды для выгрузки)

Полная схема — в [`scripts/spec_template.json`](scripts/spec_template.json) (в примере
**3 вида** — два канонических и один нестандартный, иллюстрация структуры; у
реального процесса строк может быть больше восьми пунктов опорного списка).
Ключевые поля:

- `process_name`, `owner`, `purpose`, `frequency`, `kpi`, `date`, `version`, `status`;
- `duration_summary` — одна строка: что из встречи про сроки; что оценено; что уточнить;
- `duration_breakdown[]`: `{ stage, source, explicit, estimate, logic, clarify }` — для markdown (формат А, блок 3); **не** для Excel;
- `process_description` — `{ title, purpose, owner, …, narrative }` — **только** для markdown (форматы А/Б/В) и `spec.json`; **не** выгружать в Excel;
- `stages[]`: `{ name, duration, critical, actor, artifact }` — стадии (столбцы);
  **`duration`:** `{из встречи} | ~X [оценка]` или `не уточнялось | ~X [оценка]`;
- `activities[]`: **итоговые строки матрицы для этого процесса** (шаг 7): виды,
  выведенные из процесса (сверка с опорным списком в `reference.md`); список из 8
  пунктов **не исчерпывающий** — при необходимости добавляй свои; ключи в `as_is` /
  `to_be` должны **точно совпадать** с этим списком;
- `as_is` / `to_be`: `{ "<вид деятельности>": { "<стадия>": "<текст клетки>" } }`;
  **формат клетки `to_be`** — по `reference.md` § «Формат клетки»: тип ИИ + что
  делает ИИ + что делает человек + сценарий взаимодействия + артефакт; голое
  «частично» без расшифровки — ошибка;
- `stage_summary[]`: `{ stage, responsible, comment }`;
- `human_only[]`: `{ stage, what, why }`;
- `cjm[]`: `{ stage, critical, actions, touchpoints, as_is, to_be, effect }` —
  карта пути клиента в табличном виде (AS IS → TO BE); заполняй только для процессов
  с клиентским путём, для внутренних оставляй пустым (лист не появится).

Имя файлов программа делает из названия процесса: `<имя>.spec.json`, `<имя>.xlsx`.

**Базовый `export_matrix.py`** — **единственный** допустимый формат Excel: 6 базовых
листов (Контекст, Легенда, AS IS, TO BE, Сводка по стадиям, Что не отдаём ИИ) плюс
опциональные «CJM (AS IS → TO BE)» и «Эффект от внедрения», которые скрипт добавляет
сам только при наличии данных (`cjm[]`; `as_is_short` / `to_be_short` / `time_savings`
у стадий). Поля `duration_breakdown` и `process_description` сохраняй в `spec.json` и
markdown; **запрещено** добавлять в `.xlsx` лист «Описание процесса», лист «Этапы
процесса» или нарратив формата Б.
