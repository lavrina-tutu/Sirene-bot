# Стандарт контрактного раздела ТЗ

## Назначение

Инструменты экосистемы стыкуются друг с другом (читают/пишут общие данные, вызывают API). Без явного контракта эта стыковка держится на памяти архитектора — при доработке одного инструмента легко незаметно сломать формат для другого. Раздел `## Контракты экосистемы` — единственное место, где зафиксировано «что именно» передаётся между инструментами (в отличие от `EcosystemManifest.json`, который фиксирует только «кто с кем» через `links`).

Раздел живёт **внутри master-ТЗ** (`TZ/<Tool>/<Tool>_TZ.md`), не в отдельном файле — по инварианту «один master-файл на инструмент».

## Когда заполнять

- Обязателен для любого инструмента, у которого есть входящие или исходящие связи с другими инструментами/сущностями экосистемы.
- Если внешних контрактов нет (инструмент полностью автономен) — раздел всё равно должен присутствовать, с текстом «Нет внешних контрактов».

## Шаблон раздела

```markdown
## Контракты экосистемы

### Источник истины
- Владелец записи: <Tool> (или другой инструмент/файл, если <Tool> — только читатель)

### Входные контракты
| Поле | Тип | Обязательность | Источник (кто отдаёт) | Формат/enum |
|---|---|---|---|---|
| login | str | required | AnywhereContacts.ContactStore | login = email до "@" |

### Выходные контракты
| Поле | Тип | Потребитель (кто получает) | Формат/enum |
|---|---|---|---|
| contact.sources[*].active | bool | ProtocolFromSummary (matcher) | true/false, any() по источникам |

### Зависимости
- Получает от: [Tool A, Tool B]
- Отдаёт: [Tool C, Tool D]

### Breaking changes policy
- Версионирование формата: semver на поле `schema_version` внутри данных (не версия ТЗ)
- При breaking change: обновить `schema_version`, добавить `migrate_vN_to_vN+1()`, уведомить потребителей (список — из «Зависимости»)

### Границы («что НЕ трогать»)
- <явный список>
```

## Строгий синтаксис (единственное жёсткое требование)

Остальной текст раздела (нарратив, пояснения вокруг таблиц) — свободный. Но сами таблицы должны соблюдать это, чтобы их можно было парсить автоматически (`render_manifest.py`):

- **Порядок колонок фиксирован**, ровно как в шаблоне выше — не переставлять, не переименовывать заголовки.
  - Входные контракты: `Поле | Тип | Обязательность | Источник (кто отдаёт) | Формат/enum`
  - Выходные контракты: `Поле | Тип | Потребитель (кто получает) | Формат/enum`
- **Тип** — только одно из: `str`, `int`, `bool`, `enum[...]` (со списком значений внутри скобок), `datetime(iso8601)`.
- **Обязательность** (только во входных контрактах) — только `required` или `optional`.
- Заголовки подсекций (`### Источник истины`, `### Входные контракты` и т.д.) — писать буквально, без вариаций.

## Пример заполненного раздела (на основе AnywhereContacts)

```markdown
## Контракты экосистемы

### Источник истины
- Владелец записи: AnywhereContacts (`ContactStore`, `contacts.enc`, ключ — `login`)

### Входные контракты
| Поле | Тип | Обязательность | Источник (кто отдаёт) | Формат/enum |
|---|---|---|---|---|
| login | str | required | MoveFromExchange / коннекторы источников | login = email до "@" |
| fio | str | optional | коннекторы источников | ФИО как строка, "Фамилия Имя" |
| email | str | required | коннекторы источников | валидный email, маскируется при выводе |

### Выходные контракты
| Поле | Тип | Потребитель (кто получает) | Формат/enum |
|---|---|---|---|
| contact.sources | dict | ProtocolFromSummary, MeetingScheduler | ключ — имя источника (exchange/telegram/...), значение — {email, synced_at, active} |
| contact.sources[*].active | bool | ProtocolFromSummary (matcher) | true/false, any() по источникам определяет "живой" контакт |

### Зависимости
- Получает от: [MoveFromExchange, ExchangeOrgLookup]
- Отдаёт: [ProtocolFromSummary, MeetingScheduler]

### Breaking changes policy
- Версионирование формата: semver на поле `schema_version` внутри `contacts.enc` (сейчас "2.0")
- При breaking change: добавить `migrate_vN_to_vN+1()` в `schema.py`, уведомить потребителей из списка «Отдаёт»

### Границы («что НЕ трогать»)
- Не менять `login` как первичный ключ без миграции всех потребителей
- Не выводить raw `email`/`login` пользователю без маскирования через `render_contact`
```

## Если контрактов нет

Раздел не пропускать, писать явно:

```markdown
## Контракты экосистемы

Нет внешних контрактов — инструмент не читает и не пишет данные других инструментов экосистемы.
```
