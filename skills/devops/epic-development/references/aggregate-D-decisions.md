# Модуль D «База» — решения брифа (18.06.2026)

## Три выходных продукта системы

| Продукт | Аудитория | Где | Кто отвечает | MVP | Фаза 2 |
|---|---|---|---|---|---|
| P1: PM Dashboard (Warnings) | Только PM | Snapshot (Obsidian) | Модуль G «Срез» | ✅ авто | — |
| P2: Meeting Minutes (протокол) | Команда + заказчик | Snapshot → PM → Confluence | G + PM вручную | ✅ Obsidian | автоматизация |
| P3: Project Status (история) | PM + начальство (1-1) | D-артефакты (Obsidian) | Модуль D «База» | ✅ авто | Confluence |

**Важно:** Snapshot = PM-артефакт (содержит Warnings). Публичная часть (Minutes) = только «Решения», «В работе», «Следующие шаги» без Warnings.

## Разграничение D vs StatusSnapshot (теперь модуль G)

| | Модуль D «База» | Модуль G «Срез» |
|---|---|---|
| Входные данные | MeetingSignals от C (все встречи) | Одна свежая встреча + card.md |
| Что делает | Накапливает историю | Генерирует читаемый документ |
| Выход | decisions.md, action_items.md, timeline.md | snapshot-YYYY-MM-DD.md |
| Для кого | PM (1-1 с начальством) | PM (P1) + команда (P2) |
| Триггер | Пайплайн AggregateFrom | MoveFromFF (сразу после встречи) |
| Хранение | `Projects/<slug>/ai/` | `Projects/<slug>/snapshots/` |

## Семантика decisions vs action_items

**decisions.md:**
- Редко меняется
- Источник истины в спорах («договорились что...»)
- Историческая запись — не удаляется
- Противоречия: зачёркивание `~~текст~~` + пометка «пересмотрено [дата]»
- PM может опровергнуть через `<!-- pm: -->` в Snapshot

**action_items.md:**
- Часто меняется
- Сквозная нумерация `#N` по проекту (не по встрече)
- PM закрывает через `<!-- pm: #N закрыто -->`
- Система помечает кандидатов `[?]` при сигнале «выполнено» в summary
- Только PM ставит финальный `[x]`

## Архитектура файлов (append-only)

```
Projects/<slug>/
├── card.md          ← служебные поля (last_active, meetings_count) — D обновляет
├── ai/
│   ├── decisions.md     ← накопленные решения
│   ├── action_items.md  ← задачи #N
│   └── timeline.md      ← хронология
└── snapshots/
    └── <slug>-snapshot-YYYY-MM-DD.md  ← модуль G
```

## Решения по открытым вопросам

| Вопрос | Решение |
|---|---|
| Резолв противоречий | Новое решение + зачёркивание старого `~~текст~~` + «пересмотрено [дата]» |
| Closure action_items | Система помечает `[?]`, PM закрывает через `<!-- pm: #N закрыто -->` |
| Сквозная нумерация | `#N` глобально по проекту, не сбрасывается при новых встречах |
| pm_locked | Убрано из scope — D append-only, конфликтов нет |
| Health/stale | PM контролирует вручную на 1-1. Фаза 3 если понадобится |
| _uncategorized встречи | D пишет в `Projects/_uncategorized/`, F шлёт еженедельный дайджест PM |
| Snapshot граница | G — отдельный модуль (не часть D) для удобства разработки |
