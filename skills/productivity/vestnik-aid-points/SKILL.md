# vestnik-aid-points — баллы за Вестник АиД

## Overview

Скилл для **подсчёта баллов** за выпуск [Вестника Аналитики и Данных](https://dom.tutu.ru/pages/viewpage.action?pageId=324382467) и **подготовки текстового сообщения** о начислении.

**В scope:** парсинг Confluence, резолв ФИО/руководителей, арифметика, форматирование вывода.

**Вне scope:** отправка сообщения в Telegram или любой другой мессенджер — только подготовка текста.

**Reuse-first:** не дублировать инфраструктуру. Использовать существующие:
- Confluence-доступ (`load_confluence_env`, curl + `CONFLUENCE_TOKEN`) — см. `tutu-confluence-jira`
- `contacts.enc` / AnywhereContacts — см. `show-contacts`
- `~/USERTOOLS/OrgLookup` — резолв руководителя через GAL

Новый Python-код допустим **только** как сплейка парсинга таблицы + арифметика (inline `python3 -c` или короткий одноразовый скрипт в `/tmp`). Не создавать новый USERTOOLS-инструмент и CLI.

| Параметр | Обязательность | Источник |
|---|---|---|
| **Период / вкладка** | обязателен | Имя вкладки `horizontal-nav-item` на странице авторов (pageId=`324382467`), напр. «Апрель-Июль 2026» |

Если период не указан — **спросить у Саши** (один вопрос, варианты из доступных вкладок, если уже загружена страница).

## Шаг 1: Парсинг вкладки авторов

**Страница:** pageId=`324382467` («Вестник Аналитики и Данных»).

### Загрузка

```bash
load_confluence_env() {
  while IFS='=' read -r _k _v; do
    case "$_k" in
      CONFLUENCE_TOKEN|WORKVAULT_PATH)
        [ -n "$_v" ] && export "$_k=$_v"
        ;;
    esac
  done < "$HOME/USERTOOLS/ConfluenceSync/.env"
}
load_confluence_env

curl -s -H "Authorization: Bearer $CONFLUENCE_TOKEN" \
  "https://dom.tutu.ru/rest/api/content/324382467?expand=body.storage" \
  > /tmp/vestnik-authors.json
```

⚠️ Читать через `json.load(open(...))`, не `json.loads()` на stdout curl — backslash в теле страницы ломает парсинг (см. `tutu-confluence-jira`).

### Алгоритм

1. Найти вкладку по имени: элемент `ac:name="horizontal-nav-item"` (или аналог horizontal-nav) с текстом = запрошенный период.
2. Извлечь HTML/Storage-контент **этой** вкладки (секция после выбранного nav-item).
3. Распарсить таблицу: каждая строка данных → `(тема, ri:userkey автора)` из ячейки «Автор» (`<ri:user ri:userkey="...">`).
4. **Агрегировать** по `userkey` → число тем.

**Правила:**
- **1 строка = 1 тема.** У одного автора может быть N тем (N строк с одним userkey).
- Строки **без темы** или **заготовочные** (пустая ячейка «Тема», placeholder-текст) — **не считать** молча; **отметить** и **уточнить у Саши**, включать ли их в расчёт.

### Пример агрегации (Апрель-Июль 2026, 7 тем, 4 автора)

| Автор (userkey → ФИО на шаге 3) | Тем |
|---|---|
| Малый Денис | 1 |
| Бобровник Фёдор | 1 |
| Казакова Анастасия | 3 |
| Галашов Владислав | 2 |

## Шаг 2: Парсинг страницы расчёта

**Страница:** pageId=`496620177` («Расчет баллов за Вестник Аналитики»).

### Критично: версионность

**Читать правила КАЖДЫЙ раз** при расчёте. **НЕ хардкодить** ставки и получателей в скилле или коде — они могут меняться (текущая редакция: «с 16.07.26»).

```bash
load_confluence_env
curl -s -H "Authorization: Bearer $CONFLUENCE_TOKEN" \
  "https://dom.tutu.ru/rest/api/content/496620177?expand=body.storage" \
  > /tmp/vestnik-rates.json
```

### Что извлечь со страницы

| Блок | Что парсить |
|---|---|
| **Управление** | Фиксированная ставка (баллы) + **получатель** (ФИО) |
| **Авторы** | Таблица/текст ставок за тему по числу тем автора: 1 тема → ставка₁, 2 темы → ставка₂, 3+ тем → ставка₃₊. Итог автора = `N_тем × ставка(N)` |
| **Руководители авторов** | Ставка за одного автора (в примере 50) |
| **Подготовка темы/вестника** | Ставка за тему (в примере 68,57) + **получатель** (ФИО). Итог = `ставка × число_тем` |

Страница может быть оформлена **текстом**, а не HTML-таблицей — парсер должен уметь извлечь значения из произвольного storage-format (regex + эвристики по ключевым словам: «Управление», «автор», «руководител», «подготовк»).

### Текущие значения (справочно, из редакции 16.07.26 — сверять со страницей!)

- Управление: 100 баллов
- Автор: 1 тема → 100/тему; 2 темы → 150/тему; 3+ тем → 200/тему
- Руководитель: 50 за каждого уникального автора в подчинении
- Подготовка: 68,57 за тему (7 тем × 68,57 = 480)

## Шаг 3: Резолв ФИО автора

`userkey` → `username` / `displayName` через Confluence REST API (см. `tutu-confluence-jira`, раздел «Резолв пользователя Confluence»):

```bash
load_confluence_env
curl -s -H "Authorization: Bearer $CONFLUENCE_TOKEN" \
  "https://dom.tutu.ru/rest/api/user?key=<userkey>"
```

Дополнительно: `contacts.enc` через `find_contacts_for_display` / `get_contact_for_display` (`show-contacts`) — для уточнения ФИО, если Confluence `displayName` неполный.

### Формат вывода ФИО

**«Фамилия Имя»** — единообразно для всех блоков вывода.

В **этом скилле** маскирование PII **не применяется** — вывод предназначен для официального начисления баллов, нужны полные ФИО.

### Питфол: userkey ≠ username ≠ login

Confluence `username` часто не совпадает с корпоративным `login`. При несовпадении — резолвить по ФИО через CQL (`user.fullname~"Фамилия Имя"`) или через `contacts.enc`.

## Шаг 4: Резолв руководителя автора

Поле `reports_to` в `contacts.enc` **часто пустое** → основной путь: **OrgLookup / GAL**.

### Запуск

```bash
cd ~/USERTOOLS/OrgLookup && \
PYTHONPATH=../AnywhereContacts \
../AnywhereContacts/venv_linux/bin/python -c "
from orglookup import hierarchy
from anywhere_contacts import create_store, ContactsBaseSettings

settings = ContactsBaseSettings()
store = create_store(settings.contacts_enc_path, settings.contacts_encryption_key)
contact = store.get_contact('<login>')  # login из contacts.enc по ФИО автора
res = hierarchy.get_manager_login(contact.email)
print(res.manager_display_name, res.manager_login)
"
```

Альтернатива CLI: `orglookup manager <login>` (см. `show-contacts`).

### ⚠️ GAL может ошибаться

**Прецедент:** для Галашова Владислава GAL вернул Сысоева, реальный руководитель — **Жиров Александр**.

**Правило:** руководитель из GAL при **первом расчёте периода** помечать **«требует подтверждения Сашей»**. Не публиковать/не считать окончательным без сверки.

Для повторных расчётов того же периода — использовать подтверждённые значения, если Саша их зафиксировал.

## Шаг 5: Подсчёт баллов

Все ставки — **со страницы расчёта** (шаг 2). Ниже — формулы (числа из редакции 16.07.26, для справки).

### Авторы тем

```
баллы_автора = N_тем × ставка(N_тем)
```

где `ставка(N)`:
- N=1 → 100
- N=2 → 150 (за тему)
- N≥3 → 200 (за тему)

Примеры: 1 тема = 100; 2 темы = 300; 3 темы = 600.

### Руководители авторов

```
баллы_руководителя = ставка_за_автора × число_уникальных_авторов_в_подчинении
```

(в примере: 50 × число авторов). Один руководитель может курировать нескольких авторов.

### Управление

Фиксированная сумма со страницы (в примере 100) → получатель со страницы.

### Подготовка темы/вестника

```
баллы_подготовки = ставка_за_тему × общее_число_тем
```

(в примере: 68,57 × 7 = 480) → получатель со страницы.

### Итого по человеку

**Суммировать по всем ролям.** Один человек может быть одновременно автором и руководителем другого автора — баллы складываются.

## Шаг 6: Вывод

### Заголовок

```
Начисление баллов за Вестник АиД (<период>)
```

### Сводная таблица (ASCII)

```
ФИО                          | Кол-во баллов
-----------------------------+--------------
<Фамилия Имя>                | <N>
...
-----------------------------+--------------
ИТОГО                        | <сумма>
```

### Детальный расчёт (под таблицей, компактно)

Четыре блока:

**Авторы тем**
```
<Фамилия Имя> — <N> тем × <ставка> = <баллы>
...
```

**Руководители авторов**
```
<Фамилия Имя> — <N> автор(ов) × <ставка> = <баллы>  [требует подтверждения Сашей — если GAL]
...
```

**Дополнительно**
```
Управление: <Фамилия Имя> — <баллы>
Подготовка: <Фамилия Имя> — <число_тем> × <ставка> = <баллы>
```

**Итого по человеку**
```
<Фамилия Имя> — <сумма по всем ролям>
...
```

ФИО везде полные: **«Фамилия Имя»**.

## Питфоллы

| Проблема | Решение |
|---|---|
| **userkey ≠ username ≠ login** | Резолвить по `rest/api/user?key=`; при несовпадении — CQL по ФИО или `contacts.enc` |
| **GAL ошибается в руководителе** | Помечать «требует подтверждения Сашей»; прецедент: Галашов → GAL=Сысоев, реально=Жиров |
| **68,57 в подготовке** | В детальном расчёте показывать дробную ставку; **итог по блоку — целым** (68,57×7=480) |
| **Пустые/заготовочные темы** | Не считать автоматически; отметить и уточнить у Саши |
| **Страница расчёта — текст, не таблица** | Парсить regex/эвристиками; не полагаться только на `<table>` |
| **Ставки/получатели меняются** | Всегда читать pageId=496620177 заново; не хардкодить |
| **JSONDecodeError на curl stdout** | Сохранять в `/tmp/*.json`, читать `json.load()`; удалять файл после использования |
| **web_extract блокирует dom.tutu.ru** | Только `terminal` + curl (см. `tutu-confluence-jira`) |
