# Sweep-рецепт: команды и паттерны

## 1. Паттерн-строка

Один regex на все идентификаторы запроса, например:
`SanyaTkachik|sanyatkachik|shu_mzk|i\.alex\.tkachenko|a\.tkachenko@bk|Ткаченко Александра`

## 2. Зоны и команды (search_files или rg)

1. `~/WorkVault` — files_only, потом content с context=1..2 по найденному
2. `~/WorkVault_backup` — то же (сверить актуальность: каталог мог быть вычищен)
3. `~/.hermes/sessions` — json/jsonl дампы; FTS5 их НЕ покрывает
4. `~/.hermes/cron`, `~/.hermes/logs`, `~/.hermes/error_bus`, `~/.hermes/pii_scan`
5. `~/USERTOOLS`, `~/hermes-workspace`, `~/.hermes/skills`
6. `~/Documents ~/Downloads ~/Desktop ~/scripts ~/bin`
7. Облако: `rclone listremotes` → `rclone lsf owncloud:` (read-only), подтверждение файла `rclone cat owncloud:<path>`

## 3. Точная атрибуция

Файл часто матчится по нескольким паттернам сразу. Распределять по идентификаторам НЕ по общему списку файлов, а отдельным `rg -l '<точный паттерн>'` на каждый идентификатор. Иначе в отчёте смешаются gmail/yandex/телеграм в один счётчик.

## 4. Проверка «пароли рядом»

- secret_pat: `(password|passwd|пароль|pwd|secret|token|api[_-]?key|client[_-]?secret|bearer|BEGIN [A-Z ]*PRIVATE KEY)\s*[=:]\s*\S+|пароль приложения`
- Применять ТОЛЬКО к списку файлов с совпадением идентификатора.
- Отсеять не-секреты: `os.environ[...]`, `getenv`, `DEFAULT_TOKEN = Path.home()/...`, `refresh_token` как имя поля, rclone `pass = <obfuscated>`, тестовые/плейсхолдеры.
- Реальные значения проверять распространением: `rg '<секрет>'` по всем зонам — находит дубликаты в дампах сессий и подтверждает факт утечки в облако.

## 5. Типовые ложные совпадения

- Склонения ФИО: «на Ткаченко Александра», «компьютер Ткаченко Александра» — род./вин. падеж от мужского имени, НЕ отдельное лицо. Вывод: «отдельного человека нет, есть склонения твоего имени».
- Похожие адреса: `i.alex.tkachenko@gmail.com` vs `i.alex.tkachenko@yandex.ru` — разные записи; широкий паттерн ловит оба — в отчёте разделять.

## 6. Отчёт

- Секреты маскировать полностью (тип + путь, без значения).
- Группировка: по идентификатору, внутри — по характеру данных (ТЗ/код, встречи/минутки, дампы сессий, облако-зеркало).
- Итоговая строка: что не найдено вообще (0 во всех зонах) — это тоже ответ.

## 7. Облако при удалении «без восстановления»

- ownCloud зеркалит WorkVault: локально найденный файл существует и в облаке (подтверждать `rclone cat` для критичных).
- Локальное `rm` НЕ всегда пропагирует удаление в облако (осиротевшие архивы остаются). Для необратимого удаления: `rclone delete owncloud:<path>` + чистка корзины ownCloud `.trash`.

## 8. Поиск по миграции (имена/содержимое)

- Имена каталогов: `MigrationToVM`, `MigrationToWindows`, `WindowsCutover`, `*migrat*`, `*переезд*`, `*перенос*`, `*vm*`, `*remote*`, `*gateway*`, `*desktop*`.
- Содержимое: `миграц|переезд|MigrationToVM|Remote gateway|hermes serve|serve --host|9119|WindowsCutover` — но отсеивать посторонние «миграции» (LLM-модели, сущности, Trisigma, Codex-подписка), оставлять только Hermes-переносы.
- Дампы сессий по дате-префиксу имени (`session_YYYYMMDD_*`) — июнь = на VM, август = remote desktop, ноябрь = cutover на Windows.
