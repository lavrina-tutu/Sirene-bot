# Методология матрицы ИИ-зации

Детальная справка для построения матрицы (шаги 6–11 в `SKILL.md`). Читать по
необходимости. Вся логика встроена — внешние навыки не нужны.

## Легенда: 4 типа ИИ-поддержки (дословно)

Это главная ось матрицы. Каждая клетка матрицы «как будет» относится строго к
одному из четырёх типов. Никаких «полу-агентного», «гибридного» и других
придуманных типов — только эти четыре.

| Тип | Когда применяем |
|---|---|
| **Ассистентский ИИ** | Автоматизация рутинных задач, помощь в поиске информации, подготовка отчётов, документирование. |
| **Агентный ИИ** | Выполнение сложных аналитических задач, моделирование, поиск закономерностей, сценарный анализ. |
| **Сотрудничество с человеком** | Интерактивная работа (аналитические платформы, дискуссии); требуется критическое мышление человека. |
| **Нет применимости** | Требуется высокая креативность, критическое суждение, человеческая интуиция — остаётся за человеком. |

Дополнительно: **⚠️ КРИТИЧЕСКОЕ** — маркер для самых трудозатратных или
блокирующих стадий (узких мест). Это не тип ИИ, а отдельная пометка стадии.

### Дерево выбора типа

Прогоняй каждую клетку матрицы «как будет» через четыре вопроса по порядку.
Первый подходящий ответ и даёт тип:

```
1. Решение можно записать правилом «если X, то Y»?      → Ассистентский ИИ (рутина, шаблоны)
2. Есть история данных и нужно найти в них зависимости?  → Агентный ИИ (модели, скоринг, аномалии)
3. Нужна интерпретация или критическое суждение?         → Сотрудничество с человеком (ИИ готовит, человек решает)
4. Нужна высокая креативность, ценностное решение?       → Нет применимости (только человек)
```

## Опорный список видов работы

**Источник строк матрицы — сам процесс.** Сначала разбери стадии (кто делает /
вход / выход-артефакт) и выведи виды интеллектуальной работы, которые там реально
выполняются. Список ниже — не меню на выбор, а **короткие канонические названия**
для единообразия и страховки от пропуска неочевидных видов (критическое мышление,
приоритизация и т. п.).

> **Важно:** это **не готовый и не исчерпывающий** список строк матрицы
> (`activities[]`) для конкретного процесса. Строки матрицы выводятся **из
> процесса**; к списку ниже сверяешься для единообразия названий.

Канонические виды (сверяйся после того, как вывел виды из процесса):

1. Поиск информации
2. Анализ данных
3. Критическое мышление
4. Принятие решений
5. Генерация гипотез
6. Документирование
7. Исследования
8. Приоритизация

### Критерии-триггеры для каждого вида

Прежде чем отнести активность к виду из списка, сверь её с триггерами.
Если ни один триггер не совпадает — это другой вид; добавь своё имя.

| Вид | Триггеры — что происходит в клетке | Анти-паттерны — что не является этим видом |
|---|---|---|
| **Поиск информации** | Ищет данные / документы / ответы; собирает факты из разных источников; формулирует запрос и интерпретирует выдачу. | Запуск готового SQL-скрипта; нажатие кнопки «Выгрузить»; копирование таблицы. |
| **Анализ данных** | Сравнивает одно с другим на предмет чего-то; находит паттерны, аномалии, динамику; интерпретирует числа и делает вывод. | Запуск скрипта и получение таблицы без интерпретации; выгрузка CSV; создание кода. |
| **Критическое мышление** | Оценивает корректность / полноту результата; проверяет SQL на соответствие бизнес-логике; валидирует допущения; замечает неочевидные ошибки. | Механическое исполнение инструкции; запуск без проверки. |
| **Принятие решений** | Выбирает между альтернативами; утверждает или отклоняет; несёт ответственность за выбор. | Формулировка вариантов без выбора; предложение рекомендации. |
| **Генерация гипотез** | Придумывает объяснения или идеи без готового алгоритма; формулирует «а что если…»; создаёт новую интерпретацию. | Применение известного паттерна к новым данным. |
| **Документирование** | Фиксирует результат в артефакт (таблица, страница, отчёт, допущения); структурирует и оформляет для передачи. | Отправка сообщения в чате; заполнение одного поля формы. |
| **Исследования** | Работает без playbook; проверяет гипотезы методом проб; результат заранее не известен. | Типовой SQL-запрос по паттерну; работа по чёткому алгоритму. |
| **Приоритизация** | Ранжирует задачи / элементы по ценности или срочности; решает, что делать первым. | Сортировка списка по одному числовому критерию. |

### Когда добавлять нестандартный вид

Если в стадии есть активность, которая **не попадает ни под один триггер** выше —
добавь новый вид с коротким именем по смыслу процесса. Примеры нестандартных видов,
которые часто упускают:

- **Создание кода / генерация запросов** — активность по написанию или генерации
  SQL, Python-скриптов, Jupyter Notebook. Триггеры: создаёт или генерирует код
  (вручную или через ИИ-ассистент); формулирует технические инструкции для
  инструмента. **Не путать с «Анализом данных»**: создание скрипта и запуск скрипта
  — это техническая работа, а не сравнение данных; добавляй этот вид отдельно,
  когда он реально есть в процессе.
- **Валидация результатов** — проверка корректности выгрузки: числа сходятся,
  фильтры правильные, аномалий нет. Близко к «Критическому мышлению», но отличается
  тем, что фокус именно на данных, а не на бизнес-логике.
- **Коммуникация / согласование** — переписка с заказчиком для уточнения
  требований или согласования допущений; не является «Документированием».

**Расширенные формулировки** — только для пояснения в тексте или Confluence, **не**
заменяют короткое имя строки:

| Короткое | Расширенная формулировка (по необходимости) |
|---|---|
| Поиск информации | Поиск и сбор релевантной информации |
| Анализ данных | Анализ данных и выявление закономерностей / инсайтов |
| Критическое мышление | Критическое мышление и интерпретация результатов |
| Принятие решений | Принятие решений |
| Генерация гипотез | Генерация и формализация гипотез |
| Документирование | Документирование, систематизация и коммуникация |
| Исследования | Проведение исследований / проверка гипотез |
| Приоритизация | Приоритизация и управление реализацией |

Правила:

- вид работы из процесса, которого нет в списке, — **добавь** в матрицу с формулировкой под процесс (коротко, по смыслу процесса);
- вид из списка, который не встречается ни на одной стадии, — **не включай** в матрицу;
- **не раздувай** названия строк: в матрице и Excel — коротко (из списка или своя формулировка для уникального вида работы);
- **не подгоняй процесс под 8 строк:** список — словарь имён, не обязательный набор строк;
- **Исследования vs Анализ данных:** исследования — открытая работа без playbook (гипотезы, неизвестное); анализ данных — структурированные данные, SQL, паттерны; бизнес-цель «исследовать запрос» может раскладыаться на несколько строк без отдельной «Исследования»;
- на одной стадии несколько строк допустимо, если клетки описывают **разную** когнитивную работу, а не одно и то же разными словами.

## Формат клетки (строгий)

**Матрица «как сейчас»:**

```
Вручную: <глагол + объект + кто делает + чем>.
Артефакт: <название артефакта> (<где хранится: Jira / Confluence / админка / …>).
```

**Матрица «как будет»:**

```
<тип ИИ>: <что конкретно делает ИИ-агент>.
Человек: <что конкретно делает человек в этом взаимодействии>.
Артефакт: <название артефакта> (<где хранится>).
```

Типы ИИ (строго из легенды): Ассистентский ИИ / Агентный ИИ / Сотрудничество с человеком / Нет применимости.

**Обязательно раскрывай «частично»:** если работа разделена между ИИ и человеком,
опиши явно — что делает агент и что остаётся за человеком. Слово «частично» без
расшифровки — ошибка.

**Сценарий взаимодействия (для клеток с ИИ):** для каждой клетки матрицы «как будет»,
где участвует ИИ, добавь минимальный сценарий: что агент **спрашивает / запрашивает**
у человека, что **делает сам**, что **возвращает**. Формат — в самой клетке или
отдельной строкой под ней:

```
Сценарий: агент запрашивает <данные / параметры>; человек предоставляет <что>;
агент возвращает <артефакт или ответ>; человек <финальное действие>.
```

Если клетка `Нет` — артефакт всё равно может существовать: его просто создаёт
другой вид деятельности на этой же стадии.

## Маркировка узких мест (критических стадий)

### Шаг 1. Оцени сложность процесса (5 критериев)

- [ ] **8 и более стадий** в матрице.
- [ ] **2 и более ветвлений** / параллельных потоков / условных переходов.
- [ ] **4 и более ролей или команд** участвуют в процессе.
- [ ] **3 и более стадий-кандидатов** в критические по эвристике.
- [ ] **Срывы сроков разбросаны** по нескольким стадиям, а не сосредоточены в одной.

### Шаг 2. Выбери способ маркировки

- Выполнено **≤1** критерия → процесс **простой** → встроенная эвристика (ниже).
- Выполнено **≥2** критериев → процесс **сложный** → углублённый разбор по теории ограничений (ниже).

### Простой процесс — встроенная эвристика

Поставь префикс `⚠️ КРИТИЧЕСКОЕ:` стадиям, которые:

- самые длительные или с наибольшим разбросом времени;
- дают больше всего срывов сроков или возвратов на доработку;
- через них проходят все задачи (узкое место по теории ограничений).

### Сложный процесс — встроенный разбор по теории ограничений

Теория ограничений (Голдратт) исходит из того, что пропускную способность всего
процесса определяет одно-два самых узких звена. Найди их встроенным разбором:

1. **Очереди.** На каких стадиях задачи накапливаются и ждут? Стадия, перед
   которой растёт очередь, — кандидат в ограничение.
2. **Пропускная способность.** Какая стадия медленнее всех обрабатывает поток?
   Она задаёт темп всему процессу.
3. **Срывы и возвраты.** Где чаще всего срываются сроки и куда задачи
   возвращаются на доработку.
4. **Зависимость.** Через какие стадии проходят все без исключения задачи —
   их замедление бьёт по всему процессу.

Стадии, набравшие больше всего признаков 1–4, помечай `⚠️ КРИТИЧЕСКОЕ:`. В шапке
матрицы укажи: «Маркировка критических стадий: разбор по теории ограничений».
Спорные стадии вынеси в «открытые вопросы».

## Принципы (10)

1. **Сначала структура, потом содержание.** Без осей «виды деятельности × стадии» не пишем ни одной клетки.
2. **Список — ориентир, а не догма.** Виды деятельности выводятся из процесса; опорный список лишь страхует от пропусков и стабилизирует названия.
3. **Один словарь.** Только 4 типа ИИ из легенды, без выдуманных.
4. **«Как сейчас» → «как будет», а не «как сейчас под ИИ».** Сначала фиксируем реальность, потом улучшаем.
5. **Артефакт обязателен.** Без артефакта клетка «как сейчас» — пустая.
6. **Меньше ИИ — лучше.** Где справляется правило или человек — туда ИИ не суём.
7. **Узкие места — отдельной меткой.** ⚠️ КРИТИЧЕСКОЕ видно с первого взгляда.
8. **Готово к показу.** Любая матрица ложится в Confluence или слайд без правок.
9. **Любой формат на выходе.** Markdown — первичный, Excel — выгрузка по умолчанию, CSV — только по просьбе.
10. **Матрица «как будет» — рекомендация, не директива.** Итоговые назначения требуют обсуждения с владельцем процесса перед запуском работ.
