# CHECK — сверка чужого SR (план vs факт)

**Цель:** сравнить 44401–44403 с 44404–44406, оценить выполнение и объективность объяснений.

## Файлы

```
WorkVault/Projects/sr-tool/<ФИО>/
├── SR-{key}_{месяц}_{год}.md        # сырые поля 1–6
└── SR-{key}_{месяц}_{год}_check.md  # таблица план/факт
```

ФИО из summary (`SR - Криворотов Кирилл (Июнь - 2026)` → `Криворотов Кирилл`). После записи — `rclone sync`.

## Raw-файл

44401 → пронумерованные пункты плана; сопоставить с 44402 (критерии) и 44403 (OKR). 44404–44406 — та же нумерация.

## Check-таблица

Одна строка = один пункт плана.

| № | Что запланировано | Критерии и done/not done | Доп. успехи вне плана | Объективность объяснений |

Правила:
- **done/not done по каждому критерию**, не по пункту целиком.
- Доп. успехи — только из 44404, отсутствующие в 44401/44402.
- Объективность 44405: **причинно-следственная связь** с недостигнутым критерием; общие фразы без деталей = низкая объективность.
- Полностью done → «план не нарушал — n/a».
- Итог в конце: счётчик done/not done, системные паттерны в объяснениях.

## Методика vs выполнение

Просьба «опиши как поняла» / «напиши инструкцию» — **только описание**, ждать «делай»/«ок» перед применением к SR.

## Объективность — только CHECK

Правило объективности **не** переносить в бриф собственного Блока 5 (SELFCHECK).
