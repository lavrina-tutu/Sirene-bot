# Dialog Backlog — бэклог из переписки с Сиренью

## Что это

Автоматически поддерживаемый бэклог открытых вопросов и задач из Telegram-переписки Саши с Сиренью.

## Файл бэклога

`/home/tkachenkoav/WorkVault/Hermes-Backlog/dialog-backlog.md`

## Формат файла

```markdown
---
last_scan_at: 2026-06-16T20:30:00+03:00
next_id: 91
---
# Dialog Backlog — переписка с Сиренью

## 📇 Тема 1
- [ ] Открытая задача ^bk-001
  - 💬 Контекст: ...
  - 📅 `created:: 2026-05-28` · `updated:: 2026-06-16`
- [x] Закрытая задача ^bk-002
  - 📅 `created:: 2026-05-28` · `updated:: 2026-06-01`

## ✅ Закрытые (архив)
- [x] Старые закрытые ^bk-000
```

## Формат дат 📅

Каждый пункт имеет суб-буллет с датами:
```markdown
  - 📅 `created:: YYYY-MM-DD` · `updated:: YYYY-MM-DD`
```

- `created` — дата создания пункта (при добавлении через add_items)
- `updated` — дата последнего изменения:
  - При создании = created
  - При suggest_close обновляется на сегодня
  - При update_items обновляется на указанную дату или сегодня

Если пункт имеет контекст (`💬`), строка с датами идёт после него.

## Инструменты

> ⚠️ **backlog_merge.py устарел** — не использовать для закрытия пунктов и обновления контекста. Работай с файлом напрямую через `read_file` + `patch`. Скрипт оставлен только для исторической справки.

### backlog_merge.py (устарел, справочно)

Путь: `/home/tkachenkoav/USERTOOLS/DialogBacklog/backlog_merge.py`

Детерминированный merge изменений в dialog-backlog.md.

```bash
python backlog_merge.py --plan plan.json [--file PATH] [--dry-run]
```

#### Формат plan.json

```json
{
  "suggest_close": ["bk-005", "bk-012"],
  "add_items": [
    {
      "section": "🔧 Hermes / Сирень",
      "text": "Проверить X",
      "context": "Упоминалось 28.05",
      "created": "2026-06-16",
      "updated": "2026-06-16"
    }
  ],
  "update_items": [
    {
      "anchor": "bk-NNN",
      "text": "новый текст",
      "context": "новый контекст",
      "updated": "2026-06-16"
    }
  ],
  "new_last_scan_at": "2026-06-16T15:00:00+03:00"
}
```

#### Операции

1. **suggest_close** — добавляет `<!-- AI: suggest close -->` к открытым пунктам и обновляет `updated` в строке 📅
2. **add_items** — создаёт новый пункт с автоматическим якорем и датами (created/updated = сегодня по умолчанию)
3. **update_items** — обновляет существующий пункт:
   - `text` — заменяет текст (только для `[ ]` пунктов)
   - `context` — добавляет/заменяет строку контекста
   - `updated` — обновляет дату в строке 📅

## Правила работы с файлом

- `- [x]` поставленный **вручную Сашей** — закрыто навсегда, AI не трогает
- AI может предлагать закрытие (`<!-- AI: suggest close -->`), но НЕ менять `[ ]` → `[x]` самостоятельно
- Новые пункты добавляются с якорем `^bk-NNN` (следующий ID из frontmatter `next_id`)
- Группировать по темам (📇 Контакты, 🤖 Hermes, 📋 Инфраструктура, 📅 Meetings и т.д.)
- Одна строка = одна задача, кратко, суть понятна без контекста
- **Всегда добавлять строку 📅 с датами** при создании нового пункта

## Режим ревью бэклога (Review Mode)

**Триггер:** «проверь бэклог» (или: «посмотри бэклог», «обнови бэклог», «что в бэклоге»).

### Шаги ревью

**1. Читай бэклог:** `read_file("~/WorkVault/Hermes-Backlog/dialog-backlog.md")`  
Запомни все открытые `[ ]` пункты с их id (`^bk-NNN`).

**2. Собери сегодняшние сессии:**  
SQL против state.db — `sessions WHERE started_at > today_start ORDER BY started_at DESC`.  
Из телеграм-сессий: что обсуждали, что делали, какие задачи решили.

**3. Сверка — что закрылось сегодня?**
- Задача выполнена в сессии → предлагать закрыть (`[x]`)
- Не упоминалась → оставлять
- Новое, не в бэклоге → добавлять новый пункт

**4. Проверка cron-ошибок:**  
Сессии `source='cron'` с паттерном "skill not found" или "error" → добавлять в бэклог если не было.

**5. Формируй отчёт:**
```
## 📋 Ревью бэклога — {дата}
### ✅ Предлагаю закрыть
### 🔴 Обнаружены новые проблемы
### 🏗️ Epic-статусы
### 📌 Открытые пункты (без изменений)
### ℹ️ Статус задач в работе
```

**6. Доставка:**  
`send_message(target="telegram:-1004300127777:6", message=отчёт)` → топик 📋 Backlog (thread 6)

**7. Обновление бэклога (только если Саша подтвердил):**  
Закрывать пункт только если явно подтверждено. Техника:
1. `search_files` по `^bk-NNN`
2. `read_file` с offset
3. `patch: [ ] → [x]`
4. patch: обновить `last_scan_at` во frontmatter

**Правила режима ревью:**
- Если cronjob time window пропущен (next_run_at=null) — сразу делать `cronjob(action='run')` вручную
- EPIC-структура: раздел `## 🏗️ EPIC: AggregateFromMeetings` с тегом `^epic-aggregate`
- Повторный «проверь бэклог» в той же сессии → отвечать кратко без повторного чтения файла
- Никогда не пиши [SILENT]
- Не используй backlog_fetch.py и backlog_merge.py — устарели
- cron-сессии не считаются «ответом Саши»
- `memory(replace)` для next_id: сначала search_files по паттерну next_id в MEMORY.md

## Как подтверждать закрытие

Саша пишет номера через запятую: `bk-005, bk-007`
Сирень обновляет файл — меняет `[ ]` → `[x]` для указанных пунктов.

**Прямое "закрываем" = немедленный `[x]`** без suggest_close и без запроса подтверждения:
- «закрываем bk-062» — закрыть сразу
- «карточка готова, срез готов закрываем оба» — закрыть оба сразу
- «дизайн главной готов 064 закрываем» — закрыть сразу

`suggest_close` использовать только когда AI сам инициирует предложение закрыть (без команды от Саши).

## Паттерн пошагового разбора бэклога

Саша разбирает пункты по одному: «NNN про что?»
- Сирень объясняет суть пункта кратко (3–5 строк), без лишних деталей

- Саша отвечает → ответы сохраняются в `💬`-контекст пункта через `patch` напрямую (backlog_merge.py здесь неудобен — нет простого способа обновить контекст существующего пункта по якорю)

- Если Саша говорит «есть ли ко мне вопросы?» — это сигнал что он готов к уточнениям по пункту

## Паттерн: закрытие устаревших пунктов

Когда появляется новый пункт (bk-NNN), который заменяет или делает неактуальным старый:
1. Закрыть старый: `[ ]` → `[x]`
2. Добавить в контекст старого: `— **закрыто**: [причина]. Заменено на bk-NNN.`
3. Обновить даты: `updated:: сегодня` · `closed:: сегодня`

Пример (bk-007 закрыт в пользу bk-098):
```markdown
- [x] MoveFromExchange: верификация данных — **закрыто**: заменено bk-098. ^bk-007
  - 📅 `created:: 2026-05-28` · `updated:: 2026-06-22` · `closed:: 2026-06-22`
```

## Питфоллы

- **Баг: конфликт якорей bk-NNN** — `backlog_merge.py` читает `next_id` из frontmatter, но если в файле уже есть якоря с бо́льшими номерами, утилита присвоит коллизионные ID. Признак: два разных пункта с одинаковым `^bk-NNN`. Фикс: перед запуском merge смотреть реальный максимальный ID: `grep "\^bk-" dialog-backlog.md | grep -oE "[0-9]+" | sort -n | tail -1` и выставлять `next_id` выше.
- **При изменении условий задачи** — использовать `update_items` в plan.json. Дата `updated` обновится автоматически.
- **Дубли якорей возникают при параллельной записи** — если два джоба пишут в бэклог одновременно, оба читают один `next_id` и создают коллизию. Обнаружено 16.06: 10 дублей (bk-026..030, bk-061..065). Фикс: второе вхождение каждого дубля перенумеровать в max+1 скриптом Python; см. `scripts/dedup_anchors.py`.
- **Не дублировать** уже существующие пункты
- **Читать frontmatter** перед записью — взять актуальный `next_id` и `last_scan_at`
- **Обновлять frontmatter** после каждой записи
