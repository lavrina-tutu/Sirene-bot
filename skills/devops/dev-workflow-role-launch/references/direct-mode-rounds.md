# Direct-mode по-адресные раунды (W1/candidate декомпозиция на codex exec)

Для длинной декомпозиции (серийные W1-части в `candidate/hermes-workspace`) работы вести ВНЕ канбана серийно, без остановки между частями (Саша: «Да продолжай не спрашивай», «Делай по очереди всё необходимое чтобы быстрее закрыть вопрос»). Переспрашивать только на реальных развилках: NEW-ENTITY, смена модели-исполнителя, транспортная граница carrier.

## Раундовый цикл — один раунд = адресный промпт + один валидный коммит

Промпт раунда доступно: ТОЛЬКО закрываемые пункты вердикта/чек-листа (не «закрой всё»); **жёсткий write-scope** поимённо («НЕ писать pipeline_gates/terminal_boundary/…», «НЕ создавать новые schema/test файлы»); границы-зависимости с названным владельцем («это dependency W1-06, заглушку не выдумывать»); обязательные nodeids; `TMPDIR=/tmp` + контроль H до/после.

Запуск (background, notify+persist):
```bash
codex exec -C <D> -m <model> --skip-git-repo-check --json --sandbox danger-full-access \
  -- "$(cat /tmp/<prompt>.md)" 2>&1 | tee evidence/W1-XX-DONE.rN-<model>.log
```
Модели: код → `gpt-6.1-sol`; архитектор/ревизор → `gpt-6-astra`. Из памяти/алиасов, не из текста канона.

## Read-back — обязателен после КАЖДОГО exit-0 (до следующего раунда)

Уведомление gateway показывает только хвост вывода. Реальный итог — из tee-лога, последнее сообщение agent через `--json`:
```python
import re
t = open(log, encoding='utf-8', errors='replace').read()
msgs = re.findall(r'"type":"agent_message","text":"((?:[^"\\]|\\.)*)"', t)
text = msgs[-1].encode().decode('unicode_escape', errors='replace')
```
Там commit, count passed, остаток, зависимости. НЕ продолжать серию по одной focus-нотификации exit 0, не прочитав содержание.

## Независимая верификация оркестратора перед закрытием части

«Глазами», не по отчёту исполнителя:
- `git status` чист, HEAD на ожидаемом short;
- `--collect-only` — ровно ожидаемый набор nodeids (12 W1-03, затем + полные protocol и т.д.);
- полный `pytest` (`TMPDIR=/tmp`) — контрольное число (13/16/… passed), 0 skip/xfail;
- CLI `--help` rc0; `git diff --check` чист.
Только после этого: `out/W1-XX-CLOSE.md` (HEAD, nodeids, материализовано, зависимости с владельцем, читаемый итог).

## Открытая транспортная граница (ENV-03 class)

Когда carrier внешнего failure → worker rc75/78 NOT_PROVEN: вести все не-HOST-под-зависимые подпункты (resolver, бюджеты, crash-переживаемость receipt), а транспортный carrier честно помечать NOT_PROVEN-блокером. НЕ выдумывать HOST-carrying заглушку, НЕ закрывать часть по одному classifier. При boundary-проблеме (полная часть требует чужого слоя) — адресная дельта архитектора + решение владельца, не бесконечные раунды и не упрощённый оракул.

## Сбой раунда с незакоммиченным срезом

SIGTERM или зависающий тест в срезе исполнителя: откатить `git checkout -- <файлы>` к стабильному HEAD и повторить начисто; не чинить в грязном срезе. Зависший срез не валидный артефакт (rc124/tail-труба теряет вывод — писать control вывод отдельным файлом, а не только в трубу).

## Нормативы и склонности

- Все новые сущности — маркер **[NEW-ENTITY, требует согласования Саши]** (напр. plugin path) до проектирования.
- Замер usage фокусных прогонов (input/cached/output/reasoning) — фиксировать в лог/память.
- Отчёт по-человечески, без канбан-жаргона; варианты владельцу — предметно по именам, не «вариант 1/2». Уведомления — в тот топик, откуда пришёл вопрос.
- prep-лаб (hooks/plugin/receipts) строго в отдельном lab home под bwrap, production H read-only; контроль `find ~/.hermes -newermt '<start>'` c оговоркой о живых runtime mtime (нулевой diff не заявлять без доказательства).
