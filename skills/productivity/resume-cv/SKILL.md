# Resume/CV — составление и правка под ИИ/HR-читаемость

Класс: сделать резюме Саши читаемым для (а) ИИ/ATS-парсеров, (б) HR, (в) руководителей, (г) проектного офиса, сохранив текущий шаблон (экспорт hh.ru), и добавить актуальный опыт (Туту.ру).

## Процедура (в этом порядке)

1. **Извлечь текст исходника.** Исходник — обычно RTF-экспорт hh.ru. Старый `pandoc` (2.14) НЕ поддерживает `-f rtf`. Ставить striprtf через отдельный venv: `uv venv .venv && uv pip install --python .venv/bin/python striprtf`, читать `rtf_to_text(open(f, encoding='cp1251').read())`. Копировать исходник в scratch, не трогать оригинал.
2. **Собрать факты резюме** (полный инвентарь: шапка, желаемая должность, места опыта с датами, образование, курсы, навыки, языки). Выписать отдельно, что менять.
3. **Собрать реальные факты по актуальной роли из корп. систем, НЕ выдумывать.** Для Туту: страница «Проекты. Статус проектов» (статусы + комментарии) и страница «Проектный комитет» — искать все записи `РП: А. Ткаченко` / `Руководитель проекта: А. Ткаченко` (это список его проектов как РП), затем тянуть уставы/главные страницы проектов, чтобы понять «что делал / зачем / результат». Способ: `curl -H "Authorization: Bearer $CONFLUENCE_TOKEN" .../rest/api/content/<pageId>?expand=body.storage,title`, токен из `~/USERTOOLS/ConfluenceSync/.env`; json сохранять в файл и читать через `json.load` (curl-json в stdout с backslash ломается).
4. **Переписать по HR/AI-правилам** (см. references/resume-hr-ai-rules.md) в том же шаблоне hh.ru: `Шапка → Желаемая должность → О себе → Опыт (новый→старый) → Образование → Курсы → Навыки → Языки`.
5. **Сохранить черновик в `~/WorkVault/Outbox/`** (папка выдачи Саши), запустить синк `systemctl --user start owncloud-sync.service` и подтвердить доставку через `rclone lsjson owncloud:WorkVault/Outbox/` (exit 0 ≠ доставка — проверять имя файла). Шлифовка идёт в том же топике; метрики и спорные факты закрываются с Сашей поштучно.
6. **По запросу «дай вводные архитектору»** — собрать самодостаточный промпт-файл (полный текст резюме + вводные + что спросить), запустить `agent -p "$(cat /tmp/...)" -f --model cursor-grok-4.6-high` фоном, просить записать отчёт в файл (переживает обрыв канала).

## Питфоллы

- **Не выдумывать метрики и достижения.** Метрика без факта → плейсхолдер `[вставить]` или качественная формулировка эффекта; фейковая цифра хуже, чем её отсутствие (ИИ-скоринг и руководитель распознают overclaim).
- **AI-washing.** «10 лет AI» при фокусе с 2025 — красно́й флаг для скоринга. Писать честно: фокус AI/аналитика с <год>, роль — руководитель проектов, не ML-инженер.
- **Один текущий работодатель.** Два «настоящее время» подряд = красный флаг ATS. Новое место — первым, старое закрыть точной датой ухода (уточнить у Саши).
- **Достижения над обязанностями** в каждом месте, обязанности 5-6 уникальных (не копипаста между местами).
- **«О себе» не начинать с «N лет в ИТ»** — возраст+студенческие годы как главный хук стратегически слабо; ядро — PM-стаж и текущий фокус.
- **Навыки — по приоритету** (PM-ядро → методологии → AI/data → PMO-инструменты → короткий бэкграунд), убрать нерелевантное (вождение, устаревшие теги 2000-х), вычистить опечатки (они снижают ИИ-скоринг).
- **Опечатки в исходнике** (Orchad→Orchard, Cristal→Crystal, Entermediate→Intermediate, Abby Flexy→ABBYY FlexiCapture): править при переносе.
- **Уровень английского** (B2 vs Intermediate): выбрать один — несостыковка флаг.

## Туту-проекты (блок достижений)

Буллет по каждому проекту Туту пишется по `references/tutu-project-bullets.md` — там правила формата (официальное название, статус, выгода для бизнеса первой фразой, «Выполняемые задачи», функция вместо названий инструментов, экономия «во сколько-то раз» без сумм, результат-глаголы) и сбор фактов из устава+минуток+отчёта. Загружать перед написанием буллетов проектов.

## Финальный RTF (клонирование эталона hh.ru)

Когда надо выдать готовый `.rtf` по эталону hh.ru с актуальным содержанием (rev4→rev5 и т.д.) — НЕ пересобирать документ с нуля: скопировать каркас/шапку(с фото)/хвост эталона побайтово и подменить только содержимое секций. Полный порядок, кодировка `\'xx` (cp1251), таблица типографики и питфоллы (наследование цвета `\cf`, фрагментация текста `\loch\f1 \hich\f1`) — в `references/rtf-clone-formatting.md`. Читать его перед генерацией RTF.
