# emit-prompt: входы пакета и YAML в brief.md

Питфоллы оркестратора при подготовке роли (`emit-prompt` → `invoke-role`).

## Входы пакета берутся из контракта, не из каталога

`emit-prompt` собирает входы фазы из `inputs:` секции `brief.md`, а не сканирует каталог поезда. Новую улику (finding по rework, директиву владельца, обновлённый AC-list, свежую версию master) надо СНАЧАЛА добавить в `inputs:` нужной фазы в brief.md, потом пере-эмитить. Иначе пакет останется без неё, а вызванная роль отработает на старом контексте — потерянный круг и повторный цикл.

Проверять полноту пакета сразу после emit, до invoke:

```sh
python3 - <<'EOF'
raw=open('/tmp/task.md').read()
for token in ('finding-name', 'directive-name', 'AC-list.md'):
    print(token, ':', token in raw)
EOF
```

Не эмитить и не инвокать, пока каждая обязательная входная улика не подтверждена `True`. Фазы, которые обычно страдают: TZ:finalize (патч финальных входов), HF:impl (rework-finding/AC-list), HF:test (исторический AC-report). Проверять каждую, а не только первую.

## YAML в brief.md: закавычивать `purpose:` с двоеточием

Значения `purpose:` с двоеточием внутри (например `task_semantics_unrepresented:segments`, `display_only (§..) или блокер`) обязательно брать в двойные кавычки `"..."`. Незакавыченное `:` ломает YAML: patch проходит и отчёт об успехе есть, но следующий emit-prompt/next падает с parse-ошибкой (внешне выглядит как «контракт сломался сам»). Закавычивать с первой попытки, а не чинить по факту падения.

## Нормативная развилка → архитектор, не дефект исполнителя

FAIL теста бывает двух родов: (1) код разошёлся с планом — это rework исполнителя; (2) два места master-ТЗ читаются противоположно (например, одна норма требует «переносить с пометкой», другая — «оставить блокером») — это вопрос интерпретации требований, решает архитектор.

Для (2) НЕ записывать в finding оркестраторский вердикт («должно быть display_only») и НЕ откатывать на HF:impl как на дефект. Откатнуть на TZ:patch, в evidence сформулировать развилку нейтрально: обе цитаты из master, фактический FAIL и вопрос «что верно» без своего ответа. В `inputs:` TZ:patch добавить эту находку и пере-эмитить. Оркестратор не подменяет содержательное решение архитектора (и финально — владельца).
