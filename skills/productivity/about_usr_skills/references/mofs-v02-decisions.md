# MOFS v0.2 — Ключевые архитектурные решения (20.07.2026)

## 4 корзины NER-прогона
1. **Люди (contacts)** — через `contacts.enc` (email → `[[Имя Фамилия]]`)
2. **Проекты/темы (projects)** — через `entities.json`, kind ∈ {project, one_on_one, multisync, sync_aid, unknown}
3. **Инструменты (tools)** — через `entities.json`, kind=tool или `tags:["tool"]`
4. **Переговорки (rooms)** — через `WorkVault/Contacts/meeting-rooms.md` (НЕ через entities.json)

## Контакты — из тела текста, не frontmatter
ФИО участников и исполнителей лежат в теле summary (`## Участники:`, `## Задачи:`), а не в frontmatter-поле `participants`. Матчинг контактов должен идти по тексту, как и остальные 3 корзины.

## Провенанс frontmatter (решение D7)
Каждая запись в `_mark_objects_registry.json` содержит поле `source`:
- `mofs_auto` — автоматический матч детерминированным фильтром
- `mofs_llm_fallback` — матч через LLM
- `manual_via_mofs` — ручная правка через `mofs edit`

**Правило:** frontmatter встреч правится ТОЛЬКО через MOFS (`mofs edit`), не через Obsidian напрямую. Соглашение, не техническое ограничение.

## Bootstrap --undo механизм
Перед бутстрапом снимается снапшот:
- `frontmatter_before` для каждой встречи (пустой `{}` если MOFS-полей не было)
- список созданных карточек-заглушек

`mofs bootstrap --undo <manifest_id>`:
- Удаляет `projects`/`tools`/`rooms`/`contacts` из frontmatter встреч (записи с `source: mofs_auto`/`mofs_llm_fallback`)
- Удаляет созданные карточки (из манифеста)
- **НЕ трогает** записи с `source: manual_via_mofs`
- Fallback-детекция: если текущее значение отличается от снапшота вне ожидаемого — встреча пропускается, в лог пишется предупреждение

`mofs bootstrap --undo --dry-run` — показывает план без применения.

## КРИТИЧЕСКИЙ ПИТФОЛЛ: dry-run не гарантирован
**20.07.2026:** job с задачей «только диагностика» выполнил `mofs rematch --all` на 564 встречах без `--dry-run`. Баг: `--dry-run` в реализованном коде реально применял изменения.

**Обязательная проверка перед любым прогоном на архиве:**
```bash
# Smoke-тест dry-run на ОДНОМ файле
mofs rematch --meeting-id <id> --dry-run
# Проверить mtime файла: не изменился? → dry-run работает
stat "path/to/meeting.md" | grep Modify
```
Если mtime изменился → СТОП, баг в dry-run, не запускать на архиве.

## Стратегия бутстрапа (откладывается)
- Вперёд сразу (новые встречи после запуска кронов)
- Ретропрогон архива — после 1-2 недель обкатки, не сразу
- `--undo` механизм делает ретропрогон безопасным для отката

## mofs review — фильтры для ревью матчинга
Изолированная функция `apply_filters(entities, filters: dict)` с AND-логикой.
Фильтры: по slug, дате, provenance, bucket.
Не строить общую библиотеку фильтров заранее — YAGNI.

## Wikilinks формат
Везде `[[slug|display_name]]` — target=slug (стабильный), отображение=display_name (читаемо).
