# ContractAssistant — автоматизация знаний и ответов по договорам ТУТУ

Инструмент хранит канонические факты по договорам в `WorkVault/Entities/Contracts/` и готовит ответы на вопросы о договорах **только из этих фактов**.

## Ключевые факты

- **Данные:** `~/WorkVault/Entities/Contracts/Contracts.md` (карточка зонтика), `Rules/` (регламенты), `<slug>/<slug>.md` (агрегат договора)
- **Код:** `~/USERTOOLS/ContractAssistant/` (пакет `contractassistant`)
- **Регламент закупок:** `~/WorkVault/Entities/Contracts/Rules/purchase-rules.md` (пороги сумм, RACI, комиссия)
- **CLI:** `ca_watch`, `ca_answer`, `ca ask "<вопрос>"`

## 🔒 КРИТИЧНОЕ ПРАВИЛО ИСХОДЯЩИХ (по требованию Саши)

**Никакой ответ наружу (JIRA-комментарий, Loop, почта, мессенджеры) — без прямого явного указания Саши.**
- СА готовит: **проект ответа + обоснование (почему такой ответ)** → шлёт в Messages → **ждёт явного OK Саши** → только тогда постит в место вопроса.
- Без явного OK — никакой отправки. Даже `auto_post: true` не обходит этот рубеж.
- Любой вопрос «ответь в JIRA/Loop» → сначала черновик + причина → OK.

## Когда использовать

### 1. Создание/обновление договора в vault
При новом договоре (заявка ADD/TOMAKE, КП):
- Создать папку `Entities/Contracts/<slug>/` (латиница, без мусора)
- Положить КП PDF в `artifacts/`
- Создать `<slug>.md` по стандарту H2 (§6.4 ТЗ): Задачи JIRA, Контрагент, Суммы и сроки, ЮЛ и роли, Закупочная процедура, Выбор поставщика, Предмет/состав работ, Открытые вопросы, Журнал Q&A, Переписка, Источники
- ИНН/ЮЛ/суммы — храним; **телефоны/паспорта — НЕ хранить** (ПДн)
- Обновить `Contracts.md` (индекс активных), `Rules/` при необходимости

### 2. Ответ на вопрос о договоре (JIRA/Loop/почта/чат)
1. Определи slug договора (ключ JIRA, ИНН, контрагент)
2. Прочитай агрегат `<slug>.md` + регламент `Rules/purchase-rules.md`
3. Найди факт:
   - **known** — факт есть с цитатой секции → готовь ответ с `cite`
   - **partial/unknown** — факта нет / противоречие → эскалация Саше (не выдумывать)
4. **НЕ постить самому**: подготовь проект ответа + причину → покажи Саше → только после «да» постишь (JIRA comment / Loop post)
5. Запиши в «Журнал Q&A» агрегата: Q, A, cite, action

### 3. On-demand: `ca ask "<вопрос>"`
COП: `~/USERTOOLS/ContractAssistant/venv_linux/bin/python -m contractassistant ask "<вопрос>"` — вернёт classify + цитату.

## Порядок для срочных вопросов (JIRA-комментарии/Loop)

Паттерн как у срочных MFL/Exchange: мониторинг JIRA-комментариев по `jira_keys` агрегата, Loop DM-allowlist + @упоминания, Exchange (вопрос → схема; не вопрос → уведомление). Каждый вопрос — через схему «проект ответа → OK Саши → пост». Вопросов без ответа не оставлять: unknown → эскалация.

## Запреты

- Не выдумывать суммы/ИНН/комиссию/сроки — только из агрегата/регламента. Нет цитаты → `unknown`.
- Не постить наружу без явного OK Саши.
- Не оглашать бюджет/потолок закупки (регламент), кроме внутренней роли заказчика/закупок.
- Не обещать сроки подписания, которых нет в агрегате.
- Не менять поля JIRA (комиссия/суммы/КБК) — только комментарий.

## Ошибки

При сбое — `report_error.sh --tool ContractAssistant` (ErrorBus, не Messages).
