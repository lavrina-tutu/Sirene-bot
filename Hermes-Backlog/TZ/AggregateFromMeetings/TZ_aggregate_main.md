## 1. Назначение
Превратить разрозненные FF-транскрипты/саммари в **актуальные структурированные артефакты**:
- карточки проектов в `Projects/<slug>/` (срезы, решения, action items, риски),
- карточки контактов в `People/{login}/` (1‑1 контекст, commitments, латиница),
- карточки синков в `Syncs/<slug>/` (повестки регулярных площадок).

**Размер корпуса (M9):** ~940 файлов FF (summary + transcript) на сегодня. Для bootstrap классификации и алиасов используется подмножество — **478 summary с датой ≥ 12.08.2025**.

Цель — PM за 30 секунд понимает «где мы сейчас» по любому проекту и по любому человеку.

Полная цель/входы/выходы — см. `research/AggregateFrom-research-v0.1.md` (блоки 4–5).
Сущность «Проект» как точка истины для классификации — см. `research/AggregateFrom-project-entity-v0.1.md`.

## 2.1. Выходные продукты системы

Система AggregateFromMeetings + StatusSnapshot совместно производят **три выходных продукта** для разных аудиторий:

| Продукт | Аудитория | Где хранится | MVP (Фаза 1) | Фаза 2 |
|---------|-----------|--------------|--------------|--------|
| **P1: PM Dashboard** (Warnings + аналитика) | только PM | Модуль G «Срез» (Obsidian) | ✅ авто | — |
| **P2: Meeting Minutes** (протокол встречи) | команда + заказчик | Модуль G «Срез» → Confluence | ✅ Obsidian-черновик, PM модерирует → ручной перенос | автоматизация переноса в Confluence |
| **P3: Project Status** (полная история) | PM + начальство (1-1) | Модуль D «База» (Obsidian) | ✅ накапливается автоматически | автопубликация в Confluence |

### Разграничение зон ответственности

- **Модуль G «Срез»** = иммутабельный снимок по одной встрече. PM-артефакт. P1+P2. Триггер: вызов от F после D (только route=project/1on1).
- **Модуль D «База»** = накопленная история проекта за все встречи. База данных проекта. Источник для PM-отчётов на 1-1.

⚠️ **Важно:** Модуль G «Срез» — PM-артефакт, содержит Warnings. Публичная часть (для Meeting Minutes / Confluence) — только выбранные секции без Warnings.

### Confluence-публикация (Фаза 2)

В MVP PM переносит публичные секции вручную. Автоматическая публикация в Confluence (минутки + страница проекта) — scope Фазы 2.

## 3.1. Требование к качеству входных данных

⚠️ **Принцип «мусор на входе → мусор в Warnings»**

Секции `context.md`, допущения и ограничения в карточке проекта должны быть **максимально точными и ёмкими** — не «что дали, то и берём». PM один раз приводит эти секции в порядок перед первым запуском.

Правила:
- `context.md`: цель + ограничения + допущения — сжато, без воды, каждое утверждение проверяемо
- Допущения: конкретные («ресурсы выделены к 23.04»), не общие («команда поддержит»)
- Ограничения: измеримые («бюджет ≤ 5.99 млн», «срок до 18.06»)

Это prerequisite для работы модуля C (PM Warnings) и StatusSnapshot.

## 7.1. Confluence как источник — Фаза 0 (pull) и Фаза 2 (push)

> **Разделение фаз (M3):**
> - **Confluence pull (выкачка страниц) = Фаза 0** — Bootstrap, выкачка по реестру §3.2 + ночной cron 03:00 МСК (ВОП-5) для resync. **Не при каждом запуске пайплайна.**
> - **Confluence push (автопубликация минуток и статус-страниц) = Фаза 2** — после генерации артефактов D/G. Scope после v1.0.

### Идея
Confluence-пространство DPAN — источник истины по проектам АИД (официальные названия, составы команд, структура синков). Дополняет FF-встречи артефактами которых нет в аудио: брифы, уставы, составы участников, минутки.

### Реализация — расширение модуля A «Сборщик»

**Новый источник A3: Confluence-страницы проектов**

Для каждого проекта в `card.md` хранится `confluence_id` — ID корневой страницы проекта в Confluence. Модуль A пользуется снимком Confluence, который обновляет **ночной cron 03:00 МСК (ВОП-5), не при каждом запуске пайплайна**:
1. Проверяет `Projects/<slug>/confluence/_index.md` (реестр страниц)
2. Если страница изменилась с последнего синка (`updated_at` в Confluence > `synced_at` в `_index.md`) — выкачивает через ConfluenceSync
3. Сохраняет в `Projects/<slug>/confluence/<sanitized_title>.md`
4. Обновляет `_index.md`

**Структура `_index.md` (реестр страниц проекта):**
```markdown
---
slug: trisigma
confluence_root_id: 480923430
last_synced_at: 2026-06-21T12:00:00Z
---
# Confluence-страницы: Trisigma

| ID | Название | Файл | Последнее обновление | Синкнуто |
|----|---------|------|---------------------|---------|
| 480923430 | Trisigma проект | index.md | 2026-06-15 | 2026-06-21 |
| 490170597 | Задачи и договоренности (Минутки) | минутки.md | 2026-06-18 | 2026-06-21 |
```
