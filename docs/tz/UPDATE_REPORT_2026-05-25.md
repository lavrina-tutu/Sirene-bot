### 1. Exchange EWS: авторизация через Windows Kerberos ✅
**Документировано в:** MoveFromExchange_TZ_contacts_v1.0.md (§1, Шаг 1)

**Что изменено:**

- **Версию EWS НЕ указываем явно** — exchangelib определяет автоматически.
- Добавлены результаты тестирования:
  - ✅ Inbox: 14 писем
  - ✅ Calendar: 43 события
  - ✅ GAL resolve_names

**Замечание:** `TUTU_PASSWORD=***` в `.env` — плейсхолдер, обычно не используется при Kerberos.

### 2. Zulip: первичный источник контактов (1167 активных) ✅
**Документировано в:** 
- MoveFromExchange_TZ_contacts_v1.0.md (§13, Интеграция)
- MoveFromFF_TZ_v2.0_minimal.md (§13, Интеграция)
- MoveFromConfluence_TZ_v1.0.md (§14, Интеграция)

**Что изменено:**
- **MoveFromExchange:** остаётся важным инструментом, но теперь уточнено его назначение:
  - (а) Обогащение `contacts.enc` полями **department** и **position** из GAL.
  - (б) Синхронизация данных из Active Directory.
  - (в) Будущие инструменты (встречи, анализ почты).
  
- **MarkObjectsFromSummary** может использовать оба источника:
  - Exchange GAL (из MoveFromExchange) — для внутренних ТУТУ контактов.
  - Zulip API (1167 контактов) — более расширенная база.
  - Graceful degradation если один источник недоступен.

- **MoveFromFF** и **MoveFromConfluence** явно упоминают Zulip как дополнительный источник контактов для downstream-инструментов.

---

### 3. Confluence/Jira: переход на Keycloak SSO ⚠️
**Документировано в:** MoveFromConfluence_TZ_v1.0.md (§14, Критическое изменение)

**Что изменено:**
- **Статус:** PAT (Personal Access Token) **больше не работает** через REST API.
- **Проблема:** REST API v2 недоступен через PAT-авторизацию.
- **Решение:** требуется миграция на Keycloak SSO (обновление в v1.1).
- **Влияние на MoveFromConfluence v1.0:**
  - Чтение задач из Confluence — может быть затронуто.
  - Создание задач на странице Confluence — может быть затронуто.
  - **Рекомендация:** гарантирует работоспособность **в домене ТУТУ (через браузер или при активном session)**.
  - При production-развёртывании требуется приготовиться к миграции авторизации.

- **Действие:** Keycloak SSO миграция спланирована на v1.1 ТЗ.

## Проверка согласованности между ТЗ

### ✅ MoveFromExchange ↔ MoveFromFF ↔ MoveFromConfluence

| Аспект | Состояние |
|--------|-----------|
| **Единый источник контактов (contacts.enc)** | ✅ Согласовано: MoveFromExchange создаёт/обновляет, MoveFromFF и MoveFromConfluence используют для резолва email → ФИО. |
| **Зулип как дополнительный источник** | ✅ Согласовано: все три ТЗ упоминают Zulip как доступный источник для downstream-инструментов. |
| **Graceful degradation при недоступности contacts.enc** | ✅ Согласовано: все инструменты продолжают работать с email как есть, если контакты недоступны. |
| **Формат participants в _registry.json (MoveFromFF)** | ✅ Согласовано: MoveFromFF сохраняет список email, MoveFromConfluence и MarkObjectsFromSummary используют для резолва. |
| **Resolvable fields из Exchange GAL (department, position)** | ✅ Согласовано: MoveFromExchange отвечает за синхронизацию этих полей в contacts.enc. |
| **Контракт between-инструментов** | ✅ Согласовано: каждое ТЗ явно описывает, какие данные оно гарантирует для downstream. |

### ✅ Противоречия: Не найдено ❌

**Потенциальные конфликты, проверенные:**
1. **MoveFromExchange vs Zulip как источник:** разрешено — Exchange специализируется на GAL (department, position), Zulip — на расширенной базе контактов. Не противоречат.
2. **MoveFromFF и MoveFromConfluence используют contacts.enc:** разрешено — оба используют опционально (graceful degradation).
3. **PAT vs Keycloak в MoveFromConfluence:** разрешено — v1.0 использует PAT (временно), v1.1 будет использовать Keycloak. Явно задокументировано.
