# Dialog Backlog — бэклог из переписки с Сиренью

## Что это

Автоматически поддерживаемый бэклог открытых вопросов и задач из Telegram-переписки Саши с Сиренью.

## Файл

`C:/Users/tkachenkoav/WorkVault/Hermes-Backlog/dialog-backlog.md`

## Формат файла

```markdown
---
last_scan_at: 2026-05-28T12:00:00+03:00
next_id: 21
---
# Dialog Backlog — переписка с Сиренью

## 📇 Тема 1
- [ ] Открытая задача ^bk-001
- [x] Закрытая задача ^bk-002

## ✅ Закрытые (архив)
- [x] Старые закрытые ^bk-000
```

## Правила работы с файлом

- `- [x]` поставленный **вручную Сашей** — закрыто навсегда, AI не трогает
- AI может предлагать закрытие (`<!-- AI: suggest close -->`), но НЕ менять `[ ]` → `[x]` самостоятельно
- Новые пункты добавляются с якорем `^bk-NNN` (следующий ID из frontmatter `next_id`)
- Группировать по темам (📇 Контакты, 🤖 Hermes, 📋 Инфраструктура, 📅 Meetings и т.д.)
- Одна строка = одна задача, кратко, суть понятна без контекста

## Крон

- **Понедельник 09:00** — сводка в Telegram (job_id: `1734ad364b99`, модель: Opus)
- **По запросу** — написать "обнови backlog" или "что открыто в бэклоге"

## Формат понедельничной сводки

```
📋 Backlog · понедельник <дата>

✅ Предлагаю закрыть (<N>):
• <пункт> — <причина>

🆕 Новые задачи (<N>):
• <пункт>

🟡 Висит открытым (<N> всего):
• <пункт> (<сколько дней>)

Подтверди закрытие: напиши "bk-005, bk-007"
```

Если изменений нет: `"📋 Backlog без изменений. Открытых: N"`

## Как подтверждать закрытие

Саша пишет номера через запятую: `bk-005, bk-007`
Сирень обновляет файл — меняет `[ ]` → `[x]` для указанных пунктов.

## Питфоллы

- **Баг: конфликт якорей bk-NNN** — `backlog_merge.py` читает `next_id` из frontmatter, но если в файле уже есть якоря с бо́льшими номерами (напр. bk-029..032 из MigrationToVM-блоков добавленных вручную), утилита присвоит коллизионные ID. Признак: два разных пункта с одинаковым `^bk-NNN` в разных секциях. Фикс: перед запуском merge смотреть реальный максимальный ID в файле (`grep "^bk-" dialog-backlog.md | sort -t- -k2 -n | tail -1`) и выставлять `next_id` в frontmatter выше этого значения вручную.
- **Не дублировать** уже существующие пункты при добавлении новых
- **Читать frontmatter** перед записью — взять актуальный `next_id` и `last_scan_at`
- **Обновлять frontmatter** после каждого изменения (`last_scan_at`, `next_id`)
- **Не затирать** задачи которые Саша закрыл вручную `[x]`
- Микро-утилиты: `backlog_fetch.py` и `backlog_merge.py` лежат в `USERTOOLS/DialogBacklog/`. Понедельничный cron (job `1734ad364b99`) использует их для детерминированного мержа — LLM через промпт вызывает утилиты, не пишет в файл напрямую.
- **При ответе на "что дальше?"** — обязательно читать и файл backlog, и историю переписки за 2 недели через session_search. Только файл — недостаточно.
- **Подтверждение закрытия** — только явное от Саши (номера `bk-NNN`). AI сам `[x]` не ставит.
