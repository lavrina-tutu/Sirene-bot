# Ограничения и граница этапа 08

Gate относится к внутреннему PreparedPlan → представление/календарь/Итого,
версионному профилю и живым контрольным примерам. Публичное подключение
к первичному архиву и admission diff/publish — этап 09; сетевое исполнение — 10.

Профиль фиксирует установленный frontend build H6u7SQymvwxeyojc1ur6Z,
SHA-256 реально загруженного engine asset и Bryntum 5.4.1. Номер серверного
релиза недоступен этому аккаунту (UPM 401), он не выдуман. Elapsed eday,
наследование/разные календари задач и ресурсов и прочие перечисленные
в профиле возможности остаются not_verified. Диагностика препятствует
объявлению такого представления готовым без разрешения конкретных потерь.

Work A–D совпадает с эталонами; качество извлечения partial сохранено
из exporter, включая его недоступные timephased getters.

В отдельном read-only наблюдении старый get_attachment(version=..., status=any)
на текущей версии возвращает HTTP 400; см. legacy-version-endpoint.json.
Код прежних этапов не менялся. Контроли этапа 08 проверяют текущие metadata,
затем download точной версии и байты, фактически загруженные браузером.
Исправление сетевого helper остаётся отдельной работой сетевого этапа.

Два старых test_rest_live теста пропущены как необязательные для этапа 08;
новый обязательный live-контур выполнен без HTTP mocks.
Никакой поддержки локального scheduler не приписано плагину.
Production DB/WorkVault и страницы A–D/AB не изменялись; Gateway/кроны/
наблюдатели/расписания и Registries не менялись. OwnCloud sync не подтверждён.
