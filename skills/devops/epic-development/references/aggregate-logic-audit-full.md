## Что нашли (итоги сессии)

### Ложный баг (не баг)
- **Симптом:** 10 unclear-встреч с алиасом и 0 участников → report говорил «нет участников»
- **Причина:** `explain_unclear()` в bootstrap.py перечисляла ВСЕ причины, не решающую
- **Факт:** в b_router.py строки 233–249 уже корректно делают `real_n≤1 + алиас → project`
- **Вывод:** код правильнее ТЗ. ТЗ Шаг 1 vs Шаг 6 противоречили — исправили ТЗ, не код

### Реальный блокер 1: ff_parser теряет участников
- **Причина:** FF-summary не содержит `**Участники:**` by design (шаблон MoveFromFF)
- **Участники есть только в transcript.md** (`**Участники:** email1, email2`)
- **a_sources.scan_new_meetings()** намеренно фильтровал transcript-файлы
- **Результат:** `participants_raw=[]` почти везде → 197 unclear (39%)
- **Фикс (R1):** для каждого summary подтягивать парный transcript, парсить оттуда
- **MoveFromFF трогать не нужно** — он уже пишет участников в transcript

### Реальный блокер 2: таблица имён не реализована
- **Симптом:** «Кирилл 1-1», «Daily Илья» → unclear (не 1on1)
- **Причина:** hardcoded таблица «Кирилл→kkrivorotov» есть в ТЗ B, но `grep kkrivorotov aggregate_from/ = 0`
- **Правильная концепция (R2):** B при инициализации читает `~/WorkVault/Contacts/tutu-contacts.md` через `ContactStore.load_contacts()` — aliases уже там, включая контекстные
- **Не нужен:** Python-dict в b_router.py (дублирование источника истины)
