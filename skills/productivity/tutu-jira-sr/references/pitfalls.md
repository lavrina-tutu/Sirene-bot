# SR — питфоллы

## patch vs write_file

При правке одного пункта в MD с повторяющейся структурой (`N. Заголовок` → буллиты) `patch` может зацепить соседний пункт или продублировать критерии.

**После любого patch** — `read_file` целиком: число пунктов, заголовки, нет дублей.
Нетривиальная правка — переписать файл через `write_file`, не чинить patch-цепочкой.

## 44405 ≠ «только невыполненные»

Блок 5 опрашивается по **всем N целям** плана. Выполненные тоже могли иметь проблемы (решённые — показатель качества).

Признак ошибки: в 44405 меньше пунктов чем в плане; нет «Проблем не было»; нет «Итог:».

Прецедент SR-39282: агент предложил только частичные/невыполненные — пользователь переписал поле целиком.

## % чекина противоречит тексту

`43782` = 100% + «On Track», но «Что было сделано» говорит о незавершённости — не сглаживать. Спросить: что было целью на отчётный период (не на год).

## Доп. факт к другому пункту

В брифе «по одному пункту» пользователь добавляет детали без указания номера («к п.1 добавлю…»), но факт относится к другому пункту (похожие темы: AI-аналитик vs Trisigma).

Признак: термины нового факта не встречались в текущем пункте. При сомнении — одна строка: «к какому пункту относится?»

## Статус SR между этапами

Однократный `GET /transitions` в начале сессии недостаточен. Повторять перед каждым `POST`.

## Правки методики — архитектору

Default не переписывает SKILL.md и формат полей по договорённости в сессии заполнения. Изменения — через Cursor/архитектора.

## Описание методики ≠ выполнение

«Опиши как отработать» → только текст методики, ждать подтверждения перед применением.
