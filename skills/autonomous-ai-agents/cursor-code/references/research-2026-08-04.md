## Installation Quirks

### The `curl -o` vs `>` problem
Cursor's CDN (`cursor.com/install`) detects the output target:
- `curl -fsS https://cursor.com/install | bash` → ✅ bash script
- `curl -fsS https://cursor.com/install > file.sh` → ✅ bash script
- `curl -fsS -o file.sh https://cursor.com/install` → ❌ HTML page (Next.js marketing)

Root cause: CDN uses User-Agent/output-target detection. The `-o` flag changes how curl negotiates with the server, triggering HTML response.

## Auth

### API Key
- Path: `cursor.com/dashboard` → API Keys (left sidebar, under "Data Management")
- Format: `crsr_...`
- Scope: User API Key (not Admin)
- Free Plan: headless CLI works, Background Agent API does NOT
- Team Plan (Alexander Tkachenko): all features available

### Token exchange
The CLI exchanges `CURSOR_API_KEY` for a session token via `exchange_user_api_key` endpoint. Token is cached until JWT expiry. Direct session tokens (`CURSOR_ACCESS_TOKEN`) also supported but less discoverable.
