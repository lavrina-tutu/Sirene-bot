**Отличие от CHECK:** свой SR, итоги ещё пусты. Цель — сформулировать, не оценить.

**Источник правды:** блоки 4–6 и `_draft.md` ведём в Obsidian (MD); в Jira заливаем утверждённый вариант.
Доработки — сначала правка MD, потом повторная заливка. `sync_md_header` после POST — только шапка (статус/дата/transition), не импорт текста из Jira.

## Бриф Блока 5 (44405)

После согласования Блока 4 — **отдельный проход по всем N целям**, включая выполненные.

Вопрос (один пункт = одно сообщение):
«П.N. <заголовок>. Каких знаний или навыков не хватило или какая была сложность, и как её решили?»

Правила:
- **Не фильтровать** по статусу выполнения.
- Проблема ≠ «не выполнено»; нужна конкретная причина (кто/что/почему).
- «нет» / «проблем не было» → `Проблем не было`.
- Решение есть → `Решение: …`; нет — строку не выводить.
- После последней цели — вопрос на совокупный «Итог: …» для 44405.
- Не слать промежуточные отчёты между пунктами; не перепечатывать Блок 4.

## Финализация: draft → check

1. **`_draft.md`** — Блок 4/5/6:
   - Блок 4: `**Плановый результат:**` со статусами (без ✅❌); `**Дополнительный результат:**` только если непусто.
   - Блок 5: N пунктов; `Проблема:`/`Решение:` или `Проблем не было`; абзац `Итог:`; не «Сложность:».
   - Блок 6: уроки по N пунктам; `-` если пусто.
2. **`_check.md`** — самопроверка draft перед заливкой (всё в MD).
3. Заливка — отдельный шаг по явной команде, текст из `_draft.md` → `references/flow-fill-push.md` (transition **271**).
4. После успешного POST: **`sync_md_header`** / `--sync-md` — шапка того же MD (статус Jira, дата, transition); содержимое блоков не подтягивать из Jira.
5. `systemctl --user start owncloud-sync.service` (скилл `workvault-sync`; не ручной `rclone sync`).
