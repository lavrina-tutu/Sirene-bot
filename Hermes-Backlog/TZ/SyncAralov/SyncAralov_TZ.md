# ТЗ: Автокрон синка 1-1 с Араловым (SyncAralov)

**Версия:** 0.1.0
**Автор:** Сирень (бриф с Сашей)
**Дата:** 2026-09-17
**Статус:** approved — ТЗ согласовано, открытых вопросов нет; реализация ждёт отдельного «берём в работу».

**Цель (одним предложением):** Каждый четверг Сирень автоматически ставит/переносит разовую встречу «Синк 1-1 Саша - Саша» с Араловым Александром: 45 минут (fallback 30), в приоритетное для Аралова время (11:00–16:00 или 17:00–18:00, свободно у обоих), с переговоркой 4–8 человек в Москве, без уведомлений в Loop, без вопросов к Саше — по фиксированному шаблону темы и текста.

---

## 1. Назначение и триггер

### Что делает
Встреча 1-1 с Араловым — регулярная, по четвергам. На **периодические** встречи переговорку забронировать нельзя (переговорки заняты заранее), поэтому встреча делается **разовой** на каждый четверг и ставится заранее (на следующий четверг и на через один), пока переговорки не разобрали. Крон автоматизирует постановку/перенос без участия Саши.

### Триггер
Крон, запуск **каждый четверг**.

---

## 2. Эталон встречи (шаблон)

Встреча «Синк 1-1 Саша - Саша» существует в календаре (эталон). Тема и текст всегда фиксированные, из шаблона — чтобы не потерялось, если оригинальная встреча исчезнет.

| Поле | Значение (фиксированное) |
|---|---|
| `subject` | `Синк 1-1 Саша - Саша` |
| `body` (первая строка текста) | `Регулярный синк 1-1 Саша А. – Саша Т.` |
| `duration_minutes` | **45** |
| `attendees` (required) | **только** `aralov@tutu.tech` (Аралов А.) |
| Fireflies-бот | **НЕ добавлять** (`fred@fireflies.ai` в эту встречу не включать) |
| `notify_loop` | **нет** (в Loop не уведомляем) |

> ⚠️ Отклонение от общего встречного контура MeetingScheduler (где Fireflies добавляется всегда): для SyncAralov Fireflies исключён по явному решению Саши.

---

## 3. Логика крона (каждый четверг)

Каждый четверг Сирень проверяет наличие встреч на:
- **следующий четверг** (+7 дней)
- **через один четверг** (+14 дней)

Для каждой недостающей/некорректной даты:
1. **Если встречи нет** → создать разовую по шаблону (§2).
2. **Если встреча есть, но стоит не в приоритетном окне ИЛИ без нормального места** → перенести в подходящий свободный слот.
3. **Если встреча уже стоит в приоритетном окне, со свободной для обоих и переговоркой** → оставить как есть (без действий).

**Приоритет №1 — время в окне Аралова.** Главное — чтобы встреча была в приоритетном окне Аралова (и свободно у обоих). Отсутствие переговорки — не блокер для встречи, но должно быть отражено в поле «Место».

**Fallback по длительности:** если в календаре Аралова **нет свободного слота на 45 минут**, но **есть на 30 минут** → использовать слот на **30 минут** (остальные правила те же).

**Уведомление в топик Messages:** уведомляем в топик messages (Telegram) в случаях:
- встреча **вообще не подходит по критериям** (нет подходящего по времени Аралова слота), **или** не нашли переговорку, **или** получается только 30 минут;
- **выбранный по времени Аралова слот пересекается с календарём Саши** — встреча ставится по Аралову, но Саша предупреждается о пересечении.

## 4. Выбор времени

- **Длительность:** 45 минут (fallback 30).
- **Приоритетные окна:** `11:00–16:00` или `17:00–18:00` (время по Москве).
- **Приоритет времени — у Аралова (первостепенно):** главное, чтобы выбранный слот был **свободен у Аралова**.
- **Свобода у Саши — желательна, но НЕ блокер:** если у Аралова слот есть, а у Саши в это время **пересечение** — встречу **ставим по времени Аралова** (как было запланировано), а Саше уходит **уведомление в топик messages** о пересечении.
- Просмотр — **только в будущее, ближайшие 2 месяца**.
- Слот ищется в будущем (не в прошлом), Пн–Пт.

## 4а. Дедупликация (обязательно — по итогам исследования архитектора 17.09)

**Правило №1 — окно времени только через `calendar.view(start, end)`.**
`filter(start__range=now, now+62d)` НЕ разворачивает recurring-серии и вернёт только мастер. Мастер «Синк 1-1 Саша - Саша» стоит на **13.11.2025** (вне окна) → крон «не увидит» встречу и создаст дубль. `view` по дате серию отдаёт (type=Exception/Occurrence, UID общий с мастером).

Алгоритм проверки наличия/дедупа перед create:
1. Слот постановки в МСК (aware) → `_ews(slot_start)`.
2. `calendar.view(start, end)` по 2–4 ближайшим четвергам (не один ±5 мин; можно combine-сдвиг). **Не** комбинировать `view` с `.filter()` (EWS запрещает — отсекать на клиенте).
3. Игнорировать не-`CalendarItem` (в `calendar.all()` бывают `Message` без `required_attendees`).
4. Матч дубля: subject нормализовать (регистр/пробелы) ≈ `Синк 1-1 Саша - Саша` **или** `SequenceMatcher ≥ 0.7`; затем `item.refresh()` и искать `aralov@tutu.tech` в required/optional. **Не** матчить по комнате («Саванна (8)» есть и у другой серии).
5. Для ответа «существует ли weekly-серия вообще» — поиск master: `filter(subject__icontains='Синк 1-1 Саша')` без окна по start, на клиенте `type == RecurringMaster` + участник aralov. Не `filter(type=...)` на сервере (`type`/`uid` не searchable).
6. UID — стабильный ключ серии (мастер 13.11.2025 и Exception 24.09 — один UID). В restriction не вставлять.
7. **ErrorServerBusy:** `Configuration(retry_policy=FaultTolerance(max_wait=120))`, узкие `view`-окна, `.only(...)` без attendees, backoff `e.back_off` (часто 60 с). FailFast по умолчанию роняет крон.
8. Не считать дублем соседние серии: «Синк Департамента» (16:00, организатор Аралов), «Синк 1-1 … (пропавший)» (07.11.2025) — другие UID.

Готовый контур (read-only сниппет): `find_sync_in_slot()` (дубль на слот) и `find_sync_master()` (серия существует) — предоставлен архитектором, применить в реализации. Код MeetingScheduler для create-дедупа уже на `view` — переиспользовать.

## 5. Переговорки и поле «Место»

### Формат поля «Место»
- С переговоркой: **`Имя переговорки (вместимость) - Zoom`**
  - пример: `Саванна (8) - Zoom`
  - пример: `Два стула (2) - Zoom`
  - Вместимость — фактическая, из переговорки.
- Без переговорки (ни одной свободной на период): **`только ВКС`**.

### Алгоритм назначения переговорки (двойной контроль)
1. На выбранный слот подобрать свободную переговорку **4–8 человек** в офисе Москва.
2. **Переговорку «Лес» не задействуем** (она для руководства, бронь не подтвердят). Также исключаем «Кабинет» (как в MeetingScheduler).
3. После назначения — **проверить, что переговорка реально приняла встречу** (подтвердила бронь / встала в календарь переговорки).
4. Если переговорка **не приняла** → искать **другую** переговорку на тот же период.
5. Если свободных переговорок на **4–8 человек нет** → искать **на 2 человека** (формат `Имя (2) - Zoom`).
6. Если **и такой нет** → в поле «Место» записать **`только ВКС`**, и **через неделю перепроверить**, не появилась ли свободная переговорка → перенести в неё.

> **Двойной контроль назначения переговорок:** (а) проверка принятия сразу после назначения (§5 п.3), (б) перепроверка через неделю при «только ВКС» (§5 п.6).

- [ ] Каждый четверг крон обрабатывает +7 и +14 дней.
- [ ] Все созданные/перенесённые встречи: тема `Синк 1-1 Саша - Саша`, текст `Регулярный синк 1-1 Саша А. – Саша Т.`, 45 мин.
- [ ] Участник — только `aralov@tutu.tech`, без `fred@fireflies.ai`, без Loop.
- [ ] Встреча всегда в приоритетном окне Аралова (11–15 или 17–18), свободно у обоих.
- [ ] Поле «Место» соответствует формату (§5): переговорка с вместимостью ИЛИ `только ВКС`.
- [ ] Переговорка «Лес»/«Кабинет» не используется.
- [ ] Контроль принятия переговорки выполнен; при «только ВКС» — повторная проверка через неделю.
- [ ] Крон работает без вопросов к Саше.

## 7. Что НЕ трогать

- **Не создавать периодическую встречу** (на периодику переговорку не зарезервировать) — только разовые.
- **Не включать** Fireflies-бота в эту встречу.
- **Не уведомлять в Loop.**
- **Do not restart Gateway.**
- Не менять общий контур MeetingScheduler для других встреч (там Fireflies/Loop остаются как есть) — только для кейса SyncAralov.
