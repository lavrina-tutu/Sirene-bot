## Контекст сбоя публикации
План «ZD. Закупка данных 181126.mpp» (sluq `zd`, страница 537561928) не публикуется:
блокер `calendar_intervals_unsupported` (календарь проекта, uid:40, — рабочий день 00:00–00:00
все 7 дней недели, т.е. круглосуточный календарь). Категория `unsupported_semantics` (row 8,
exit 5, schedule-affecting). `proposals` в operation show пуст, поэтому штатным resume с
`--accept-proposal` это не снимается и флаг «игнорировать предупреждения» не выдумывается.
Архив уже сохранён (snapshot_9686afab…, archive=verified, operation_56d682a69c…).

## Решение владельца
План с круглосуточным рабочим календарём (все 7 дней, интервал 00:00–00:00) публикуется
как есть (publish-as-is), по аналогии с принятым решением fix4 для вехи
(`milestone_interval_conflict=publish_collapsed`, owner-decision-v1.json):
плагин отображает даты как снимок из MPP, календарный интервал не пересчитывается;
исходные даты/интервалы остаются в архиве; MPP не правится; добавить пометку о
круглосуточном календаре. Скилл должен принимать такие планы БЕЗ вопросов (постоянное
правило владельца, а не разовая операция).

## Что не меняется
- Числа A–D и полный gate §20 master-ТЗ EditPlanConfluence не ломать.
- Confluence/Gateway/cron не трогать. Секреты (CONFLUENCE_TOKEN) не выводить.
- Изменение владельческой директивы не подменяет независимую REV-проверку.
