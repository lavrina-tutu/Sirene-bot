# Формат страниц-протоколов "Задачи и договоренности (Минутки)"

Найдено на реальных примерах (07.2026): Trisigma (pageId 490170597), AI-ready Трансформация
(pageId 499570832), AI-аналитик/AI-MAS (pageId 477061038) — все три дочерние страницы
корневых проектных страниц (`card.md.confluence_id`), находятся через:

```bash
curl -s -H "Authorization: Bearer $CONFLUENCE_TOKEN" \
  "https://dom.tutu.ru/rest/api/content/<rootPageId>/child/page?limit=50"
```

## Два подтверждённых варианта таблицы

### Вариант А (Trisigma, AI-ready) — 2 колонки, эталон по решению пользователя (09.07.2026)

Заголовок: `Дата постановки | Задачи и Договоренности`.

Каждая строка = одна встреча/день. Внутри правой ячейки — свободный текст с блоками
`Участники:` / `Решения:` / `Блокеры:` / `Задачи:` / `Риски:` как `<h2>` + `<ul>`, задачи —
`<ac:task-list>`. Порядок вставки новых строк **не единообразен между проектами** — Trisigma
подписан "Последние задачи сверху списка" (новое сразу после заголовка), AI-ready подписан
"снизу-вверх" (новое в конец, перед служебной строкой "вверх"). Пользователь зафиксировал:
**для нового инструмента — новые встречи всегда добавляются сверху**, независимо от того, как
конкретный существующий протокол был устроен раньше.

### Вариант Б (AI-MAS/AI-аналитик) — 3 колонки, отдельное поле участников

Заголовок: `Дата | Участники | Итоги`. Колонка "Участники" — **простой текстовый список**
(`<ul><li>ФИО</li></ul>`), БЕЗ `<ac:link>`-mention — контраст с mentions внутри самих задач.
Колонка "Итоги" содержит те же блоки Решения/Блокеры/Задачи, что и в Варианте А.

## Формат задачи (`<ac:task>`) — общий для обоих вариантов

```xml
<ac:task-list>
<ac:task>
<ac:task-id>101</ac:task-id>
<ac:task-status>incomplete</ac:task-status>
<ac:task-body><ac:link><ri:user ri:userkey="8a8383b5..." /></ac:link> Trisigma. Текст задачи <time datetime="2026-07-15" /> </ac:task-body>
</ac:task>
</ac:task-list>
```

Ключевые находки:
- `ac:task-status` — `incomplete` / `complete` (не `done`/`todo`).
- Исполнитель — реальный Confluence `@mention` через `<ri:user ri:userkey="...">`, НЕ email/текст.
  Резолв userkey — см. основной SKILL.md, раздел "Резолв пользователя Confluence".
- **Тег проекта — не формальный макрос**, а вручную напечатанный текстовый префикс перед
  текстом задачи: `"Trisigma. <текст>"`, `"AI-ready.<текст>"`, `"AI-аналитик.<текст>"`.
  Значение тега — разговорное имя проекта как оно фактически используется в существующих
  протоколах, НЕ обязательно совпадает с полем `name` в `card.md` (пример: slug `ai-mas` →
  тег `"AI-аналитик"`, slug `ai-transformaciya` → тег `"AI-ready"`). Пользователь решил
  (09.07.2026): собрать отдельный реестр тегов по фактическому употреблению в протоколах,
  не выводить автоматически из `card.md.name`.
- **Дата задачи** — не отдельный `<ac:date>` макрос (гипотеза не подтвердилась), а **inline**
  `<time datetime="YYYY-MM-DD" />` внутри `<ac:task-body>`, обычно в конце текста.
- Иногда встречаются доп. Jira-макросы внутри задачи (`<ac:structured-macro ac:name="jira">`)
  и inline-комментарии (`<ac:inline-comment-marker>`) — не мешают парсингу, можно игнорировать
  при первой версии инструмента.
