# Оценка конкретного железа под локальные LLM для Hermes

Divide any hardware question into TWO scenarios BEFORE looking at specs — they have different answers:

1. **Оркестрация Гермес на локальной модели** → почти всегда НЕТ (см. Rule 3 SKILL.md). Агентная оркестрация = много последовательных итераций, тул-коллов, длинных контекстов; локально это либо мелкие модели (качество ниже flash-API за копейки через шлюз), либо большие на 3–8 ток/с — оркестрация встаёт. Внешний Tutu-шлюз (DeepSeek-flash ~$25/мес + Sonnet-ревизор + Codex Sol) не заменить локально ни на каком настольном железе.
2. **Локальные LLM как ДОП сценарий** (приватность, оффлайн, эксперименты, суммы в чаты без интернета) → ВОЗМОЖНО и тогда железо имеет смысл. Оценивать по критериям ниже.

## Критерии оценки мини-ПК под локальный инференс

| Фактор | Что смотреть | Признак «хорошо» |
|---|---|---|
| **RAM** | Ограничивает класс модели (Q4-квант: ~32 ГБ ≈ 30–40B, ~64 ГБ ≈ 70B). Фиксирована, не апгрейдится | Чем больше — тем лучше; главный ресурс |
| **iGPU vs дискретка** | Маркетинговое «AI-творчество»/NPU — НЕ замена VRAM. Интегрированный GPU (Radeon 890M и т.п.) делит память, ускоряет только модели ≤~14B, упирается в bandwidth памяти | Дискретная VRAM — реально быстрее; iGPU — умеренный бонус |
| **Пропускная способность памяти** | Потолок CPU/iGPU-инференса (~90 ГБ/с у DDR5-5600) | Чем выше (LPDDR5X/HBM) — тем быстрее большие модели |
| **Скорость по размеру модели** | 7–14B Q4 → рабочие 15–30 ток/с (iGPU); 32B → 3–6 ток/с — для оркестрации непригодно | Для диалога хватит 7–14B; для агентной работы — мало |
| **SSD** | Место под веса моделей (32B Q4 ≈ 20 ГБ, можно держать несколько) | ≥512 ГБ достаточно, 1 ТБ — запас |
| **Сеть** | 10GbE для Hermes+Nextcloud избыточно (хватает 1Gb); полезно только под NAS/видео, не для LLM | Не платить за неё ради LLM |
| **ОС/Linux** | Целевой хост — чистый Linux, как на ВМ (AlmaLinux 9.x) | Стирает заводскую ОС, SSH по ключу |

## Три pitfall при оценке железа
- **Назвал модель — сверь, а не бери опечатку из объявления.** Промо-тексты уродуют модели (напр. «Ryzen AI 9 HX 470» — таких нет, реальная серия HX 370). Оценка по несуществующей модели невалидна.
- **«NPU»/«AI»-бейдж ≠ ускорение LLM.** NPU (XDNA и пр.) разгружает локальные мелкие инференсы в Windows-стеке, но для LLM-инференса через llama.cpp/Ollama на Linux решающую роль играет CPU+RAM+bandwidth, не NPU TOPS.
- **Сравнивать чтобы понять цену-за-характеристики, не покупать по маркетингу.** 64 ГБ за цену 32 ГБ-машины — реальное преимущество именно под локальные LLM; но если цель оркестрация — преимущество ничего не даёт.

## До/после рекомендации
- НЕ предлагать покупку без ответа на вопрос «под какой сценарий» (оркестрация vs доп. локальные). Это меняет весь вывод.
- Отвечать по существу первым абзацем, затем критерии; ценовые/характеристики — из текущего каталога, не из памяти.
- Дизайн-развилка по железу в dev-графе: вердикт даёт архитектор (cursor-cli, роль architect), Сирень подаёт его решение, не своё.
