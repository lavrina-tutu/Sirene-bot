# RTF-клонирование эталона (финальный .rtf резюме)

Когда: собрать готовый `.rtf` по эталону (RTF-экспорт hh.ru / корп. шаблон), наполнив его актуальным содержанием, сохранив 1:1 шрифты, цвета, таблицы, границы, фото и колонтитулы.

## Подход: клонировать каркас, подменить тело

НЕ пересобирать RTF с нуля. Скопировать скелет эталона побайтово, заменив только содержимое секций:

- **framework** = байты от `{\rtf1` до первой `\trowd` тела: `fonttbl`, `colortbl`, `stylesheet`, `theme`, `sectd`, колонтитулы (`\headerl/\headerr/\footerl/\footerr`), нумерация списков. Копировать как есть.
- **шапка** = от первой `\trowd` до начала первой секции (фото `\pict` + ФИО + контакты). Копировать как есть; мелкие правки (возраст, добавить поле) — точечной заменой подстроки, не перегенерацией.
- **tail** = от `{\*\latentstyles` (или `{\*\datastore`) до конца файла — закрывающие группы + OLE. Оставить целиком.
- **body** = секции генерировать заново теми же управляющими командами (`\trowd … \cell … \row`, `\f1`, `\fsN`, `\cfN`).

Проверка: `{`==`}` по счёту; `\pict` (фото) и `\datastore` не трогать.

Границы блоков искать через рабочий рекурсивный парсер RTF→(byte_offset, char), который пропускает служебные группы (`fonttbl`, `colortbl`, `stylesheet`, `info`, `pict`, `object`, `listtable`, `datastore`, `themedata`, `latentstyles`, `generator`, `header*/footer*`, `sp/sn/sv`, `picprop/shppict/shp`, `pntext/pntxta/pntxtb`), а остальной текст декодирует `\'xx`. Плоский парсер, пропускающий ВСЕ группы `{…}`, возвращает 0 символов — текст в RTF лежит внутри групп.

## Кодировка

RTF cp1251 хранит кириллицу как `\'xx` hex. Не-ASCII → `\'%02x`, ASCII/цифры/пунктуация — как есть:

```python
def enc(s):
    out=[]
    for ch in s:
        o=ord(ch)
        if o<128: out.append(ch)
        else: out.append(''.join("\\'%02x"%c for c in ch.encode('cp1251')))
    return ''.join(out)
```

Итоговый файл писать `content.encode('cp1251')`. Буквы `ё`, `—` (em dash 0x97), `·` (0x95), `«»` (0xAB/0xBB), `’` (0x92), `–` (en dash 0x96) — есть в cp1251.

## Типографика эталона hh.ru (иначе «всё сливается»)

- Заголовок секции: Arial `\f1` 12pt `\fs24`, серый `\cf22`, под ним тонкая серая линия `\brdrb\brdrs\brdrw15\brdrcf24`.
- Компания / должность: Arial 12pt **жирный** `\b`, чёрный.
- Тело / буллеты: Arial 9pt `\fs18`, чёрный.

Заголовок и содержимое РАЗНЕСЕНЫ по размеру (12pt vs 9pt) и цвету (серый vs чёрный) — это и есть визуальная иерархия. Один размер у всего = «сливается». Каждая строка тела — `\pard \intbl \ql … ` с явным `\f1\cf0\fs18`.

## Питфоллы

- **Цвет наследуется**: `\cf22` (серый) на заголовке секции протекает в следующий абзац, если его не сбросить — весь блок становится серым. Каждый абзац тела начинать с `\cf0` (или `\cf1` чёрный) после цветного заголовка.
- **Текст фрагментирован**: Word/hh.ru вставляют `\loch\f1 \hich\f1` и переносы строк между словами/буквами — поиск фразы подряд НЕ работает. Искать короткий уникальный хвост слова (напр. `\'e2\'ea\'e0\'ec` = конец «командировкам») и учитывать вставки.
- **Маркер поиска — с бэкслэшем**: control word в файле это `\rtlch`; в raw-строке писать `rt"…}{\rtlch"`, а не `"}{rtlch"` — без `\` маркер не найдётся (`assert` упадёт).
- **`\trowd` и `\row` не всегда парны**: вложенные таблицы hh.ru дают `\trowd` > `\row` в счётчиках — это нормально; свои сгенерированные строки обязаны закрываться `\cell \row` каждую.
- **pandoc пишет, но не читает RTF** (`-f rtf` → `Unknown input format rtf`) — round-trip через pandoc невозможен; только прямая правка/генерация.

## Regeneration

Держать результат детерминированным: один markdown-источник секций (содержательное наполнение, с правками опечаток) + скрипт-генератор, который читает эталон + markdown и пишет `.rtf`. Имя итогового файла несёт версию (`…_rev5.rtf`). По каждой правке (добавить курс, возраст, поле) — править markdown-источник и/или точечную подстановку в шапке, запускать скрипт, сверять текст и баланс скобок.
