# Loop: отправка DM и массовая персонализированная рассылка

Проверено на проде 17.08.2026 (рассылка Trisigma по таблице исполнителей).

## 1. Отправка личного сообщения (DM) конкретному пользователю

Паттерн «резолв пользователя → создать/найти DM → отправить пост».

### Шаг 1 — резолв получателя (autocomplete, надёжнее `users?term=`)

```bash
curl -s --max-time 15 -H "Authorization: Bearer $LOOP_TOKEN" \
  --get --data-urlencode "name=krivorotov" \
  "https://loop.tutu.ru/api/v4/users/autocomplete"
```
→ `users[]` + `out_of_channel[]`; взять `id` нужного пользователя.

**Питфолл резолва:** логин в Loop не всегда совпадает с транскрипцией ФИО.
Пример: «Воробьева» → `vorobeva`, а НЕ `vorobyeva`. При пустом/неполном результате
перебирать варианты (`vorobev*`, `vorobyov*`, `vorobeva` и т.п.).

### Шаг 2 — создать/найти DM-канал

⚠️ **Тело — JSON-массив строк id, НЕ объект:**
```bash
curl -s -X POST -H "Authorization: Bearer $LOOP_TOKEN" -H "Content-Type: application/json" \
  -d "[\"$MY_ID\",\"$OTHER_ID\"]" "https://loop.tutu.ru/api/v4/channels/direct"
```
Объект `{"user_ids": [...]}` → `400 api.payload.parse.error: cannot unmarshal object into Go value of type []string`.
Если DM уже существует — эндпоинт вернёт существующий канал. Ответ: `id` (type `D`).

### Шаг 3 — отправить пост

⚠️ **Для DM-каналов `POST /channels/{id}/posts` НЕ работает** → `404 api.context.404.app_error: missing a team_id`
(direct-каналы имеют пустой `team_id`). Использовать глобальный эндпоинт с `channel_id` в теле:
```bash
curl -s -X POST -H "Authorization: Bearer $LOOP_TOKEN" -H "Content-Type: application/json" \
  -d "{\"channel_id\":\"$CH\",\"message\":\"...\"}" \
  "https://loop.tutu.ru/api/v4/posts"
```
→ `id` поста; ссылка на сообщение: `https://loop.tutu.ru/tutu/pl/{post_id}`.

`requests`/`httpx` и здесь зависают на loop.tutu.ru — использовать `curl` через subprocess.

## 2. Массовая персонализированная рассылка по таблице (предпочтения Саши)

Когда один шаблон рассылается N исполнителям из таблицы (JIRA-задачи / подразделения /
исполнители), например для сбора оценок по проекту:

1. **Обращение — только имя, и именно та форма, что написана в таблице/списке**, НЕ полное
   ФИО из резолва Loop. Пример: в таблице «Лебедев Миша» → «Привет, Миша!», даже если в Loop
   он «Михаил». Аналогично «Базаров Саша», «Бугрова Оля», «Полусмак Настя», «Воробьева Аня» —
   форма из списка, не из Loop. (Саша дважды поправил на это.)
2. Сообщение на каждого — персональное: свой `<Подразделение в дат. падеже>` и своя
   `<ссылка на задачу JIRA>` встраиваются в текст шаблона.
3. Исключать получателей по явному указанию Саши (напр. «Криворотову и Некипелову не
   отправляем») — держать отдельный список «кому отправляем» и сверяться с ним перед массовой отправкой.
4. Перед массовой рассылкой — показать Саше итоговую таблицу «имя для обращения + username +
   подразделение + задача» и дождаться «отправляй».
