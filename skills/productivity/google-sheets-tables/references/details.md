## 1. Критический питфолл реавторизации — не перегенерировать ссылку

Скрипт `setup.py` хранит pending OAuth-состояние (`state` + `code_verifier`) в `~/.hermes/google_oauth_pending.json`. **Каждый `--auth-url` перезаписывает этот файл новым verifier.** Если юзер уже отправил вам `code`, а вы ДО обмена кода ещё раз запустили `--auth-url` (напр. чтобы «обновить» ссылку) — старый `code` больше не совпадает с сохранённым verifier, и `--auth-code` падает:

```
ERROR: Token exchange failed: (invalid_grant) Invalid code verifier.
```

Значит: **всегда генерируй ссылку ОДИН раз, жди код, обменивай немедленно.** Не дергай `--auth-url` повторно до успешного обмена. Если `--auth-code` уже дал ошибку про verifier на старый код — сгенерируй свежую ссылку и попроси юзера пройти по ней ещё раз (старый код мёртв).

## 2. batchUpdate форм-фактура (питфоллы, встречены вживую 10.09.2026)

- **`values().batchUpdate` НЕ существует.** Для заливки фона/формата вызывай `spreadsheets().batchUpdate` (POST на `/spreadsheets/{SID}:batchUpdate`) с телом `{"requests":[...]}`. `values().batchUpdate` → HTTP 400 `Invalid JSON payload received. Unknown name "requests"`.
- **`updateCells.range` — это GridRange-объект, НЕ A1-строка.** Строка вида `"Лист1!A2:K2"` в `updateCells` → HTTP 400 `Invalid value at 'requests[0].update_cells.range'`. GridRange = `{"sheetId":<int>,"startRowIndex":..,"endRowIndex":..,"startColumnIndex":..,"endColumnIndex":..}` (sheetId брать из `spreadsheets().get()`, индексы 0-based, НЕ хардкодить 0).
- **Раскраска фона построчно (проверенный паттерн):**
  ```python
  meta = svc.spreadsheets().get(spreadsheetId=SID).execute()
  sheet_id = meta['sheets'][0]['properties']['sheetId']
  reqs=[]
  for r in range(1, N):  # data rows; row 0 = header
      rg={"sheetId":sheet_id,"startRowIndex":r,"endRowIndex":r+1,"startColumnIndex":0,"endColumnIndex":11}
      reqs.append({"updateCells":{"range":rg,"fields":"userEnteredFormat.backgroundColor",
          "rows":[{"values":[{"userEnteredFormat":{"backgroundColor":{"red":217/255,"green":234/255,"blue":211/255}}} for _ in range(11)]}]}})
  svc.spreadsheets().batchUpdate(spreadsheetId=SID, body={"requests":reqs}).execute()
  ```
- **RGB дробью, не целым:** при `updateCells` задавай `"red":217/255` и т.п. Целыми `217`/вычисление с итогом `int` даёт цвет-сосед (прослеживается как `#D9EAD2` вместо `#D9EAD3`). Точные канон-цвета: зелёный `#D9EAD3`=`217/234/211`, розовый `#F4CCCC`=`244/204/204`, серый `#CCCCCC`=`204/204/204`.
- **Чтение фона: пустая ячейка может не иметь ключа `values`.** При `spreadsheets().get(...,fields="...backgroundColor")` строки без заливки приходят без `values` или с пустыми значениями — читать через `rd.get('values',[{}])` и fallback на `{}`, не `rd['values'][0]` (иначе `KeyError`).

## 3. Питфоллы (полный текст)

- **Русская локаль Google Sheets (ru_RU): разделитель аргументов в формулах — `;`, десятичная запятая — НЕ точка.** Запись формулы с запятыми через API (`=IF(1>0,"a","b")`) даёт `#ERROR!` на листе с locale=ru_RU; число с точкой `1.7` в USER_ENTERED парсится как **дата** (1 июля) → серийный номер ~46204 вместо 1,7 и молча взрывает все вычисления (напр. X в миллиардах). Формулы писать с `;` (`=IF(1>0;"a";"b")`), десятичные литералы в ячейках — с запятой (`1,7`). Диапазоны `:` и строки в кавычках не меняются. `=1+1` без аргументов работает и с `,` — не вводит в заблуждение. Проверять локаль: `GET /spreadsheets/{SID}?fields=properties.locale`.
- **После записи сетки формул со ссылками на ячейки-параметры — читать ОБРАТНО вычисленные значения контрольных ячеек (первую строку данных, итог/окупаемость) и сверять с ожиданием.** Сдвиг блока параметров на строку (лишний заголовок в списке значений) молча ломает все ссылки `$B$9..`: значения правдоподобны, но неверны; красный флаг — неожиданный результат («окупаемость в 1-м месяце», ячейка-произведение в миллиардах). Записал → прочитай 2-3 контрольные ячейки → только потом отчитывайся.
- **Большие/кириллические массивы писать через Sheets API v4 urllib PUT, НЕ через `google_api.py sheets update --values`.** Для 200+ строк с кириллицей и кавычками в значениях CLI-флаг `--values '<JSON>'` склеивается в bash-строку и ломается на кавычках/длине — результат не пишется. Проверенный путь: собрать `rows=list[list[str]]` в execute_code → `api("PUT", f"https://sheets.googleapis.com/v4/spreadsheets/{SID}/values/{urllib.parse.quote('Лист!A1:E208')}?valueInputOption=RAW", {"range":"Лист!A1:E208", "values":rows})` (см. «Прямой API»).
- **Сетку из 100+ строк пиши ОДНИМ PUT, не построчно** — построчная запись (по ячейке/строке в цикле) упирается в лимит запросов: HTTP 429 Too Many Requests посреди записи, и перезапуск цикла снова упирается. Чанк на весь диапазон (`A24:H203`, 180 строк формул) проходит за один запрос. Построчно — только когда большой пакет упал с 400 и надо локализовать виновную ячейку (тогда построчная запись с try/except, вывод номера строки).
- **Новый документ с понятным именем таба создавать явно:** `google_api.py sheets create --title "..." --sheet-name "Активные"` → вернёт `spreadsheetId` + URL; имя таба тогда известно заранее (не гадать «Лист1»). id таба брать из `GET /spreadsheets/{SID}` `sheets[].properties.sheetId` для формат-запросов (не хардкодить 0).
- **Колонка «Попадает в релиз» в выгрузке задач Jira = зарезолвить как `fixVersions`, не искать отдельный customfield** (в карте полей фигурирует как "Версия"/fixVersions).
- **Делиться доступом на корп. рабочий адрес (@tutu.tech и др. не-Google аккаунты) — только с `--notify`.** Drive Permissions API падает с 400 `"К этому адресу не привязан аккаунт Google, поэтому необходимо установить флажок 'Оповестить по электронной почте'"`, когда `sendNotificationEmail` выключен (по умолчанию). Фикс:
  ```bash
  GAPI="python ${HERMES_HOME:-$HOME/.hermes}/skills/productivity/google-workspace/scripts/google_api.py"
  $GAPI drive share <SHEET_ID> --email gladkikh@tutu.tech --role writer --notify
  ```
  Пример из сессии (02.09.2026): Гладких Юрий = `gladkikh@tutu.tech` (логин `gladkikh`; корп. домен ТУТУ — именно `@tutu.tech`, не `@tutu.ru`). Перед расшаркой адрес искать через `show-contacts` (store.find_contacts_for_display('фамилия')), не угадывать домен — по запросу «гладких» нашлись и `gladkikh` (Юрий), и `gladkikhda` (Дарья).
- **Питфолл генерации сетки в execute_code: НЕ переиспользовать имя переменной цикла для вычисляемых ячеек.** При сборке `rows` в цикле `for i in range(...)` нельзя внутри тела присваивать `i = "=SUM($C$19:C{r})"` (имена колонок накопления) — в Python `i` затёрт и в `str(i)` для номера месяца уходит уже формула, колонки смещаются, все ссылки дают `#REF!`. Использовать отдельные имена для счётчика и для колонок (`mi` для месяца, `icol/jcol/kcol/lcol` для формул). Этот баг проявляется ТОЛЬКО на чтении-проверке после записи (B-колонка = #REF!), а запись «успешна» — контролировать колонку номера месяца сразу после PUT.
- **Заголовок таблицы и блок параметров не должны делить строку.** Писать блок параметров и заголовок помесячной таблицы на РАЗНЫЕ строки с явной пустой строкой между ними; если заголовок перекрыл строку параметра (напр. формула crossover в B15 затёрта заголовком "№") — результат `#REF!` и битый MATCH. При addSheet/перезаписи сверять макеты: параметры строки 1..N, таблица со строки N+3.
- **Не верить дефолтному имени листа** «Sheet1» из примеров — на RU-аккаунтах реально «Лист1».
- **Файл в Drive — это Office-вложение (.xlsx), а не нативная Google-таблица** → Sheets API `values.get` падает с `HttpError 400 ... "This operation is not supported for this document. The document must not be an Office file."` даже при валидном токене. Распознать до чтения: `google_api.py drive get <id>` → `mimeType: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` (нативный Google Sheet — `application/vnd.google-apps.spreadsheet`). Если .xlsx-upload: не читать через sheets API, а скачать через Drive и разобрать локально: `drive download <id> --output /tmp/f.xlsx`, затем распаковать xlsx как zip (`xl/worksheets/sheetN.xml` — данные, `xl/sharedStrings.xml` — строки, `xl/workbook.xml` + `xl/_rels/workbook.xml.rels` — имена/порядок листов). openpyxl может отсутствовать и в sandbox, и в venv — парсинг на stdlib zipfile+ElementTree надёжен. Такой лист ещё и заметно больше нативного гугл-документа (413 КБ vs 100 КБ) — тоже подсказка.
- **`--auth-url` один раз** (см. критический питфолл).
- Применение notes/форматов по критериям — сопоставлять строки по канону текста колонки A (`.startswith(key)`), а не по жёстко зашитым номерам строк: секции-подзаголовки сдвигают нумерацию.
- Таблицы-шкалы, вложенные в Confluence-критерий (5/4/3/2/1), в таблицу-артефакт не тянуть, если просят описание «для справки» — шкала идёт в note, не отдельным столбцом.

## 6. Модель окупаемости / сравнение затрат (полный текст)

### 6.1 Обязательный первый шаг — семантика модели
НЕ строить, пока модель затрат не подтверждена. Собрать у Саши полную семантику затрат по обоим сценариям, пересказать её по-человечески (что разово, что ежегодно, что ВКЛЮЧЕНО в цифру, что платится параллельно) и получить «да» до записи. В сессии 2 из 3 правок были семантикой модели («X уже включает сопровождение 1 152 000, отдельно не прибавлять», «у Trisigma платится и лицензия 4 млн, и сопровождение 1 152 000»), а не формулами — переделка таблицы после неверной семантики дорога. Саша сам просит «повтори, как поняла» — это сигнал к подтверждению, а не к немедленной записи.

### 6.2 Производные цифры из явных вводных
Не подставлять готовое значение. Пример: стоимость содержания специалистов = ставка × часы/мес × FTE × 12 (3000 × 160 × 1,7 × 12 = 9 792 000), а не «захардкоженное число». Вводные — отдельные изменяемые ячейки, производные — формула от них (B7=B4*B5*B6), тогда Саша меняет вводные и пересчёт живёт сам.

### 6.3 Структура таблицы (проверенный формат)
1. Блок входных параметров (ставки, сроки, лицензии, ставка×часы×FTE → годовая стоимость) — ячейки-параметры, меняются юзером.
2. Блок результата: месяц окупаемости + лет — формулой `INDEX(диапазон;MATCH("ОКУПАЕМОСТЬ";столбец_статуса;0))` по столбцу-статусу, не считая самому.
3. Помесячная таблица (горизонт ~15 лет): дата месяца, затраты сценария А/мес, сценария Б/мес, накопленно обоих, разница накопленная, столбец-статус `=IF(AND(разница<=0;разница_предыдущая>0);"ОКУПАЕМОСТЬ";"")`.
4. Блок чувствительности по ключевому параметру (напр. X — стоимость содержания специалистов): X → месяц окупаемости → лет → вывод. Показывает, при каком X окупаемость наступает/не наступает вовсе — это часто и есть ответ «окупится или нет».
5. Условное форматирование: строка со статусом «ОКУПАЕМОСТЬ» подсвечивается зелёным (TEXT_EQ по столбцу-статусу) — месяц виден глазами при любом изменении параметра.

### 6.4 Разовую стоимость показывать симметрично — блоком на месяцы
Разовую стоимость (внедрение вендора И доработку своей) показывать симметрично — блоком на месяцы её длительности. В колонке сценария разовый платёж делится равными долями на месяцы работ (внедрение Trisigma 18 705 000 / 12 мес = 1 558 750/мес; доработка своей 6 342 000 / 10 мес = 634 200/мес). Это требование Саши (19.10.2026) — НЕ убирать разовую доработку как «двойной счёт»: 18,7 млн внедрения тоже не только ФОТ команды (там аналитики, архитекторы, админ-ресурс), поэтому симметричное представление доработки своей корректно для сравнения. Архитектор может назвать это двойным счётом — показать ему возражение владельца и применять решение Саши.

### 6.5 Рекуррентная ставка «своя» — решение владельца, не автоподстановка X/12
После разового блока Саша вправе выбрать: (а) содержание команды по ФОТ X/12, или (б) постоянный темп доработок = разовый объём / его месяцы (6 342 000 / 10 = 634 200/мес) во ВСЕХ месяцах — аргумент «платформу дорабатываем всеми ресурсами (аналитики, архитекторы, админ-ресурс), не только 1,7 специалистами, и темп сохраняется после блока». Вариант (б) делает «свою» дешевле и резко отодвигает/убирает окупаемость Trisigma — это не баг, а следствие вводной. Всегда спрашивать, какой темп после завершения блока: ФОТ команды или темп доработок; в пояснениях грамотной фразой фиксировать, ПОЧЕМУ в колонке такие цифры, а не 1,7 FTE/ФОТ.

### 6.6 С предоплатой лицензии — статус только на первом пересечении
С предоплатой лицензии раз в год (а не 1/12) накопленная разница пересекает ноль НЕСКОЛЬКО раз — статус «ОКУПАЕМОСТЬ» должен ставиться только на первом переходе. Формула `IF(AND(G{r}<=0;G{r-1}>0);...)` даёт вторую метку после очередной предоплаты (Trisigma снова накопленно дороже, потом опять дешевле). Помечать только первое пересечение: `=IF(AND(G{r}<=0;COUNTIF($G$24:G{r};"<=0")=1);"ОКУПАЕМОСТЬ";"")` — флаг, когда в диапазоне от начала ровно одна ячейка ≤0. Внимание: внутри COUNTIF разделитель тоже `;` (русская локаль), запятая в критерии `,"<=0"` → #ERROR!.

### 6.7 Границу «разовое vs рекуррентное» определяет владелец
Не класть труд дважды — но границу «разовое vs рекуррентное» определяет владелец модели, не архитектор. Архитекторский вердикт «разовая доработка = те же люди, что в X, не слагаемое» был переопределён Сашей: он хочет видеть разовую доработку отдельным блоком на её месяцы (симметрия с внедрением вендора), а X — только после. Это самый частый источник спора в таких моделях: арифметика сходится, спор про семантику, и решает владелец. Если владелец просит «показывать доработку так же, как показано внедрение» — выполнять, даже если архитектор считает это двойным счётом; фиксировать оба взгляда в ответе, применять решение Саши.

### 6.8 Crossover TCO ≠ «окупаемость вложений»
Помесячное сравнение двух сценариев даёт месяц, когда накопленные затраты сценария А ≤ накопленные сценария Б. Это «месяц, когда TCO Trisigma ≤ TCO своей», а НЕ «возврат 18 млн». Разница важна: при сравнении кумулятивных потоков сходятся и «виртуальные» зазоры (лицензии, ФОТ, сопровождение), не только инвестиция. В ячейке-результате подписывать «crossover TCO», а в ответе Саше отдельно пояснять, что именно закрыто к этому месяцу (зазор за счёт ежегодной экономии), и что вернуть «18 млн как инвестицию» модель не обещает.

### 6.9 Прожарка архитектором — шаг, не опция
Экономическую модель обязательно прогнать через архитектора. Саша явно просит «критически прожарь расчёт и вводную архитектором» для финального варианта. Собрать бриф: полные вводные (что разово/ежегодно/включено), текущую модель, ТОЛЬКО вопросы для прожарки (верны ли допущения, корректна ли методология «окупаемости», что упущено). Архитектор (через codex CLI, gpt-6-astra, invoke-role) найдёт семантические ошибки (двойной счёт, необоснованное допущение освобождения ресурса, сглаженную вместо предоплаты лицензию) и даст пороги чувствительности. Если Саша после вердикта уточняет вводную, которая меняла ключевое допущение — продолжить resume сессии роли с пересказом уточнения, не перегенерировать.
