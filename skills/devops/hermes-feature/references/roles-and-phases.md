# Роли и фазы для предметной работы

Единственный процесс — `devops/dev-workflow` и Б55. Этот reference не содержит самостоятельной очереди, launch-команд, моделей или маршрута через чат. Роль запускает только pipeline после `emit-prompt`; backend/model берутся из YAML.

| Область | Владелец | Предметная граница |
|---|---|---|
| ТЗ, план/IAC, риски, диагноз | архитектор | пишет канонный файл, не код и не state |
| Независимый verdict | ревизор | `REV:tz`/`REV:plan`, не двигает очередь |
| Реализация и IAC.verify | исполнитель | согласованный write-set, backup/QA evidence; не меняет план и не владеет `HF:docs-handoff` |
| Backup, docs handoff, shared state, gates | оркестратор | действует по G6 и плану; не принимает содержательные решения |

## Предметные проверки

1. До реализации: verify backup, identity/target, write-set и отсутствие неразрешённой новой сущности.
2. Во время реализации: не менять production state, секреты, Gateway, cron или конфиг вне плана; фиксировать дифф и rollback evidence.
3. На тесте: исполнить `IAC.verify`; разделять component/unit PASS, runtime FAIL и отсутствующее evidence.
4. Для бага: собрать факты в `BUG:diagnose`, затем вернуть архитектору подтверждённый диагноз/план; не чинить по предположению.
5. Для research: читать и документировать факты без записи, пока не появится отдельный утверждённый контракт.

`HF:impl` и `HF:test` — разные вызовы. Запросы об изменении требований, повтор замечания и техническое восстановление регулируются тремя разными регламентами `dev-workflow/SKILL.md`.
