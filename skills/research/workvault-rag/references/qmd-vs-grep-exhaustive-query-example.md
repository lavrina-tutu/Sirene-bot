# qmd vs grep — exhaustive query example (09.07.2026)

## Задача

Саша спросил: «какие открытые задачки ждёт от меня Александр Аралов? что мы обсуждали с ним за последние 2 недели?» (сессия 07–09.07.2026, коллекция `meetings-summary`).

Это exhaustive-запрос: сущность (Аралов) × диапазон дат (24.06–08.07), нужен полный список, не топ-N по релевантности.

## Что вернул grep (ground truth)

Прямой поиск `grep -l "Аралов" *.md` + фильтр по дате префикса имени файла (24.06–08.07) дал **18 файлов** с упоминанием Аралова в этом диапазоне, из них 8 встреч с реальными задачами/рисками, адресованными ему или обсуждёнными с ним, включая самые свежие: 07.07 (AI-мультиагентная система — риск про Delivery), 08.07 (AI-ready трансформация — задача про нового лидера; АДМ ЧЕКИН — риск про ДВХ).

## Что вернул qmd (`mcp_qmd_query`, collections=["meetings-summary"])

Два прогона:
- `candidateLimit` default, `limit=15` → 0 из нужных 8 июльских встреч в топе (топ занят апрельскими/майскими документами лексически ближе к запросу "Аралов Александр задача")
- `candidateLimit=200`, `limit=60` → всё ещё **только 2 из 8** релевантных встреч попали в выдачу (07.01, 07.02), причём без раскрытия конкретных action items в сниппете. 07.07 и 08.07 не появились вообще ни в одном прогоне.

## Почему

- qmd коллекция `meetings-summary` индексирует **содержимое** файла (текст summary), не путь/имя файла. Дата видна модели только если она явно упомянута в тексте документа (например "10 июля" как дедлайн внутри обсуждения) — сама дата встречи (из имени файла) не участвует в ранжировании.
- BM25+vector ранжирует по семантической близости запроса к тексту документа. Старые документы, где тема упомянута плотнее/явнее, обходят свежие документы с более короткими/лаконичными упоминаниями — независимо от того, что свежие релевантнее по факту недавности.
- Добавление слова "июль 2026" в vec-запрос не действует как фильтр — это не структурированный date range, просто ещё один токен для семантического сходства, который может случайно попасть в резонанс с нерелевантным документом (например обсуждением дедлайна "10 июля" в апрельской встрече) и пропустить реально майский/июльский документ, где слово "июль" не встречается текстуально.

## Вывод / паттерн на будущее

Для запросов вида **"все X от/про Y за период Z"** — сначала пре-фильтр по дате (имя файла, `search_files` или прямой листинг директории с проверкой префикса даты), потом уже внутри суженного набора — точечное чтение или qmd для смысловой навигации. qmd хорош для смысловых/нечётких вопросов без жёсткого структурного требования на полноту по датам, но не гарантирует полноту при exhaustive date-range запросах.
