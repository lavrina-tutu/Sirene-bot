| ID | Решение | Контекст | Статус | TZ ref |

| **PD-058** | **Поиск объекта для `_DELETE`/`_UPDATE`:** reconciler находит задачу/решение/риск **по смыслу** (Haiku), не по точному совпадению текста. Идентификатор `^{slug3}{hex}` в команде задаёт цель явно, когда указан. | Q-B5 (30.06), PD-052 | `in_tz` | TZ_F (протокол маркеров) |
| **PD-057** | **Единый ID сущностей `^{slug3}{hex}`:** Obsidian block reference в конце строки. `slug3` — 3-буквенный код проекта; `hex` — сквозной счётчик внутри проекта+тип без ведущих нулей (`^trx11`, `^trx27ff`). Тип (T/D/R) определяется блоком, в ID не дублируется. Счётчики — `state.json → last_ids: {slug3: {T,D,R}}`. Ссылки `[[срез#^trx11]]` работают нативно. | Q-B5/Q-B6 (30.06), PD-052 | `in_tz` | TZ_G (§5), TZ_F |
| **PD-056** | **Синтаксис команд PM Notes:** маркеры `_ADD` / `_DELETE` / `_UPDATE` + свободный текст. Тип сущности — по заголовку подблока `### PM Notes (tasks\|decisions\|risks)` под соответствующей секцией среза (лейбл страхует от поломки разметки Obsidian). | Q-B4 (30.06), PD-052 | `in_tz` | TZ_G (§5), TZ_F |
| **PD-055** | **Изменение в срезе = перезапись без истории:** срез G — сырая агрегация робота; PM Notes в срезе исправляют ошибки транскрибации → `_UPDATE` перезаписывает текст на месте без сохранения старой версии. История решений хранится **в карточке проекта D** (зачёркивание при удалении/изменении), не в срезе. | Q-B3 (30.06), PD-052 | `in_tz` | TZ_G (§5), TZ_D |
| **PD-054** | **Удаление vs выполнение:** `_DELETE` физически убирает строку из среза (задача была ошибочно распознана); «задача выполнена» = штатный чекбокс `- [x]` (остаётся в срезе). Два разных глагола PM → два разных действия reconciler. | Q-B2 (30.06), PD-052 | `in_tz` | TZ_G (§5), TZ_F |
| **PD-053** | **Где создаётся задача из PM Notes (`_ADD`):** новая задача пишется **в тот же срез**, в секцию `## ✅ Задачи (добавлено PM)` (Tasks-формат). Срезы остаются единственным физическим источником задач, Tasks-query подхватывает штатно. | Q-B1 (30.06), PD-052 | `in_tz` | TZ_G (§5), TZ_F |

## 2026-06-30 — Бриф PM Notes (поштучный, Cursor/Opus)

> Финализация модели синка PM Notes. Источник: [[pm/sessions/2026-06-30_pm-notes-decisions]]. Уточняет/раскрывает PD-046.

| ID | Решение | Контекст | Статус | TZ ref |
|----|---------|----------|--------|--------|
| **PD-052** | **Полномочия PM Notes (CRUD):** PM Notes управляет тремя типами объектов карточки — задачи, решения, риски — с полным набором операций: создать (в т.ч. не найденную роботом в summary), изменить (для задачи: текст/owner/срок; для решения и риска: суть), удалить/отменить (зачёркивание). Тип «комментарий» — свободный текст без структурного эффекта (только контекст для следующего среза). Непонятное Haiku не применяет молча → пишет в дайджест PM | Q5 (30.06), PD-027 | `in_tz` | TZ_F (PM-блоки), TZ_D |
| **PD-051** | **Детект изменений PM Notes + гранулярность:** хэш считается по каждому блоку `<!-- pm: -->…<!-- /pm -->` отдельно, ключ `(snapshot_path, block_index)`, хранится в `state.json.pm_notes_hashes`. Изменился хэш блока → обрабатывается только соответствующий раздел карточки; правка соседних секций среза агента не триггерит. Один блок → один раздел → одна транзакция | Q3, Q6 (30.06) | `in_tz` | TZ_F, TZ_D, главное ТЗ §8 |
| **PD-050** | **Архитектура реконсиляции — отдельный модуль:** `pm_notes_reconciler` вызывается F-оркестратором первым шагом каждого прогона (перед обработкой новых встреч) + поддерживает ручной запуск `--only-pm-notes <slug \| snapshot>` без ограничения окна. Окно скана = 5 календарных дней (параметр конфига). Если хэш PM Notes не менялся — no-op (без LLM, без записи), за 5 дней работа агента может быть нулевой | Q2, Q4 (30.06), PD-046 | `in_tz` | TZ_F, TZ_aggregate_main (§2) |
| **PD-049** | **Старшинство PM Notes vs свежая встреча — хронология:** обработка от старого к новому; более свежий срез (новая встреча) перекрывает более раннюю PM Note по стандартным правилам резолва конфликтов (D). Если контекст новой встречи неверен — PM переопределяет его в PM Notes нового среза. Конфликт-пометки не вводим | Q1 (30.06), PD-046, OQ-004 | `in_tz` | TZ_D, TZ_F |
