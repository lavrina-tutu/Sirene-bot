# Запуск тестов USERTOOLS: используй tool-local .venv

При прогоне тестов любого инструмента из `~/USERTOOLS/<Tool>/` **сначала сделай `cd ~/USERTOOLS/<Tool>/` и запускай через его собственный `.venv`**, если он есть:

```bash
cd ~/USERTOOLS/<Tool> && ls -d .venv 2>/dev/null
./.venv/bin/python -m pytest tests/<file> -q
```

Global `python3` на ВМ **не имеет** зависимостей инструментов (например, `loguru` для AnywhereContacts) — прогон глобальным интерпретатором падает с `ModuleNotFoundError`, хотя код и сами тесты корректны. Это НЕ признак сломанного кода.

Порядок диагностики при падении тестов:
1. Есть ли `~/.hermes/_Archives`-бэкап и tool-local `.venv` → запускать через `.venv/bin/python`.
2. Только если `.venv` нет — ставить недостающие зависимости в него (`./.venv/bin/pip install <missing>`), не в глобальный python.
3. После зелёного прогона — подтверждать `grep`'ом, что файлы реально изменены (не верить self-report исполнителя).

Это retry-pattern, а не «тесты сломаны»: код один и тот же, разница только в интерпретаторе.
