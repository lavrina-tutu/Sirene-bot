# Пересчёт чисел в скобках карточек отделов — когда НЕ автоматизировать

## Ситуация
Пользователь просит: «напиши в скобках карточек Отделов количество персонала — там где есть скобки — проверь и поправь количество подчинённых (уникальных)».

## Главный вывод (verified 15.09.2026, оргструктура АИД)
Пересчёт вложенных отделов по **коннекторному дереву ЧАСТИЧНО работает** — не стоит сразу сдаваться:

- **Работает для большинства отделов**: обход от карточки-отдела вниз по `line data-start→data-end` через роли/пустые узлы до sticky-людей с дедупликацией имён даёт надёжное число. В сессии так посчитаны: Группа BI-аналитики (1)=**2** (Набиева+Царьков), Отдел клиентской аналитики (6+3 вакансии)=**6**, Отдел маркетинговой и HR (предпол.7)=**9**.
- **НЕ работает / загрязняется** на отделах с **перекрёстными коннекторами**: напр. Отдел машинного обучения «насобирал» 30+ человек = почти весь департамент. Когда число отдела абсурдно велико (сравнимо с суммой других / превышает департамент по частям) — верить нельзя, идти на сверку.
- Ещё причины неполноты: часть людей привязана только визуально (sticky рядом с ролью, без line), у части ролей (DS ЖД, MLOps) нет персоны.

**Абсолютно надёжно вычисляется только общий уникальный состав всего фрейма** (сумма sticky-людей минус дубли имён). Пример: «Департамент аналитики и данных (80)» → 75 уникальных.

## Как действовать
1. Общий заголовок (департамент/фрейм целиком) — пересчитать по уникальным через дедупл-скрипт и поправить смело.
2. Вложенные отделы со скобками:
   - **Сначала попробовать коннекторное дерево** (скрипт `analyze2.py` из сессии): от отдела вниз по `data-start→data-end` через все узлы (включая **пустые роли без `data-content` — они транзитные, не должны обрывать обход**; терминальный — только `data-type="sticky"`), собрать sticky-имена, дедуп.
   - **Проверка правдоподобия**: если результат абсурден (≈ сумма департамента / заметно больше соседних отделов) — отдел имеет перекрёстные коннекторы, числу НЕ верить.
   - Поправлять смело можно однозначные (малые, с ясным составом, напр. BI-аналитики 1→2). Спорные (маркетинг, ML) — показать список Саше и ждать подтверждения ДО записи числа.
3. Если пользователь не даёт состав — честно: «автоматически надёжно пересчитано только…; по этим отделам идём по одному с твоей сверкой».

## Разница с дедупликацией имён
Унификация дублей-имён («Цветкова Лена»→«Цветкова Елена») — отдельная выполнимая правка: поиск по имени → widget_ids → стаб `data-content`. Пересчёт количества подчинённых в отделе — принципиально другая, НЕ выполнимая автоматически задача. Не путать.
