# travel-writing

## Триггеры
- «напиши отчёт о путешествии»
- «оформи рассказ о поездке»
- «есть транскрипты из фф / Fireflies»
- «нужен красивый текст на память»

## Workflow

### Шаг 0 — Уточнить формат (бриф, по одному вопросу)
1. **Назначение:** личный дневник / пост / статья / на память
2. **Стиль:** эмоциональный, поэтический, информативный, литературный (Гоголь, Пришвин и т.п.)
3. **Объём:** один абзац на день / развёрнуто / каждая деталь
4. **Дополнительные источники:** транскрипты, голосовые, фото-подписи

### Шаг 1 — Получить план-хронологию
Автор присылает план (список дней и событий). Этот план — **эталон хронологии и смысла**. Не менять порядок, не переставлять события без явного ОК автора.

### Шаг 2 — Забрать транскрипты из Fireflies
Транскрипты живут в Fireflies («фф»). Забирать через GraphQL API:
```python
# API ключ: FIREFLIES_API_KEY в ~/.config/hermes/.env
# Список транскриптов:
query = '{ transcripts(limit: 10) { id title date duration } }'
# Полный транскрипт:
query = '{ transcript(id: "ID") { sentences { text speaker_name start_time } } }'
endpoint = 'https://api.fireflies.ai/graphql'
header = 'Authorization: Bearer KEY'
```
MoveFromFF тоже работает: `cd ~/USERTOOLS/MoveFromFF && .venv/bin/python3 -m movefromff --mode manual --from-date YYYY-MM-DD --to-date YYYY-MM-DD`

### Шаг 3 — Фильтрация транскриптов
Разделить на **три корзины** и показать автору:
- ✅ **В текст** — путешественное, красивое, эмоциональное, характерные детали
- 📎 **«От автора»** — байки, отступления, истории не строго о маршруте, но сказанные в вечер похода. Лирические вставки в духе автора стиля.
- ❌ **Выкинуть** — сиюминутное (деньги, бытовые покупки, технические обсуждения снаряжения без поэзии)

**Важно:** не спешить выкидывать «бытовое» — спрашивать. Пример: обсуждение стёртых кроссовок и мозолей = **сквозной мотив «цена пути»** (проверка людей и снаряжения). Казалось бы — мусор, оказалось — поэзия.

### Шаг 4 — Поштучный бриф по деталям
**Критично:** разбирать **по одной детали за раз**.
- Называть предлагаемую деталь с формулировкой «предлагаю оставить/выкинуть»
- Указывать день и пункт из плана
- Ждать подтверждения («да» / «нет» / поправка) — **не переходить к следующей без ответа**
- Если автор возвращается к предыдущему пункту — дорабатывать его немедленно, потом продолжать

**Предположения по хронологии** формулировать явно: «Это про день 3, п.5?» — не утверждать, спрашивать.

**Сквозные мотивы** — фиксировать отдельно. Если деталь повторяется в разных днях — это мотив, а не единичная вставка. Примеры из практики:
- «Цена пути» — кроссовки, мозоли, горло, ячмень → упоминать по ходу дней
- «Доброжелательность местных» — не один раз в конце, а при каждой встрече с местными по ходу рассказа

### Шаг 5 — Раздел «от автора»
Предложить лирические отступы — зарисовки и истории, сказанные вечером похода, не всегда прямо связанные с маршрутом. Размещать как врезки или эпилог.

Кандидаты в «от автора» (из практики):
- История с чужим участником похода как **назидание** (держать путь, не поддаваться эмоциям) — особенно если есть живой пример из этого похода
- Исторические справки о местах (читали с телефона в лагере)
- Страх дождя как сквозное ощущение
- Километраж с иронией

### Шаг 6 — Интеграция
**Только после явного «всё верно, начинай»** от автора.
- Следовать плану как скелету
- Детали из транскриптов вписывать в соответствующие дни
- Стиль — согласованный на шаге 0
- Каждая деталь из плана должна присутствовать в тексте

## Итерационная правка через Opus cron

После написания текста правки передавать напрямую в `cronjob` с моделью `claude-opus-4-7` (не claude-opus-4-5). Каждая итерация — отдельный крон. Формат правки:
```
## ПРАВКА N — Раздел/день
УБРАТЬ: ...
ДОБАВИТЬ/ИЗМЕНИТЬ: ...
```

Важно: правки типа «убрать отсюда + вписать туда» не теряются — Opus видит оба указания вместе. После каждой итерации проверять что перенесённые блоки на месте.

## Паттерны итеративной правки (из практики — обновлено 14.06.2026, расширено)

- **Правки собирать поштучно** — каждая правка нумеруется, содержит УБРАТЬ+ДОБАВИТЬ явно
- **Перемещение блоков между главами** — писать в одной правке: «УБРАТЬ из Дня X + ВПИСАТЬ в День Y с таким-то контекстом». Opus видит оба указания вместе — блоки не теряются.
- **Итерации**: 3-4 Opus-крона за сессию — норма для большого текста. Каждый крон = одна пачка правок. Не смешивать правки разных глав в одном кроне если они конфликтуют.
- **Opus-крон напрямую редактирует файл** — не писать в /tmp и не читать обратно. Opus получает задание, правит ~/WorkVault/Personal/kavkaz-tropa-rasskaz.md, сохраняет. После — читаем файл и выводим чистовик главы.
- **Перестановка абзацев** — описывать ТЕКУЩИЙ порядок и НУЖНЫЙ порядок нумерованным списком. Opus точнее исполняет чем «перенести X перед Y».
- **Проверка после кроna**: читать только изменённую главу, не весь текст. Экономит время.
- **МЧС/сервисные упоминания** — не собирать в один абзац. Раскидывать по хронологическим главам короткими фразами («вечером включили телефоны — МЧС дозвонились»).
- **Обратный путь такси** — рассказ водителя о семье и сёлах = отдельная сцена в главе «обратная дорога», не в главе «заброска».
- **Ресторан с именем** — всегда называть по имени («Папаха», «Мучари»). Создаёт атмосферу.
- **Вставки про природу/зверьё/философию** — не в предисловие, а в хронологически уместные места: природа и труд людей — в середине, зверьё — у финала.

## Питфоллы из сессии 14.06.2026 (часть 2)

- **Исторические справки о городах** — проверять через delegate_task с toolsets=['web']. Пример: Каспийск — советский военно-промышленный город 1932 г., основан при заводе «Дагдизель», база Каспийской флотилии. Не выдумывать — делегировать.
- **Сквозные счётчики по тексту** (число дождей, дней, км) — при правке одного места проверять все остальные упоминания того же числа. Пример: поправили «3 дождя» → «4 дождя» в послесловии, но могут быть дубли в других главах.
- **Точечные правки (1–2 слова)** — делать напрямую через `patch`, не через Opus-крон. Крон — для структурных и стилистических правок от 3+ абзацев.
- **Абрикосовый сад без абрикосов** — не писать «Абрикосы! Этот край ими богат» если их нет. Реальность важнее ожидания: «деревья есть, абрикосов нет — дождливый год».
- **Запахи природы** — вплетать фоново, одной фразой, в существующие описания. Не отдельным абзацем. Не «благоухание разлилось» — а «пахло чем-то тёплым, акацией, что ли». Распределять по тексту: акация на подъёме (день 2), шиповник на крутых взлётах (день 3), горная мята в долинах (день 5), коровяк на спуске (день 6).
- **Финальная сцена возвращения** — не заканчивать на аэропорту. Московская суета, маршрутка, задние двери = живая точка, контраст с горной тишиной. Включать.
- **Отдельные фразы пользователя «поправь только это»** — если правка одна и мелкая, делать через patch напрямую, без крона. Подтвердить изменённой строкой сразу.
- **«Через задние двери»** и подобные мелкие бытовые детали финала — не выбрасывать. Это живая текстура возвращения в обычную жизнь, ценная именно своей прозаичностью.
- **Местный колорит еды** — описывать конкретно: что подали, что впервые попробовали, какая была реакция. «Интересный и вкусный завтрак» — слабо. «Абрикосовая каша, чуду с малиновым вареньем, яичница» — сильно.
- **Мулла/религиозная сцена** — подавать через детали: замечание про плечи, парирование Юли, вопрос про семейный статус. Не пересказывать как лекцию, а показывать диалог. Уважение к культуре + внутренняя позиция автора — без спора, но с мыслью.
- **Хронология внутри дня** — соблюдать строго: утро → рынок → кухня → кафе → набережная → магазин → снова кухня → такси. Если автор указывает последовательность явно — это эталон, не переставлять.

## Питфоллы из сессии 14.06.2026

- **«Поход берёт своё» и подобные авторские обобщения** — не вписывать в середину глав. Такие итоговые наблюдения — в послесловие или в итоги, не в хронологию дня.
- **«Самый сложный/тяжёлый за весь поход»** — не писать раньше финала: герои этого ещё не знали в тот момент. Только «самый крутой из того, что знали до той минуты» или подобное.
- **Детальное описание участников группы** — в предисловии только краткое представление (кто такие). Развёрнутые портреты — в послесловии, как срез памяти «каким запомнился каждый».
- **Описание дороги/инфраструктуры** — не ограничиваться «шли по дороге». Детали имперского масштаба (водоотводы, мосты, обвалившееся полотно) создают атмосферу и глубину.
- **Порядок сцен внутри вечера**: сначала ресторан (атмосфера, еда), потом добыча вина (история с багажником), потом совместное питие. Логика: сначала место, потом добыча, потом застолье.
- **Отсылки на будущие главы («расскажу позже»)** — убирать если история уже есть в другой главе. Читателю достаточно самой истории там, где она стоит.
- **Сервисные звонки (МЧС и подобные)** — только вечером, не утром и не днём. Утренние упоминания убирать по всему тексту.
- **Местные жители и их маршруты** — не «обогнали нас и это унизительно», а смешно и восхищённо: горы им дом родной. Тон — добродушный, не самоуничижительный.
- **Болячки участников** — в перечне потерь не называть у кого именно что болело. Общий список без имён: «горло, ячмень, колени, мозоли...»
- **Размышления на подъёме** — подъём = хорошее время для мыслей. Дом, дети, работа, друзья впереди, те кто остался дома, те кого нет. Без пафоса — «не грустно, просто так».
- **Террасы на склонах** — не просто пейзаж, а история труда: столетиями пахали, сейчас техника не доберётся → луга. Вписывать при описании долин и горных пейзажей.
- **«Как живые»** в описании воспоминаний — убирать: это клише. «Закрою глаза — и вот они» достаточно.

## Питфоллы из сессии 13.06.2026

- **Структурные блоки перемещать через cron-правки**, не вручную — меньше риск потери
- **Предисловие не перегружать** — абзацы про природу/зверьё/дожди лучше расставить хронологически по главам, а не скучивать в начале
- **«От автора» — не один блок в конце**, а лирические вставки между главами в нужных местах
- **Субъективные оценки от лица автора** — строго под запретом без явного запроса («мы прошли правильнее» и т.п.)
- **Бытовые детали ≠ мусор**: кроссовки = цена пути; трусы сушить этажом выше = характер этнодома. Предлагать, не выкидывать сразу.
- **Умершее животное рядом с живым** — не убирать: Саша ценит контраст (дохлая корова + конь рядом = «смерть соседствует с жизнью, как Чох»)
- **Исторические факты проверять делегатом** — delegate_task с toolsets=[«web»], сверять победы/поражения, имена, годы. Пример: Ахульго = поражение Шамиля (не победа).

## Питфоллы

- **Не начинать писать без финального ОК** — бриф сначала, текст потом.
- **Не менять хронологию плана** — план проверен всеми участниками, он эталон.
- **Не выдумывать детали** — только то, что есть в плане и транскриптах.
- **Fireflies требует авторизацию** — web_extract не работает на app.fireflies.ai. Только GraphQL API.
- **Исторические/культурные факты** — проверять через web_search. Пример: «Уастырджи» (не «Вастерджи») — осетинский покровитель путников и воинов. Проверять написание имён, топонимов, культурных отсылок.
- **Культурный контекст ≠ запрет на поэзию.** Уастырджи — осетинский святой, а поход был в Дагестане. Это несоответствие — художественная вольность автора. Не исправлять без запроса, предложить варианты и дать выбор.
- **Не спешить с «выкинуть»** — предлагать, ждать ответа. Бытовые детали часто несут смысл (кроссовки = цена пути, трусы на верёвке = спартанство этнодома).
- **Субъективные оценки от лица автора** — не добавлять без явного запроса. Автор сам решает что хорошо, а что нет.
- **Транскрипт = вечерний разговор о прошедших днях** — хронология там перепутана. Привязка к дням только через бриф с автором.

## Стили (примеры)
- **Гоголь:** живые зарисовки, лирические отступы, ирония, точные детали быта, природа как персонаж, неожиданные сравнения (протосс-пилон из StarCraft = жанровая деталь эпохи)
- **Пришвин:** природа на первом плане, философские наблюдения, тихая радость
- **Дневниковый:** хронология + эмоции, разговорный язык

### Гоголь — конкретные приёмы (из практики)
- Восклицания без надрыва: «Коровы! Куда без них.»
- Ирония через деловитость: «барашки шли рядом, деловито, будто тоже сверяли трек»
- Бытовая деталь как образ: «нужник с видом на проходной двор (любители панорамных видов оценят)»
- Характер через действие: «Андрей покачал головой с таким видом, будто лично построил этот подъём»
- Запахи — фоном, одной фразой: «пахло чем-то тёплым, акацией, что ли»
- Собаки «с видом людей при исполнении» — олицетворение без штампов
- Сделка с честью: «Сделка состоялась, честь сохранена у всех сторон»

## Конвертация готового текста
- **PDF:** pandoc md → html, затем weasyprint html → pdf (xelatex часто отсутствует на AlmaLinux)
  ```bash
  pandoc file.md -o /tmp/file.html --metadata title="..." --metadata author="..." --standalone
  weasyprint /tmp/file.html file.pdf
  ```
- **FB2 + ZIP:** pandoc md → fb2, затем zip
  ```bash
  pandoc file.md -o file.fb2 --metadata title="..." --metadata author="..."
  zip file.fb2.zip file.fb2
  ```
- **Фактическая версия:** отдельный файл `_shortstory.md` — та же структура глав, без стиля, только факты, объём в 3-4 раза меньше. Создаётся через Opus-крон с явной инструкцией «убрать стиль, оставить хронологию и факты».
- **Установка зависимостей (AlmaLinux/RHEL):** `sudo dnf install -y pandoc zip` + `pip install weasyprint`
