# JQL-паттерны и выборки OKR

## Фильтр АИД (обязательный по умолчанию)

Любая выборка KR/Objective: `cf[43743] = "АИД"` — в OKRS и OKRAID. Снять фильтр только по явной просьбе («все подразделения», «Отели» и т.д.).

## Годовые цели департамента

```
project = OKRS AND issuetype = 6 AND cf[43743] = "АИД"
  AND cf[43701] = "Functional Annual OKR" AND fixVersion = "2026 ф.г."
```

## Квартальные цели

```
project = OKRS AND issuetype = 6 AND cf[43743] = "АИД"
  AND cf[43701] = "Functional Quarterly OKR"
  AND fixVersion in ("Q1 2026","Q2 2026","Q3 2026","Q4 2026")
```

## KR — не через JQL напрямую

KR выбираются через `issuelinks` каждой Objective (`type.name == "Contains"`, `outwardIssue` = KR/дочерняя квартальная). Для чекин-полей — только OKRTool.

Обход issuelinks при первичной выгрузке:
- `outwardIssue` — дочерний KR
- `inwardIssue` — родитель (обратное направление)
- Проверять обе стороны связи

Дочерние ключи разом: `customfield_44601` (CSV) или обход issuelinks для многоуровневой иерархии.

## «Мои OKR на месяц» / незакрытые за период

Базовый JQL:
```
project in (OKRS, OKRAID) AND fixVersion = "<период>" AND cf[43743] = "АИД"
```

**Питфол status:** `AND status != "Закрыта"` в мульти-проектном JQL может дать `400` — убрать из JQL, фильтровать `fields.status.name != "Закрыта"` в Python.

Полезные поля для статус-выборки: `summary, status, issuetype, assignee` (чекин-customfield не нужен).

Альтернатива: `statusCategory != Done` — проверять на живом JQL; при `400` — пост-фильтр в Python.

## Смена исполнителя

Поиск логина: `GET /user/search?username=…` с URL-кодированием кириллицы (`--data-urlencode` / `urllib.parse.quote`), не raw-байты в URL.

`PUT /issue/{key}` → `{"fields": {"assignee": {"name": "<логин>"}}}` — только явно перечисленные ключи, без каскада на Contains-детей.

Верификация — один batch `jql=key in (KEY1,KEY2,…)`.

## Dependency (внешние зависимости)

Отдельный issuetype; связь с KR — Contains, **inwardIssue** со стороны KR. Если `issuelinks` пуст — «нет связи Contains», не додумывать.

Таблица Dependency: при неоднозначных колонках — переспросить список колонок одним предложением.

## Сверка данных (формат)

Сопоставление 5 чекин-полей между уровнями (Objective↔KR, годовая↔квартальные):
1. Текст + % + метрика верхнего уровня
2. Совокупность нижнего уровня построчно
3. Средний % нижнего vs % верхнего
4. Комментарий: `ОК` / `⚠️ <суть расхождения>`

Расхождения **фиксировать**, не исправлять без решения Саши. Для актуализации годовой по Q1+Q2 — объединённый текст (Q1 + Q2), не с нуля.
