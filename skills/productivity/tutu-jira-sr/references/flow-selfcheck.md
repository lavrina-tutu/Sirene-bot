## Канон брифа итогов (по сессии 09.2026)

**Блок 4 — поштучно, с показом плана.** Для каждого пункта сначала показать «План (что обещали)» = текст из Блока 1, затем «Результат (вариант)»; утверждать формулировку у пользователя по одному пункту. Факты для варианта результата брать по приоритету: **1) OKR-чекин** (доверять как первоисточник), **2) свои закрытые задачи за период** (JQL `assignee = currentUser() AND resolved …`), **3) протоколы соответствующих проектов** (Entities/<slug>/protocol.md, свежие записи периода). Если в указанных источниках факта нет — честно пометить «требует факта» и спросить, не выдумывать.

**Блок 5 — по одному пункту.** Вопрос «Каких знаний/навыков не хватило или сложность, и как решили?». Ответ **«сложностей нет / пропускаем» → пункт пропустить, НЕ вносить** в Block 5 (не писать «Проблем не было»). Решение есть → `Решение: …`; нет → строку решения не выводить.

**Блок 6 — по одному пункту**, пропуски допустимы («пропускаем»).

**Ключевые номера задач всегда кликабельными ссылками** (`[OKRS-3119](https://hq.tutu.ru/browse/OKRS-3119)`), не текстом.

## Бриф Блока 5 (44405)

После согласования Блока 4 — **отдельный проход по всем N целям**, включая выполненные.

Вопрос (один пункт = одно сообщение):
«П.N. <заголовок>. Каких знаний или навыков не хватило или какая была сложность, и как её решили?»

Правила:
- **Не фильтровать** по статусу выполнения.
- Проблема ≠ «не выполнено»; нужна конкретная причина (кто/что/почему).
- «нет» / «проблем не было» → `Проблем не было`.
- Решение есть → `Решение: …`; нет — строку не выводить.
- После последней цели — вопрос на совокупный «Итог: …» для 44405.
- Не слать промежуточные отчёты между пунктами; не перепечатывать Блок 4.

## Финализация: draft → check

1. **`_draft.md`** — Блок 4/5/6:
   - Блок 4: единый нумерованный список пунктов. Каждый: `N. <Заголовок> (<KEY> <URL>) — ✅ **Выполнено** / ❌ **Не выполнено** (<статус>). <текст результата>`. Доп. результат по конкретному плановому пункту — строка сразу после него: `Доп.результат: <текст>` (не отдельный раздел). Новый результат вне плана (доп. цель) — продолжает нумерацию последним пунктом: `N+1. Дополнительный результат — <название>: <описание>`. Не выносить доп. результаты в отдельный список-раздел.
   - Блок 5: N пунктов; `Проблема:`/`Решение:` или `Проблем не было`; абзац `Итог:`; не «Сложность:».
   - Блок 6: уроки по N пунктам; `-` если пусто.
2. **`_check.md`** — самопроверка draft перед заливкой (всё в MD).
3. Заливка — отдельный шаг по явной команде, текст из `_draft.md` → `references/flow-fill-push.md` (transition **271**).
4. После успешного POST: **`sync_md_header`** / `--sync-md` — шапка того же MD (статус Jira, дата, transition); содержимое блоков не подтягивать из Jira.
5. `systemctl --user start owncloud-sync.service` (скилл `workvault-sync`; не ручной `rclone sync`).
