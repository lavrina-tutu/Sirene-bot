# Confluence — восстановление страницы из истории версий

Класс задач: страница Confluence Server/DC перезаписана (пропали протоколы, строки таблицы,
контент). Найти точку потери в истории версий и восстановить из полной версии — **не трогая
уцелевшие строки**.

Проверено live (26.08.2026): «Кирилл 1-1» (pageId 508804979) потерял 29 из 31 протокола —
v198 (12:25) полная, v199 (13:42) остались 2 + 30 пустых `<tr><td><br /></td>`. Восстановлено
через PUT тела v198.

## Принцип безопасности для уцелевшего — СНАЧАЛА спроси, кто правил страницу

**Критично (исправлено 26.08.2026 после ревью Саши): НЕ возвращай полный снапшот целиком, если
владелец правил страницу руками.** Исходная версия этого скилла рекомендовала «просто вернуть
полный v198 целиком» — это была ОШИБКА: страница уже была доработана Сашей вручную (правленые
строки 25.08/26.08), и восстановление полного снапшота из данных PFS затерло его правки.
Саша поправил явно: «вернуть записи из истории страницы, не используя наши протоколы», «склеить
страницу — мои новые данные + случайно затёртые».

**Правило:** при восстановлении страницы, которую владелец правит руками:
1. СНАЧАЛА сравни битую версию (ту, что осталась после потери) с полной-источником по якорям
   `pfsrow-X`. Если какие-то строки в БИТОЙ версии НЕ пусты И отличаются от полной — это
   ручные правки владельца, их НАДО сохранить.
2. Склей: возьми полное тело из истории, НО для якорей, которые в битой версии непусты и
   изменены, подставь их версии ИЗ БИТОЙ страницы (владельца). Т.е. верни потерянные строки
   из полной, но НЕ перезапиши правленные владельцем.
3. Спроси Сашу (2 варианта), если не очевидно: полный откат к битой версии vs полное vs склейка.
   По умолчанию для hand-editeд страниц — склейка.

**Ключевой вопрос «кто виноват» НЕ по `by`:** поле `by` у v199 показывает «Ткаченко», но это и
человек, и все PAT-токены. Реальный признак ручного стирания — сигнатура пустых `<td><br/></td>`
+ полное отсутствие следов инструмента в логах (крон `published=0`, реестр не менялся,
agent.log чист, ни один write-путь инструмента не запускался в окно потери).

Алгоритм склейки (полное тело + правки владельца по якорям) — `references/merge-owner-edits-and-lost-rows.md`.

## Шаг 1 — Локализовать точку потери (только чтение)

API исторических версий в этой инсталляции:
- ✅ `GET /rest/api/content/{id}?status=historical&version={N}&expand=body.storage`
  → полный storage-корпус версии N (HTTP 200, `body.storage.value`).
- ❌ `GET /rest/api/content/{id}/version/{N}` → HTTP 405 (не JSON).
- ⚠️ `GET /rest/api/content/{id}/history?expand=previousVersion` → только ОДНА previousVersion
  за вызов; для спуска по версиям использовать `?status=historical&version=N`.
- ❌ `GET /rest/api/audit` → HTTP 403 «must be authenticated as an administrator» (PAT не админ).

Сравнение по версиям (спуск от текущей вниз), считаем pfsrow-якоря / `<tr>`:
```python
def get_ver(v):
    r = curl(GET, f"?status=historical&version={v}&expand=body.storage")
    b = r['body']['storage']['value']
    return len(re.findall(r'pfsrow-', b)), len(re.findall(r'<tr>', b))
```
Резкий обвал между соседними версиями (v198=31 → v199=2) = точка потери; версия ДО обвала —
чистый источник восстановления.

## Шаг 2 — Восстановить (PUT из полной версии)

```python
src   = get_hist(N)                       # полная версия-источник
body  = src['body']['storage']['value']
cur   = GET /rest/api/content/{id}?expand=version        # ЖИВОЙ version.number
payload = {
  "id": str(id), "type": "page",
  "title": src['title'],
  "version": {"number": cur['version']['number'] + 1},
  "body": {"storage": {"value": body, "representation": "storage"}},
}
PUT /rest/api/content/{id}   # Authorization: Bearer $CONFLUENCE_TOKEN (Confluence, не JIRA)
```
- Версию брать из ЖИВОГО ответа (`cur.number+1`), не из исторической.
- Поле `space` для PUT не нужно (см. `tutu-confluence-jira`).
- Перед write: `dry`-проверка payload (посчитать pfsrow) и бэкап снапшотов обеих версий.

## Шаг 3 — Верификация (обязательно)
GET живой страницы после PUT: version подрос, `count(pfsrow)` == ожидаемому, **0** пустых
`<br /></td><td><br /></td>`. НЕ доверять коду ответа / `action=="published"` — проверять
реальный HTML.

## Питфоллы
1. **Автор версии — не доказательство виновника.** Поле `by` покажет «Ткаченко Александр
   Владимирович», но под этим аккаунтом пишут ВСЕ PAT-токены (ConfluenceSync, PFS, TaskRefresh)
   и человек. Не делать вывод о виновнике по `by`.
2. **Пустые `<tr><td><br /></td><td><br /></td>`** = маркер ручного/другого удаления строк в
   веб-редакторе, а НЕ результат API-замены одной строки (API-замена сохраняет остальные).
   Это подсказка «переписано тело таблицы целиком», а не «republish одной встречи».
3. **Крон PFS штатно `published=0,error=0`** — не доказывает непричастность, но и не
   винит: проверь вывод крона `~/.hermes/cron/output/<job_id>/` за конкретное окно времени.
4. Хранить снапшоты v(полная) и v(битая) до восстановления в `~/WorkVault/Hermes-Backlog/_Archives/`.
