# Структура хранения результатов PROXY (Confluence, space DPAN)

Схема хранения, введённая 25.08.2026. Хранилище **Confluence-центричное** (не Google Sheets).

## Иерархия страниц

```
Сводная страница 511554221  «Парсинг-К. Таблица PROXY ответившие поставщики»
├── (в теле, СВЕРХУ) итоговая таблица «Итог по поставщикам»
│     колонки: Сервис | Статус | Описание
├── (в теле, НИЖЕ) старая матрица «Вопросы × Поставщики» (16 строк × сервисы)
├── дочерняя «Парсинг. 1. webshare»          (подстраница поставщика)
│     └── дочерняя «Парсинг. webshare тестирование»   (подстраница тестирования)
├── дочерняя «Парсинг. 2. InfraProxy.ru»
│     └── «Парсинг. InfraProxy тестирование»
├── ... и т.д. для каждого поставщика
└── дочерняя «Парсинг. N. <service>»
```

- **Подстраница поставщика** `Парсинг. N. <service>`: таблица **Вопрос | Желаемый ответ | Ответ** + `<h2>Вывод</h2>` + макрос (✅ tip / ⚠️ note / ❌ warning / ❓ info).
- **Подстраница тестирования** `Парсинг. <service> тестирование`: предложения/переписка по тестированию (child от подстраницы поставщика). НЕ имеет числового префикса.

## Итоговая таблица «Итог по поставщикам» (верх сводной)

Колонки:

| Сервис | Статус | Описание |
|---|---|---|
| `<a href="САЙТ">имя</a>` + `<br/><small>(<a href="подстраница-поставщика">подробнее</a>)</small>` | пусто, либо `<a href="подстраница-тестирования">предложены варианты тестирования</a>` | «✅/⚠️/❌/❓ РЕЗОЛЮЦИЯ. почему.» |

- **Сервис** — ссылка на сайт поставщика + ссылка «подробнее» → подстраница поставщика.
- **Статус** — пусто (нет тестирования), либо «предложены варианты тестирования» → подстраница тестирования.
- **Описание** — вердикт (✅/⚠️/❌/❓) + краткое «почему».

## Матрица «Вопросы × Поставщики» (низ сводной)

- Строки = 16 вопросов (1–13 тех., 14–16 коммерч.) + заголовок + «Выводы».
- Колонки = сервисы, отсортированы **от лучших к худшим** (слева направо).
- Желаемые ответы (колонка «Желаемый ответ») — эталон для оценки.

## Механика правок (Python + Confluence REST API)

Константы:
- BASE = `https://dom.tutu.ru/rest/api/content`
- Сводная pageId = `511554221`, space = `DPAN`
- Токен: `grep -E '^CONFLUENCE_TOKEN=' ~/USERTOOLS/ConfluenceSync/.env | cut -d= -f2-`

### GET body + version
```python
req = urllib.request.Request(BASE+"/<id>?expand=body.storage,version,title",
     headers={"Authorization":f"Bearer {TOK}"})
d = json.load(urllib.request.urlopen(req))
body, ver, title = d["body"]["storage"]["value"], d["version"]["number"], d["title"]
```

### PUT (обновить body; тело ОБЯЗАТЕЛЬНО в payload, иначе затрётся)
```python
payload={"id":"<id>","type":"page","title":title,
  "version":{"number":ver+1},
  "body":{"storage":{"value":NEW_BODY,"representation":"storage"}}}
req=urllib.request.Request(BASE+"/<id>", data=json.dumps(payload,ensure_ascii=False).encode(),
  headers={"Authorization":f"Bearer {TOK}","Content-Type":"application/json"}, method="PUT")
```

### POST (создать подстраницу)
```python
payload={"type":"page","title":"Парсинг. N. name",
  "ancestors":[{"id":PARENT_ID}],"space":{"key":"DPAN"},
  "body":{"storage":{"value":BODY,"representation":"storage"}}}
```

### Список дочерних страниц
```
GET BASE/<parentId>/child/page?limit=50  → results[].{id, title}
```

### Вставка колонки в матрицу (после нужной позиции)
Строка = `<tr>...<td/></tr>`. Разбить на ячейки, вставить новый `<td>`/`<th>` на нужный индекс в КАЖДОЙ строке (заголовок, вопросы, выводы, оплата, разделители), пересобрать, PUT. В `<colgroup>` добавить `<col class="" />`.

- Заголовок: `<th scope="col"><a class="in-cell-link" href="SITE">name</a></th>`
- Вопросные строки: `<td>ответ</td>`
- «Выводы»: `<td>вердикт</td>`
- «Оплата» и разделители: `<td></td>`

### Перенумерация подстраниц
**Переименовывать в порядке УБЫВАНИЯ** новых номеров (с последнего к первому), чтобы не было конфликтов имён. Если сдвиг тесный (напр. блок 6,7,8 → promo на 6) — сначала временные номера (99/98), потом цели. Для каждой: GET body+version → PUT только title, сохраняя полное body.

### Перестановка колонок матрицы
Переиндексировать ячейки в каждой строке (новый порядок из старых индексов), пересобрать, PUT.

## Питфоллы механики

- PUT теряет body, если не включить полный `body.storage.value` в payload.
- Версия для PUT = текущая + 1; при 409 перечитать `expand=version`.
- Не копировать заголовок-обёртку: у новой страницы контент может быть в v2, не v1.
- После перестановки проверять: число `<td>` в строке == числу колонок; порядок заголовков совпадает с задуманным.
- В Confluence **нет** Reorder API — порядок сайдбара задаётся только числовым префиксом названия.
