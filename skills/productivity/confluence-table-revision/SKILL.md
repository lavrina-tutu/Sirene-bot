# Пересборка существующей таблицы Confluence через REST

Редактирование/переформатирование УЖЕ созданной таблицы на странице Confluence. Дополняет `find-proxy-task` (там — создание страниц с нуля) и `tutu-confluence-jira` (основные REST-паттерны). Здесь — именно правка существующего контента: версии, парсинг HTML, пересборка.

## Контекст

Вся правка идёт через REST `https://dom.tutu.ru/rest/api/content/<pageId>`. Токен: `source ~/USERTOOLS/ConfluenceSync/.env` → `$CONFLUENCE_TOKEN`.

## Ключевой приём 1 — PUT требует инкремент номера версии

`PUT /rest/api/content/<id>` с `{"version":{"number": <ТЕКУЩИЙ+1>}}`. **НЕ** указывай 0 — вернёт 409 `"Version must be incremented on update. Current version is: X"`.

```python
r = subprocess.run(env + f'curl -s -H "Authorization: Bearer $CONFLUENCE_TOKEN" "https://dom.tutu.ru/rest/api/content/{page_id}?expand=version"', ...)
cur = json.loads(r.stdout)['version']['number']
payload["version"] = {"number": cur + 1}
```

## Заполнение/замена таблицы контентом из внешнего источника (Loop-пост, документ) с сохранением форматирования

Когда пользователь даёт готовый контент для таблицы (напр. ссылку на Loop-пост `pl/<id>` с markdown-таблицей) и просит «замени полностью оставив форматирование»:

1. **Заголовки колонок бери из исходника, не из головы.** Если пользователь прислал корректную таблицу со своими шапками (напр. `Слой / компонент | Описание`), переноси именно их — не подставляй прежние (`Вопрос | Ответ`). «Замени полностью» = заменить строки И шапку; «оставив форматирование» = сохранить обёртку `<table class="relative-table wrapped" style="width:...">` + `<colgroup>`.
2. **Источник пользователя главнее твоей синтезированной версии.** Когда явной правкой («вот корректная информация» + новая ссылка) пользователь заменил твой черновик, перестраивай от его данных целиком, не мержи с прежним.
3. FETCH исходника через API источника (для Loop — GET `/api/v4/posts/{id}`, см. `mattermost-loop-api`), распарси markdown-таблицу, собери storage-HTML-строки.
4. **Многочастный исходник:** длинную таблицу автор часто разбивает на несколько постов одной ветки, помечая хвост `(1/4)…(4/4)`. Фетчь ВСЕ посты ветки (по `root_id` из первого ответа), конкатенируй, потом парси. Строки последнего раздела/последнего поста с хвостовым маркером регулярка «жадным» `| … |$` на своей строке ловит НЕ полностью — парсь по ключу `| **N.` в начале строки, а ответ бери до конца строки, и сопоставь счёт найденных N с ожидаемым числом вопросов.
5. PUT с версией+1, payload БЕЗ `space`. Проверка: версия `cur+1`, `tables==1`, заголовки-шапки из исходника на месте, старые заголовки отсутствуют (`'Вопрос</th>' not in body`).

**Гейт пред-просмотра (предпочтение Саши):** при контентной правке таблицы — сначала покажи готовый вид ПРЯМО В ЧАТ (текстом/структурированно), дождись `ок`/`запиши`, и только тогда делай PUT. «Не публикуй, напиши сюда в чат» = предпросмотр, не запись. Правки пользователя после его просмотра — вносить по его замечаниям, пересобирая от его актуального содержания, не поверх своей прошлой версии.

## Ключевой приём 2: парсинг storage-HTML stdlib-парсером, не bs4
Confluence отдаёт `<body.storage.value>` — однострочный HTML с таблицей. bs4 часто отсутствует во venv → стандартной библиотекой (`import re`):

```python
rows  = list(re.finditer(r'<tr\b[^>]*>.*?</tr>', html, re.S|re.I))
for rm in rows:
    cells_raw = re.findall(r'<t[hd][^>]*>(.*?)</t[hd]>', rm.group(0), re.S|re.I)
```
colgroup отдельно: `re.search(r'<colgroup.*?</colgroup>', html, re.S|re.I).group(0)`. ⚠️ RE не понимает colspan — проверь число ячеек до правки.

## Ключевой приём 3 — добавить колонку + переставить колонки
Новую колонку добавить = в каждое `<tr>` воткнуть `<td/>`/`<th/>` (перед `</tr>`), +1 `<col/>` в colgroup. Порядок колонок = переставить массив ячеек:
```python
prefix = cells[:3]; svc = cells[3:]
new = prefix + [svc[i - 3] for i in new_order]
```

## Ключевой приём 3б — батч-добавление нескольких колонок и перенос существующей (25.08.2026)
- **Несколько новых колонок** вносятся **одним PUT**: в каждый `tr` вставляется N ячеек на целевой позиции, в colgroup +N `<col>`. Экономит вызовы и версии. (Прецедент: proxy-ipv4 + proxy-solutions добавлены вместе.)
- **Перемещение существующего поставщика** (напр. promo с конца в начало): переставь массив `svc` в новом порядке и **одновременно** переставь блок «Выводы» (row после шапки) в том же порядке — иначе вердикты «въедут» на чужие колонки. И обнови `<colgroup>` под новый/смещённый порядок.
- **Правка вердикта конкретной колонки** (напр. sx ⚠️→✅ после решения Саши): в строке «Выводы» найди ячейку по индексу колонки (после реордера позиция sx = 8-я ячейка, 0-based), замени её inner целиком на `<td>Новый вердикт</td>` — макрос/стиль ячейки теряешь, но plain-вердикт реендерится норм.
- После любой перестановки проверь: порядок `<th scope="col">` заголовков == задуманному, и **в выводах (row1) вердикты идут в том же порядке колонок**.

## Ключевой приём 4 — выводы первой строкой, потом пустая, потом вопросы
Пересборка строк = перестановка списка `<tr>`-блоков:
```python
new_rows = [0, 19, 18] + list(range(1, 14)) + [14] + list(range(15, 18))
# 0=шапка, 19=Выводы, 18=пустая, 1..13=Q1-13, 14=Оплата, 15..17=Q14-16
```
Макет: row0=шапка, row1=Выводы, row2=пусто, row3..=вопросы.

## Ключевой приём 5: порядок подстраниц — числовой префикс в title
REST API **не может** переупорядочить дочерние страницы в сайдбаре (это перетаскивание в UI). Обход: **переименуй** их `N. <имя>` — сайдбар сортирует численно, лучшие сверху.
```python
rename(pid, new_title)  # PUT с текущей версией+1, меняем только title
```

## Ключевой приём 6: циклическая перенумерация подстраниц — временные имена (25.08.2026)
Когда нужно **сдвинуть блок подстраниц циклически** (например promo=8→6, proxy6=6→7, proxywing=7→8), нисходящая/восходящая перенумерация не сработает: каждой целевой позиции всегда занята другим участником цикла — возникает «замок» имён. Решение — **временные большие номера**:
1. Сначала уводишь «жертв» на большой свободный номер, освобождая целевые: `proxy6 → Парсинг. 99. proxy6`, `proxywing → Парсинг. 98. proxywing`.
2. Затем переставляешь реальные: `promo → 6`, `proxy6(теперь 99) → 7`, `proxywing(теперь 98) → 8`.
3. Порядок строго: temp-увод всех → целевые вставки → возврат из temp.
Временные номера (99/98) гарантированно нигде не существуют, конфликтов нет. Каждый шаг: GET body+version → PUT только title, сохраняя полное body, потом вывод `Парсинг. N. <name>`.

## Шаги (паттерн «добавь поставщика в таблицу»)
1. GET `?expand=body.storage` — текущий storage-HTML.
2. Разобрать строки stdlib-ом.
3. Собрать новый HTML: colgroup + `<tbody>` + нужный порядок строк / добавленный столбец.
4. PUT с номером версии = текущий+1.

## Проверка после правки
- GET версию: стала `cur+1`, `status==current`.
- GET body: верное число ячеек, макросы `ac:name` целы.
- Подстраницы: GET `/child/page` → сортировка.

## Питфоллы
- **409** если номер версии не инкрементирован — всегда GET текущую первым.
- **Не затирай ячейки** — сохраняй raw-HTML целиком (не текст), иначе потеряешь in-cell link / макросы.
- **Пустая строка** (row18) — оставлять как есть, для визуального разрыва.
- **Сортировка не переупорядочивает выводы сама** — переставляй и массив сервисов, и массив выводов (row19) в одном порядке.
- **Строка «Выводы» содержит макрос** `ac:structured-macro ac:name="note"/"tip"/"warning"` — переноси содержимое ячейки целиком.
- **Собирай builder-скрипт storage-HTML через `write_file`, не heredoc/`python -c`.** Cyrillic с типографскими кавычками «»— и `"` внутри двойных кавычек heredoc ломает парсер на непредсказуемой строке (`SyntaxError: invalid syntax`) — этот же код через `write_file` работает. Любой непустой контент кириллицей → пиши файл инструментом, потом запускай.

## Формат дайджеста для передачи коллегам (предпочтение Саши, 25.08.2026)

Когда просят «подготовь проект описания архива со ссылками для ответственных» (внутри компании, чтобы быстро войти в курс) — кратко, по этому шаблону:
- **Итоговая таблица первой строкой** (одна ссылка).
- **Ссылки только на Confluence-страницы** — подстраницы и итоговая; НЕ на внешние сайты/поставщиков. Если Саша сказал «убери pageId» — голый URL `https://dom.tutu.ru/pages/viewpage.action?pageId=<id>`.
- **Опиши что увидишь в таблице:** колонки = объекты по пригодности, строки = критерии/вопросы, блок «Выводы» = ✅/⚠️/❌. И **принцип сортировки** (от лучших к худшим, смотри с левого края).
- **Подстраницы списком**: краткая характеристика («подходит / частично / нет») + **одна ссылка** на страницу.
- Коротко, не перегружай деталями — цель быстрый вход в тему, не пересказ таблицы.
