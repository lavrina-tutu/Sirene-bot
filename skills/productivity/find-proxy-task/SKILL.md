# Задача поиска и оценки PROXY-поставщиков (Парсинг-К)

## Контекст

Найти и оценить сервисы, предоставляющие прокси, по набору критериев, и **единообразно сохранить результаты** в Confluence (space DPAN). Хранилище **Confluence-центричное** (Google Sheets больше не основной источник — устарел, см. `references/legacy.md`).

**Сводная страница (корень):** https://dom.tutu.ru/pages/viewpage.action?pageId=511554221
**WorkVault:** `~/WorkVault/Confluence/DPAN/Департамент аналитики и данных/Проекты/Парсинг-К/...`

Полное описание схемы + механика правок (GET/PUT/POST, вставка колонок, перенумерация, перестановка) → **`references/структура-хранения.md`**. Прочитай его перед любой правкой.

## Схема хранения (кратко)

- **Итоговая таблица «Итог по поставщикам»** — в верхней части сводной страницы. Колонки **Сервис | Статус | Описание**.
  - Сервис: ссылка на сайт + «подробнее» → подстраница поставщика.
  - Статус: пусто, либо «предложены варианты тестирования» → подстраница тестирования.
  - Описание: ✅/⚠️/❌/❓ + почему.
- **Подстраница поставщика** `Парсинг. N. <service>`: таблица **Вопрос | Желаемый ответ | Ответ** + Вывод.
- **Подстраница тестирования** `Парсинг. <service> тестирование`: предложения по тестированию (child подстраницы поставщика).
- **Матрица «Вопросы × Поставщики»** — в нижней части сводной, колонки отсортированы от лучших к худшим.

## Регламент: внесение НОВОЙ партии ответов поставщиков

Когда приходят ответы (Confluence-страницы и/или письма Exchange) от новых или уже известных поставщиков:

1. **Определить поставщика и позицию в рейтинге.** Матрица отсортирована от лучших к худшим по качеству закрытия критериев. Новая позиция — по ключевым критериям (фикс+трафик, мобильные с ротацией, выбор подсетей, API, эксклюзивность, пробный период, договор).
2. **Обновить/создать подстраницу поставщика** `Парсинг. N. <service>` (таблица **Вопрос | Желаемый ответ | Ответ**, 16 вопросов + `<h2>Вывод</h2>` + макрос вердикта). Если подстраница есть — обновить её тело (не создавать дубль).
3. **Вставить/обновить колонку в матрицу** на позицию сервиса (заголовок, вопросные строки, «Выводы», «Оплата», разделители; добавить `<col>` в `<colgroup>`).
4. **Добавить/обновить строку в итоговой таблице** «Итог по поставщикам»: Сервис (сайт + «подробнее»→подстраница), Статус (пусто или ссылка на тестирование), Описание (вердикт + почему).
5. **Переиндексировать числовые префиксы** подстраниц под новый порядок (в порядке убывания, см. reference).
6. **Проверить:** число `<td>` в матрице == числу колонок; порядок заголовков совпадает; нет дублей номеров; тела не затёрты.

## Регламент: предложения по ТЕСТИРОВАНИЮ

Когда поставщик предлагает пробный период/тестирование (в письме или странице):

1. **Создать подстраницу тестирования** `Парсинг. <service> тестирование` (child = подстраница поставщика). Только информация из **последнего письма** по этой теме. НЕ имеет числового префикса.
2. **Обновить «Статус»** в итоговой таблице: поставить ссылку «предложены варианты тестирования» → подстраница тестирования.
3. Проверить: подстраница тестирования создана, статус кликабелен.

## 16 вопросов (порядок фиксирован)

**Технические (1–13):** 1. Аренда по IP или по трафику? 2. Автопродление? 3. Выбор в конкретном городе РФ? 4. Пробный период? 5. Объём пула серверных прокси в РФ? 6. Мобильные прокси? 7. API управления? 8. Эксклюзивность IP? 9. Замена недоступных прокси? 10. Ручной выбор адресов? 11. Выбор из разных подсетей? 12. Многопоточность? 13. Уведомления о сбоях?

**Коммерческие (14–16):** 14. Работа с юрлицами / договор? 15. Способы оплаты / скидки? 16. Актуальный прайс-лист?

## Источники ответов

**Confluence-страницы:** ответы могут публиковаться как страницы. Скачать: `cd ~/USERTOOLS/ConfluenceSync && python3 -m confluencesync pull <pageId> --depth 3`, затем `rclone sync ~/WorkVault owncloud:WorkVault`.

**Exchange inbox:** ответы через посредника (`sender` содержит `mrsk.lk`). Читать через exchangelib (venv AnywhereContacts). Каждое письмо = 1 поставщик. Если только уведомление Intercom/форма — пропускай.

## Питфоллы

- **Ответы в свободной форме** (не по номерам) — читать весь текст, относить фрагменты к вопросу самому.
- **Нет ответа на вопрос** — оставлять пусто, не выдумывать.
- **Иностранный ответ** (напр. proxiempire.io) — переводить на русский, теми же словами.
- **Ответ без полного набора** — не блокировать внесение; указать в Выводе «❓ недостаточно данных».
- **Google токен/лист GS** — устарел (legacy), не требуется для Confluence-схемы.
- **Письмо обновляет существующего поставщика** — обновить подстраницу, а не плодить дубль.
- **Субагент плохо читает Exchange** — в промпт делегата явно указывать `sender` и формат заголовков, либо читать самому.
