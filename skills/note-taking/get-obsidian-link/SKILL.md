# Get Obsidian Link

Формирует ссылку на файл в Obsidian vault для отправки в Telegram — в единственном формате, который реально работает.

## Известный факт (проверено 07.07.2026, не пытаться обойти заново)

Telegram **не делает кликабельной** схему `obsidian://` ни в каком виде:
- ❌ markdown-ссылка `[текст](obsidian://...)` — не рендерится, разваливается на голый текст (при `_` в пути Telegram может даже склеить хвост `summary.md` в фейковый домен `https://summary.md/`)
- ❌ голый URL как автолинк — тоже не подсвечивается ни на мобильном, ни в Desktop
- ❌ веб-редирект через `http://` на порту 8765 (или любом нестандартном) — резался файрволом корп. домена ТУТУ даже изнутри сети
- ❌ публичный хостинг (GitHub Pages и т.п.) вне корп. домена — Саша отклонил как решение

**Рабочее решение — copy-on-tap через `inline code`.** В Telegram тап по моноширинному тексту в обратных кавычках копирует его в буфер обмена одним движением. Саша сам вставляет скопированный `obsidian://` URL в адресную строку браузера — это открывает Obsidian корректно (проверено).

## Шаги

1. Найти нужный(е) файл(ы) в `~/WorkVault` (или другом известном vault — см. скилл `obsidian`), например `search_files` с `mtime`/`iname` фильтром.
2. Для каждого файла определить путь **относительно корня vault**, без расширения `.md`.
3. URL-кодировать этот путь: `urllib.parse.quote(relative_path_without_ext, safe='/_.')` — то есть кодировать всё, КРОМЕ слэшей `/`, подчёркиваний `_` и точек `.`.
4. Собрать: `obsidian://open?vault=<VaultName>&file=<encoded_path>`.
5. Отправить каждую ссылку в формате:
   ```
   **Человеческое название файла**
   `obsidian://open?vault=WorkVault&file=...`
   ```
   Название — обычным текстом (можно с подчёркиваниями как есть, это не markdown-ссылка, конфликтов с разметкой нет). Путь — строго в `inline code` (одинарные обратные кавычки), чтобы Telegram включил copy-on-tap.

## Пример (execute_code)

```python
import urllib.parse

vault = "WorkVault"
rel_path = "Meetings/NewMeetings/2026-07-07 09-00-00 ML-платформа. Внутреннее совещание_ что делать дальше_ - summary.md"

path_no_ext = rel_path.removesuffix(".md")
encoded = urllib.parse.quote(path_no_ext, safe='/_.')
url = f"obsidian://open?vault={vault}&file={encoded}"
name = path_no_ext.split("/")[-1]

print(f"**{name}**")
print(f"`{url}`")
```

## Питфоллы

- **Тип файла строго по слову запроса.** Просит "транскрипты" → отдавать только `- transcript.md`. Просит "самари"/"саммари" → только `- summary.md`. Не путать, не отдавать оба типа "на всякий случай" если явно указан один.
- **НЕ оборачивать URL в markdown-ссылку `[]()`.** Даже с экранированием `_` через `\_` Telegram может не отрендерить или сломать её — проверено на нескольких вариантах экранирования, ни один не сработал стабильно.
- **НЕ пытаться поднять веб-редирект-сервер заново** без явного запроса Саши — уже пробовали (Python http.server на ВМ, порт 8765, HMAC-токен, rate-limit), домен режет нестандартные порты. Решение отклонено и демонтировано 07.07.2026.
- **Кодировать `_` и `/`?** Нет — оставлять как есть (`safe='/_.'`). Если закодировать `_` в `%5F`, ссылка технически рабочая, но Саша просил именно raw-вид с `_` и `/` без кодирования (соответствует тому, что видно при копировании ссылки прямо из Obsidian).
- **Имя vault** — уточнить, если неочевидно из контекста; по умолчанию для этого пользователя `WorkVault`.
- Название файла в верхней строке — используй ровно как в файловой системе (Саша явно просил "названия ссылок такие же как имена файлов").
