## When to Use

Саша прислал ссылку youtube.com и просит саммари/пересказ/транскрипт видео (или «сделай саммари из видео»). Готовить детальное русскоязычное саммари по главам.

# Транскрипт и саммари YouTube-видео

## Основной путь (пробовать ПЕРВЫМ)

1. Вытащить video_id из ссылки (`…watch?v=ID`).
2. `web_extract` на `https://www.youtube.com/watch?v=ID` с `char_limit >= 50000`. Экстрактор возвращает страницу markdown-ом, включая:
   - метаданные: канал, подписчики, лайки, просмотры, дата публикации;
   - `## Chapters` — главы с таймкодами;
   - полный автоген-транскрипт в секции `### Transcript` с таймкодами `[m:ss]` (ASR есть у любого видео).
3. Сохранить транскрипт в scratch (полный текст может понадобиться для проверки деталей).
4. Составить саммари (формат ниже) и прислать в топик, откуда пришёл запрос.

Почему это первый путь: не зависит от рукотворных субтитров, от доступа браузера и от сети ВМ к youtube.com.

## Если web_extract не дал полный транскрипт

- Повторить с большим char_limit; extractor при обрезке сохраняет полный текст на диск — дочитать хвост через сохранённый файл.
- `web_search` по точному названию видео (+ спикер + transcript): поисковик индексирует полный ASR-текст, сниппеты пригодны для коротких видео, полный текст — только через web_extract.
- Прочие пути (Invidious/Piped/транскрипт-сервисы/браузерный UI) — см. `references/fallback-services.md`; это тупики, проверяются быстро и только если основной путь реально не сработал.

## Формат саммари (предпочтения Саши)

- Только русский, по пунктам/буллетами, «как можно больше деталей»: числа, имена, названия компаний/инструментов, примеры из речи сохранять.
- Заголовок с метаданными: название видео, канал/спикер, длительность, просмотры, дата.
- Структура — по главам видео (таймкоды из Chapters): каждая глава = раздел с буллетами.
- В конце — «Ключевая идея одним предложением».
- Доставка — в тот топик Telegram, откуда пришёл запрос.

## Питфоллы

- yt-dlp и youtube_transcript_api с ВМ падают с SSL-ошибкой (TLS к youtube.com фильтруется) — ретраи бесполезны, сразу web_extract.
- Браузерный UI YouTube не трогать: гостевое меню «…» не содержит «Show transcript» (только Watch ad-free/Report), пункты меню рекомендаций/плеера легко перепутать, headless-клики по координатам мимо вьюпорта — часы впустую.
- timedtext (captionTracks baseUrl из ytInitialPlayerResponse) в headless-гостевой сессии отвечает 200 ПУСТЫМ телом — пустой 200 значит отказ, не success.
- InnerTube `get_transcript` без POT-токена/валидных для сессии params даёт 400 «Precondition check failed» — крутить варианты params бесполезно.
- Invidious/Piped-инстансы массово мертвы или за Cloudflare («Verifying your browser…» в headless не проходится) — перед любой навигацией сверять список живых через `api.invidious.io/instances.json` и быстрый curl.
- Транскрипт-сервисы (youtubetotranscript.com, notegpt.io, tactiq, kome.ai) требуют Cloudflare/App Check/авторизацию — только запасной вариант, не основной.
