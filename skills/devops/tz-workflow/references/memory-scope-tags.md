# Memory Scope Tags — архитектура (27.07.2026)

## Контекст

Cron-субагенты НЕ получают MEMORY.md (`skip_memory=True` в scheduler.py).
Весь контекст субагента = только то что явно написано в промпте крона.
Оптимизация MEMORY влияет только на интерактивные сессии Сирени.

## Scope-теги

Каждый факт в `~/.hermes/profiles/tz-dev/memories/MEMORY.md` имеет тег в конце строки:

| Тег | Назначение | Примеры |
|---|---|---|
| `[impl]` | Субагент-реализатор | пути venv, entities CLI, safety batch |
| `[tz]` | Opus при написании ТЗ | принципы проектирования, инвентарь |
| `[coord]` | Только координатор Сирень | TG-топики, кроны, триггеры скиллов |
| `[all]` | Все роли | — |

## Как строить промпт субагента

1. Взять шаблон из `references/subagent-context.md` по роли
2. Добавить только факты с нужными тегами (см. таблицу ниже)
3. Добавить полный текст ТЗ

| Роль | Шаблон | Теги MEMORY |
|---|---|---|
| Opus-ТЗ | `opus-tz-writer` | `[tz]` + `[impl]` |
| Opus-исследование | `opus-research` | `[impl]` |
| Sonnet-реализация | `sonnet-implementer` | `[impl]` |

`[coord]`-факты (TG-топики, кроны, триггеры) в промпт субагента НЕ включать.

## Почему не COORDINATOR.md

Вариант с отдельным файлом (COORDINATOR.md) отклонён — лишняя сущность + риск рассинхрона.
Scope-теги дают тот же результат без новых файлов и механизмов.
Координационные факты остаются в MEMORY (Сирень их видит), но фильтруются из промптов субагентов.

## Апстрим-устойчивость

- Не патчим `scheduler.py` / `prompt_builder.py`
- Теги = часть текста строки → не ломают другие профили и скиллы
- `COORDINATOR.md` не создаём → нет нового файла который нужно поддерживать
