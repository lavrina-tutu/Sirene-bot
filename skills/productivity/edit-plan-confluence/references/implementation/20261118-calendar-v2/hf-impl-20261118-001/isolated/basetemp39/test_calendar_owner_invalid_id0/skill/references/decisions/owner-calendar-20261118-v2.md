> еще раз - не смотрим в календарь!»

## Контекст

Первая директива (v1, owner-directive-20261118.md) сформулировала требование узко: «ровно круглосуточный календарь (7×00:00–00:00) публикуется как есть по предикату». Исполнитель реализовал предикат 24/7, но на реальном MPP ZD (`777641df…`, календарь uid:40) предикат календарь не распознал, живой resume упал rc=5 `calendar_intervals_unsupported` (7 findings строки 8). HF:test не пройден: CAL-AC-09/10/11 NOT RUN/BLOCKED.

## Решение владельца (v2, переопределяет v1)

1. Календарь проекта **не анализируется и не блокирует публикацию вообще** — ни предикат «24/7», ни какие-либо календарные проверки.
2. План публикуется **1-в-1 как есть**: даты задач (start/finish/duration), связи, назначения переносятся без пересчёта и без правок MPP.
3. **Единственная гарантия:** даты задач совпадают в архиве (подготовленный snapshot / MPP) и в опубликованном Confluence; календарь в проверке не участвует.
4. Owner evidence формата v1 сохраняется, обновляется формулировка решения: `publish_as_is` для любых календарных findings (не только 24/7).

## Что это значит для §22

- Заменить предикат «ровно семь дней 24/7» на правило: календарные findings категории `unsupported_semantics` (в т.ч. `calendar_intervals_unsupported`) по решению владельца не блокируют публикацию — снимок публикуется как есть, пометка о non-verified schedule остаётся.
- Сохранение дат задач проверяется по содержимому архива/снапшота и read-back Confluence (is_equal 1-в-1).
- Предикат/owner evidence остаются как защита от молчаливого пересчёта: без активной директивы v2 — прежняя блокирующая семантика строки 8 сохраняется.
