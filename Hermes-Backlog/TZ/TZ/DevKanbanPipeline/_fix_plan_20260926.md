#### П.1.1 Хелпер занятости (замечание ревизора 2 — имя и место обязательны)

**Имя:** `_sink_row_has_foreign_content(tr) -> bool`  
**Файл:** `playground_promote.py` (не `page_merger.py`).

Реализация дословно:

1. `tds = list(tr.findall("td"))`.
2. Если `len(tds) < 2` → `False`.
3. Идти по **всем** `<td>` кроме индекса 0 (колонка даты). td0 всегда содержит `<time datetime>` — если включить td0, пустой слот даты никогда не будет пустым, ветка append умрёт.
4. Для каждого td с индексом ≥1: `wrapper, _ = _content_wrapper_inner(td)` (импорт из `page_merger`); если `_cell_has_content(wrapper)` → `True`.
5. Иначе `False`.

«Пустой слот даты» = строка с датой в td0 и `_sink_row_has_foreign_content(tr) is False` (td1–td4 пусты: только `<p/>` / `<p></p>`).

## 7. Замечания ревизора (1–5, дословно) — все закрыты пунктами выше

1. N1 «replace» для sink_aid не должен становиться row-level. Правка N1 (приоритет «якорь есть → replace») должна сохранить replace_block_by_anchor (cell-level) как путь для «anchor уже в строке даты» — 4-шаговая логика не может подразумевать переключение на replace_row_by_anchor, поскольку та заменяет весь <tr> целиком и не рассчитана на реконструкцию 5-колоночного лейаута из 2col minutes_row. Если для нового кейса «anchor есть, но это ОТДЕЛЬНАЯ (не date-row) строка встречи» действительно нужен row-level replace — new_row_xml для него обязан быть полным 5col-<tr> (через _sink_fivecol_row-подобную сборку), не голым minutes_row.  
   → закрыто П.1.4 шаги B–C.

2. Нужен новый явный хелпер для «занятости строки», не переиспользование _cell_has_content абстрактно. Правка №1 архитектора («пусто = вся строка td1–td4») требует конкретной реализации: либо новая функция _sink_row_has_foreign_content(tr) -> bool, проверяющая ВСЕ <td> строки (tr.findall("td"), не только find_last_td), либо цикл _cell_has_content по каждому td. План v2 должен называть эту функцию явно и её местоположение (playground_promote.py, не page_merger.py), чтобы не плодить неоднозначность в реализации.  
   → закрыто П.1.1 (`_sink_row_has_foreign_content` в `playground_promote.py`; все td кроме td0).

3. Тест test_promote_sink_aid_appends_into_existing_date_row (строки 694–713) должен быть переписан, не «сохранён зелёным». Его текущая фикстура _sink_storage_with_date_row() кладёт "Manual notes" прямо в ячейку Результатов и ассертит именно append туда — то есть кодирует текущее баговое поведение как контракт. В плане v2 нужно заменить его на два теста: (a) append в РЕАЛЬНО пустую ячейку Результатов при занятой другой колонке строки (должно теперь создавать новую строку, если критерий «пусто» = вся строка) и (b) append в пустую строку без чужого контента вообще (истинно позитивный кейс). Формулировка П.4 плана v1 («appends_into_existing_date_row — пустая ячейка → append») фактически не соответствует существующему тесту и должна быть исправлена как ошибка диагностики, а не как «сохранить как есть».  
   → закрыто §1.3 ошибка диагностики + П.4 (a)(b).

4. Крон-2 (dry-run route-check) требует минимального изменения кода, а не только переформулировки формулировки крона. dry_run в promote_meeting возвращает action="promoted" (строки 427–434) ДО входа в ветку §28 — не отличает «append»/«replace»/«insert_fivecol»/«new_row (occupied)». Чтобы крон-2 реально подтверждал маршрут §28 без live PUT, PromoteResult должен нести диагностическое поле (например sink_action_kind), вычисляемое ДО early-return по dry_run, либо dry_run-проверка должна переместиться ПОСЛЕ вычисления §28-решения (но перед confluence.update_page). Без этого правка №8 архитектора («переформулировать в route-check») невыполнима — нужен явный пункт в плане v2 с указанием, что это требует code change в promote_meeting, а не только скрипта крона.  
   → закрыто П.1.2, П.1.3, П.4 dry_run-тест, §3.3 Крон-2.

5. PFS_SINK_AID_PAGE_ID должен быть реализован строго локально в playground_promote.py (п.3 «Особо проверенное»), явно с указанием «не трогать config.py». Без этого уточнения велик риск, что исполнитель по аналогии с соседними константами (WORKVAULT_ROOT, post_switch_enabled() в config.py) перенесёт константу в shared-модуль и незаметно вытолкнет фикс за пределы BUGFIX-LIGHT.  
   → закрыто П.0 и §5.
