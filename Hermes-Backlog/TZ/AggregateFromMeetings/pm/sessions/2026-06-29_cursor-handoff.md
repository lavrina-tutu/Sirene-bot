## Что изменилось — сводка для Cursor

### 1. Opus deprecated полностью (PD-028)
- Opus убирается из pipeline **везде**, включая bootstrap
- Весь прогон (bootstrap + increment) делает **Haiku**
- В ТЗ: убрать все упоминания Opus как рабочего шага; пометить как `deprecated / bootstrap-only (removed)`

### 2. Новый алгоритм bootstrap + инкремент (PD-030)

```
Bootstrap:
  -1. Встречи размечены по проектам/сущностям (classification_memory) — роутинг готов
   0. Идём поштучно по проекту/сущности
   1. Развилка:
      1.1 Проект/инициатива → начинаем с брифа и устава если есть
                              (decisions+action_items+risks из устава)
                              Если нет → сразу шаг 2
      1.2 Мультисинк / 1-1 / АДМ → сразу шаг 2
   2. От самой ранней к самой актуальной встрече:
      Haiku пополняет decisions + action_items + risks,
      сравнивая с накопленным инкрементом:
        - актуальные → оставляем
        - неактуальные → закрываем
        - изменившиеся (срок / ответственный / суть) → дополняем
   3. Если проект/инициатива:
      → запрашиваем golden ref (если есть — сравниваем через Sonnet,
        закрываем явно закрытые; если нет — пропускаем)
   4. Если мультисинк/синк-аид:
      → golden ref синка, сравниваем через Sonnet

Инкремент (каждый новый MoveFromFF):
  Тот же шаг 2, но:
  PM Notes имеет главенствующий приоритет над текущим инкрементом —
  становится его новой версией.
  Новая информация из следующей FF-встречи учитывается наравне
  с (инкремент + PM Notes).
```

### 3. Новый артефакт: risks.md (PD-031, PD-034)

- Добавить `Projects/<slug>/ai/risks.md` — только для проектов/инициатив
- Не для синков, не для 1-1, не для АДМ
- Инициализируется из устава/брифа проекта; если нет — пустой файл
- Отдельного блока `Risks` в FF-summary нет — Haiku распознаёт риски самостоятельно из `Bullet points` и `Notes` по контексту
- Пополняется Haiku инкрементально (как decisions и action_items)
- В ТЗ модуль D: добавить `risks.md` в список выходных артефактов
- В ТЗ модуль C: добавить извлечение risks из Bullet points + Notes

### 4. Blockers живут в decisions.md (PD-032)

- Блокеры = отдельный тип записи в `decisions.md`
- Не в `action_items.md`, не в `risks.md`
- В ТЗ модуль D: явно прописать тип записи `blocker` в decisions.md

### 5. Резолв конфликтов — в модуле D (OQ-004)

- Конфликт решений (позднее противоречит раннему) разруливается в D
- Позднее решение зачёркивает раннее при сборке хронологии
- В ТЗ модуль D: добавить алгоритм резолва конфликтов

### 6. Идемпотентность (OQ-003)

- Если встреча уже обработана — не перепрогонять

### 7. PM Notes — приоритет в инкременте (OQ-005, PD-027)

- Все встречи попадают в агрегацию (фильтра нет)
- PM Notes: свободный текст, интерпретируется через LLM
- В инкременте PM Notes имеет главенствующий приоритет — становится новой версией инкремента
- В ТЗ модуль D: добавить правило приоритета PM Notes

### 8. Exchange Org Lookup (PD-026, bk-098)

- Golden ref расширяем: PM даст дополнительные Confluence URL
