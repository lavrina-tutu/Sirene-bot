# Модель процесса «Архитектор → Ревизор → Бриф → Реализация»

Дословная фиксация формулировки Саши от 07.09 (как он видит целевой процесс):

1. **Материал из сессии ТГ** (с нужными ТЗ) передаётся в **Курсор**, где уживается и передаётся на проработку **архитектору**.
2. **Архитектор** готовит вопросы: к каждому — 2–3 варианта ответа и свою рекомендацию. Возвращает это в основной процесс Hermes (в чат).
3. **Базовая модель профиля** показывает Саше вопросы в режиме брифа: поштучно, с вариантами ответа и рекомендациями от архитектора (**строго**: базовая модель ничего не придумывает, она только оркестратор). После каждого ответа Саши вопрос+ответ записываются в **расширение к ТЗ**.
4. После ответа на все вопросы — результаты передаются **обратно архитектору на доработку ТЗ**. Если есть новые вопросы — цикл повторяется до полного решения всех вопросов. Итог: готовое ТЗ + вся переписка архитектора с Сашей по вопросам (в расширении ТЗ).
5. По готовности ТЗ — **челендж другой LLM через Курсор**, назовём её **«Ревизор»**. Ревизор заточен на поиск слабых мест. Знает переписку и архитектуру экосистемы. Задаёт каверзные вопросы архитектору (вероятно через оркестратора). Все находки/вопросы решает с архитектором в цикле. Итог: хорошо проверенное ТЗ.
6. По ТЗ **архитектор** создаёт **пофайловый план реализации и тестирования** (включая интеграционное, если задействуются смежные инструменты).
7. **Ревизор** проверяет этот план, имея те же вводные. По согласованию (через оркестратора) — получаем **«золотой план»** реализации и тестирования.
8. Далее по «золотому плану» работает **hermes feature**.

## Ключевые принципы (из формулировки Саши)
- **Базовая модель Hermes = оркестратор**, не придумывает — только транслирует вопросы/варианты/рекомендации архитектора.
- **Бриф живёт в Telegram** (чат), не в канбане.
- Вопрос → 2-3 варианта + рекомендация архитектора.
- Каждый вопрос+ответ **сразу в расширение ТЗ** (полная переписка сохраняется).
- **Ревизор** = независимый LLM (через Kursor) для поиска слабых мест. Модель: `claude-sonnet-5-medium`.
- **Ревизор опционален**: режим без ревизора (быстрый путь, меньше токенов) — для простых задач по решению Саши.
- Итог: проверенное ТЗ → «золотой план» → hermes feature.
