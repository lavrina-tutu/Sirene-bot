# Подтверждение точного имени (инструмент/бренд) из встречи

## When to use
Саша спрашивает «о каком инструменте/продукте/бренде шла речь», часто приводя
искажённую форму со слуха («preplan» вместо ProductPlan), или просит подтвердить
название из состоявшейся встречи.

## Правило: транскрипт — источник истины, не саммари
- Авто-саммари (блок «Обсудили»/«Resolved» в заметке) перифразирует и **выбрасывает
точные proper nouns** — по нему имя не подтвердить.
- Распознавание речи (Fireflies и др.) само **искажает вендорские/латинские имена**
(ProductPlan → «Преап План», «Прио План», «пиоплан»; корпоративные названия маскируются
артефактом `TUTU` — игнорировать).

## Шаги
1. Найти встречу: `search_meetings` (mofs_index, по дате/теме) или `session_search`,
если она уже обрабатывалась.
2. Прочесть ТРАНСКРИПТ целиком (`get_meeting_body(mid, include_transcript=True)` для
встреч в WorkVault; GraphQL-запрос `transcript(id)` для Fireflies). Длинные транскрипты
читать через `execute_code`, не в контекст.
3. Искать в транскрипте И искажённую форму, И контекстные слова темы:
ProductPlan → «идея», «эпик», «роадмап», «PRD»; сверять с функциями, которые описывает
говорящий.
4. Сверить кандидата с реальными названиями на рынке (web_search), если имя не
сходится дословно.
5. Уверенно утверждать имя **только** при подтверждении в транскрипте или
единственном кандидате по смыслу; иначе назвать 2-3 варианта и попросить контекст.

## Питфоллы
- Не давать вердикт по авто-саммари — точных имён в нём обычно нет.
- Не отвергать искажённую форму пользователя как «ошибку» — это рабочий запрос:
искать по ней, а не ждать точного написания.
- Многословный кириллический `search_meetings(query=...)` может упасть с
`no such column: <слово>` (FTS5-токенайзер рвёт фразу). Fallback — однословные
запросы + `date_from`/`date_to`; ошибка ≠ «встречи нет».

## Связанные скиллы
- `workvault-rag` — поиск встреч/решения/риски по архиву (делает Шаг 1-2).
- `fireflies-transcripts` — выгрузка транскриптов Fireflies (живой звонок без
обработанной заметки).
