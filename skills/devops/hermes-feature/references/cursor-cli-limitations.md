# Cursor CLI — известные ограничения и паттерны

## `--workdir` НЕ поддерживается

Cursor CLI (`agent`) **не принимает флаг `--workdir`**. Попытка передать его даёт:
```
error: unknown option '--workdir'
```

### Альтернативы

1. **cd + agent** — запустить из нужной директории:
   ```bash
   cd ~/USERTOOLS/ProtocolFromSummary && agent -p "..." -f --model composer-2.5 --output-format json
   ```

2. **Абсолютные пути в промпте** — явно указать все пути в тексте промпта:
   ```
   Рабочая директория: ~/USERTOOLS/ProtocolFromSummary
   Файлы для правки: ~/USERTOOLS/ProtocolFromSummary/protocolfromsummary/config.py
   Тесты: ~/USERTOOLS/ProtocolFromSummary/tests/
   ```

3. **cd в теле промпта** — instruct исполнителя:
   ```
   Перед началом: cd ~/USERTOOLS/ProtocolFromSummary && source .venv/bin/activate
   ```

### Pitfall: `agent` vs `codex` vs `cursor`

Разные CLI-обёртки имеют разные флаги. `agent` (Cursor CLI) — минимальный набор:
- `-p` (print-mode), `-f` (force), `--model`, `--output-format`
- **Нет:** `--workdir`, `--config`, `--env`

Если нужен контроль рабочей директории — вариант 1 или 2 выше.

## Размер промпта и таймауты

composer-2.5 через Cursor CLI **таймаутится на больших промптах** (12+ файлов, >4K токенов в задаче).
Признаки: `[Command timed out after 300s]` без промежуточного вывода.

**Решение:** делить задачи на 2-3 промпта по 4-6 файлов каждый. Порядок:
1. Фундамент (pyproject.toml, config, клиент, маппинг)
2. Логика (форматирование, черновик, бриф, превью)
3. Оркестрация (selfcheck, CLI, `__main__.py`)

Архитектору (claude-sonnet-5-thinking-medium) — один промпт на анализ+план (до 50 файлов).
Исполнителю (composer-2.5) — только 4-6 файлов за раз, с абсолютными путями и API модулей.

### Pitfall: код с тройными бэктиками + кириллические докстринги

При передаче больших блоков кода в промпте, обрамлённых тройными бэктиками (```python ... ```),
содержащих кириллические строки-докстринги — **bash начинает интерпретировать части докстрингов
как shell-команды** до того как Cursor CLI получит промпт. Результат: сотни ошибок вида
`bash: line X: <кириллица>: command not found`, после чего промпт доходит до Cursor в мутантном
виде и таймаутится. Прецедент: OKRTool v0.1.0 (Фазы 6, 7, README — 3 таймаута подряд).

**Обходной паттерн (работает надёжно):**
1. **Не вставляй полный код в промпт** — опиши контракт словами: «создай класс X с полями Y, функция Z делает N»
2. **Дай исполнителю прочитать контекст** — «прочитай существующие модули A, B, C для конвенций»
3. **Разбей на 1-2 файла за вызов** — один промпт = один файл, следующий вызов = следующий файл
4. **Если composer всё равно таймаутится** — увеличь timeout до 120-180с, или создай файл напрямую через `write_file`

Архитектору (claude-sonnet-5-thinking-medium) — полный код в промпте ОК (он не страдает от bash-интерпретации).
Исполнителю (composer-2.5) — контракт словами, не копипаста кода.

## Написание тестов напрямую vs через Cursor

Когда API модулей уже известен (прочитан через `read_file`) и тесты механические
(проверка assert, mock-клиенты, фикстуры) — **писать тесты напрямую через `write_file`**
быстрее и надёжнее, чем делегировать Cursor CLI.

Cursor CLI на тестах:
- Требует загрузки API всех модулей → рост промпта → таймаут
- Часто ошибается в деталях assert (нужны 1-2 итерации исправлений)

Прямое написание через `write_file`:
- Архитектор уже прочитал API → знает сигнатуры → может сразу написать точные тесты
- 1-2 файла = 1 `write_file` call, полный контроль над assert
- Легче чинить regressions (видишь diff, патчишь)

**Когда всё же делегировать Cursor на тесты:** интеграционные тесты с реальными HTTP,
сложные фикстуры с реальными данными, parametrize на 20+ кейсов.

Если инструмент использует ленивый `import` (например `import openai` внутри функции),
пакет может отсутствовать в `.venv` проекта. Проверить перед запуском тестов:
```bash
~/USERTOOLS/Project/.venv/bin/pip show openai  # пусто = не установлен
~/USERTOOLS/Project/.venv/bin/pip install openai
```

Это не ошибка — пакеты типа `anthropic`, `openai` часто не объявлены в `pyproject.toml`
как жёсткие зависимости, а ставятся отдельно.

## Бэкап перед правками

Всегда создавай бэкап перед Cursor CLI правками:
```bash
TS=$(date +%Y%m%d-%H%M%S)
mkdir -p ~/.hermes/_Archives/hermes-backup-$TS/project-name
cp -r ~/USERTOOLS/ProjectName ~/.hermes/_Archives/hermes-backup-$TS/project-name/
```
