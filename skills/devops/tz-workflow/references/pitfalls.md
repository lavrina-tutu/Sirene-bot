# Common Pitfalls — tz-workflow

- **Не создавай `<Tool>_TZ_v2.md` в активной папке** — v-в-имени только для архивных снапшотов в `WorkVault_backup/`.
- **Не переименовывай кириллические архивные файлы** в `WorkVault_backup/` (это архив, не навигация Obsidian).
- **Не забудь обновить `MAIN_TZ_INVENTORY.md` в той же операции**, что и правку ТЗ, — иначе расхождение.
- **Не пиши содержание ТЗ сам, если ты не Opus** — делегируй. Механику (перенос, frontmatter, инвентарь) можешь.
- **Не рестартуй gateway.**
- **Не трогай `Projects/`, `People/`, `Meetings/`, `Contacts/`, `~/hermes-config*`, `~/hermes-workspace`.**
- **Не создавай отдельный точечный файл под доработку существующего инструмента** — правило «не распыляться». Секция в master-ТЗ.
- **Согласовать текст ≠ начать реализацию.** Ждать отдельной команды.
- **Не путай «рабочие материалы инструмента» с «ТЗ-контентом»** — брифы/research/runtime-json остаются в папке инструмента, не в `TZ/<Tool>/`. Если сомневаешься — зафиксируй как открытый вопрос.
- **Не оставляй файлы «для истории» в backup вне зеркальной структуры** — либо архив по правильному пути, либо уже есть в общем tgz-снапшоте.
- **При задаче «перенести все ТЗ по всем инструментам» — сначала `search_files` по всему дереву**, не полагайся на список в промпте (проверено: первая волна пропустила 9 инструментов).
- **Заголовок секции доработки не обновляется сам.** При делегировании явно указывай субагенту обновить заголовок по образцу завершённых секций (например `## Доработка: ... — РЕАЛИЗОВАНО (дата)`). Проверяй заголовок при финальной сверке.
- **В длинной цепочке ТЗ→бриф→обновление** — при каждом новом cronjob явно сообщать Саше: «это только правка ТЗ» или «начинаю реализацию».
- **Перед реализацией инструмента работающего с данными** — делать бэкап. `cp ~/WorkVault/Contacts/contacts.enc ~/WorkVault_backup/Contacts/contacts_pre-<Tool>-$(date +%Y%m%d-%H%M).enc`.
- **Decommissioned-инструмент ≠ автоматическая архивация без подтверждения.** Отсутствие кода — основание предложить архивацию, но финальное решение за Сашей.
- **Субагент создаёт скиллы в `~/.hermes/profiles/default/skills/`, даже если активный профиль tz-dev.** Симптом: `⚠️ Skill not found and skipped`. Фикс: `cp -r ~/.hermes/profiles/default/skills/devops/<skill> ~/.hermes/profiles/tz-dev/skills/devops/`. Предотвращение: в промпте субагента указывать полный путь `~/.hermes/profiles/tz-dev/skills/...`.
- **Если после `cronjob(action='create')` пользователь уточнил скоуп — обновлять промпт немедленно через `cronjob(action='update')`.** Проверять `cronjob(action='list')` перед ответом «уже запущено».
- **Когда Саша спрашивает «готово?» / «проверяй» — всегда `cronjob(action='list')` + читать output-файл.** Никогда не отвечать по памяти или оценке времени.
- **Не доверяй отчёту субагента о существовании кода без собственной проверки.** Перед правкой статуса `active`↔`draft` физически проверить `search_files`/`find` в реальном коде (не в `venv`/`node_modules`/`__pycache__`).
- **После создания/правки ТЗ вызвать `mofs-index index docs`** — инкрементальная переиндексация, <1 сек.
- **Бриф в режиме диалога: варианты всегда по номерам (1/2/3), не по буквам.** Один вопрос, пронумерованные варианты, рекомендация одной строкой.
