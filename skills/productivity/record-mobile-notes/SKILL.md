# Record Mobile Notes — итоги из транскрипта записи

## Триггер
Запускается по фразам:
- «подведи итоги», «собери итоги из тхт», «собери итоги с мобильного»
- «итоги из транскрипта», «разбери стенограмму», «итоги встречи из txt»
- Пользователь прислал `.txt` со стенограммой и просит структурированные итоги

**Не использовать для:**
- Fireflies API / ссылок `app.fireflies.ai` → `fireflies-transcripts`
- Публикации протокола в Confluence → `protocolfromsummary`
- Извлечения обязательств/дедлайнов из договоров с цитатами → `document-to-action-items`

## Назначение

Превратить сырую стенограмму (часто с мобильного диктофона) в компактный текстовый отчёт:
все обсуждаемые темы, по каждой — **итог / решение / требование** как в записи.
В конце — блок **«Практические действия»** (поручения/дедлайны), если в транскрипте были конкретные поручения, дедлайны или «что нужно сделать» для участников.

## Пайплайн

### 1. Получить путь к транскрипту
- Путь в запросе, вложение в диалоге или файл в `~/.hermes/cache/documents/...`
- Если путь не указан — спросить один раз

### 2. Декодировать, если файл «бинарный»
Если `read_file` вернул `Binary file` или нечитаемый текст:
→ скилл **`decode-text-document`** (типично UTF-16BE/LE с мобильных экспортов).
После `iconv` работать с `/tmp/decoded.txt` (или аналогом).

```bash
xxd /path/to/file | head -1   # feff → UTF-16BE, fffe → UTF-16LE
iconv -f UTF-16BE -t UTF-8 /path/to/file > /tmp/decoded.txt
```

### 3. Прочитать транскрипт целиком
- Читать **весь** файл (при необходимости частями), не выборочно
- Зафиксировать заголовок/контекст: тип встречи, участники, спикер — **только если сказано в записи**

### 4. Извлечь все темы
Пройти стенограмму от начала до конца. Для **каждого** обсуждаемого вопроса:
- краткое название темы (как в записи, без домыслов)
- итог / решение / требование / факт — **только то, что прозвучало**
- если по теме несколько уточнений — объединить в один пункт, не теряя смысл

**Запрещено:** дополнять, обобщать «от себя», пропускать мелкие темы, сливать разные вопросы в один.

### 5. Раздел «Практические действия»
Если в транскрипте были явные поручения, дедлайны или «нужно сделать» для участников/исполнителей —
вынести в отдельный финальный раздел списком (маркеры `•` или нумерация).
Если таких формулировок не было — **раздел не добавлять**.

### 6. Сохранить результат
Имя выходного файла: по смыслу исходника, суффикс `_итоги.txt` (или как попросил пользователь).
Типичные пути: `/tmp/<имя>_итоги.txt`, `~/WorkVault/Inbox/`, каталог рядом с исходником.

Вернуть пользователю путь к файлу и кратко: число тем, есть ли блок действий.

## Формат выходного .txt

Простой текст, UTF-8. Два рабочих варианта (выбрать один, быть последовательным в файле):

**Вариант A — табличный заголовок + нумерованные блоки** (развёрнутый формат):
```
<ЗАГОЛОВОК ВСТРЕЧИ> — ИТОГИ
Спикер: <если известно из записи>
Источник: стенограмма <имя_файла>

================================================================================
№ | ВОПРОС / ТЕМА | ИТОГ / РЕШЕНИЕ / ТРЕБОВАНИЕ
================================================================================

1. <тема>
   <итог/решение — одна или несколько строк>

2. ...

================================================================================
ПРАКТИЧЕСКИЕ ДЕЙСТВИЯ
================================================================================

• <действие>
• ...
```

**Вариант B — компактная таблица** (компактный формат):
```
<ЗАГОЛОВОК>
Итоги обсуждения (по стенограмме)

================================================================================

№ | ВОПРОС / ТЕМА | ИТОГ / РЕШЕНИЕ / ТРЕБОВАНИЕ
--------------------------------------------------------------------------------

1 | <тема>
   | <итог>

...

================================================================================
ПРАКТИЧЕСКИЕ ДЕЙСТВИЯ
================================================================================

1. <действие>
2. ...
```

Эталоны: `/tmp/Встреча_итоги.txt`, `/tmp/Синк_команды_итоги.txt`.

## Проверка перед отдачей

- [ ] Пройдена **вся** стенограмма, не только начало
- [ ] Каждая заметная тема из записи отражена отдельным пунктом
- [ ] Нет фактов, которых не было в транскрипте
- [ ] Блок «Практические действия» (поручения/дедлайны) — только при наличии в источнике
- [ ] Файл сохранён в UTF-8, читается без кракозябр
