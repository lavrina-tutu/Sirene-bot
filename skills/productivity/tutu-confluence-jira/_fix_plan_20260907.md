## Root cause (подтверждено на коде 2026-09-07)

1. `scripts/vestnik_theme_intent.py::_tokenize` (строки 76-83) кладёт в токены ВСЕ элементы `command_text` (split по `[\s,;]+]` без фильтрации. Однословный кириллический токен проходит через `parse_confluence_url` как `page_id==token` (проверено: `parse_confluence_url('Новый')` → `page_id='Новый'`).Таким образом фраза «Новый экран поездок» + ссылки даёт `resolved=['Новый','экран','поездок',<числа>...]` — кириллица уходит в `page_ids` → `run_add` вызывает `_get_page('Новый')` → падение (UnicodeEncodeError ascii / 404).Проверено на живом коде: `page_ids=['Новый','экран','поездок','517103930','517103955']`
2. CLI `--page-id` (action=append и добавляет каждое значение строкой без разбора. Передача `--page-id "517103930,517103955,517104066"` — один токен со запятыми → `parse_confluence_url` → ValueError → отброшен → `no page ids or refs in input` (проверено).

## План П.1...П.N

### П.1 — фильтрация токенов в `parse_intent` / `_tokenize`
Файл: `scripts/vestnik_theme_intent.py`.
- В `_tokenize`: НЕ фильтровать наивно по признаку «число / URL» — числа и URL должны пройти через `parse_confluence_url` как сейчас(число→`page_id`,` URL→`page_id`).
- В `parse_intent` (цикл по токенам) после `parse_url(token)`:
 - `ref.page_id` присутствует → `resolved` (числа, URL, url_utils уже даёт page_id). 
 - **отбрасывать `ref.page_id`, если токен — кириллическое слово**(т.́ результат `parse_url('Новый')` даёт `page_id==token`;иначе токен уйдёт в `_get_page` и упадёт).
- Критерий «кириллическое слово»: `re.fullmatch(r'[А-Яа-яЁё]+', token)`(без цифр, пунктуации, `-`, пробелов).Если токен — кириллическое слово → НЕ в `resolved`, НЕ в `raw_refs`; учитывать как кандидата темы(см. П.3 отбрасывать.)
- Токены с пробелами внутри(многословные кириллические фразы)уже дают ValueError → skip(не трогаем.)
- Пустые результаты → как сейчас `VestnikError('no page ids or refs in input')`.

### П.2 — `--page-id 1,2,3` + свободные ссылки в command_text
Файл: `scripts/vestnik_theme_intent.py`.
- В `_tokenize`(или в `parse_intent` перед циклом):каждую строку из `page_ids` сплитить по `,` / `;` / пробелам → отдельные id до передачи в `parse_url`.
- Свободные ссылки в `command_text` уже работают(URL-токен → `_TOKEN_SPLIT` → `parse_url` → `page_id`).Покрыть тестом — фиксы не требует(кроме фильтра П.1, чтобы url-токены не отбрасывались.)
- Фильтр П.1 должен пропускать URL-токены как сейчас.



### П.3 — Тема из свободного текста(если передан отдельно от ссылок)
Файл: `scripts/vestnik_theme_intent.py` + возможно `scripts/vestnik_theme.py`
- Ожидаемое поведение(из карточки: команда «добавь тему в Вестник <произвольный текст темы> <ссылка1> <ссылка2>»):извлекаются только URL/pageIds как материалы;текст темы — не мусор.
- Свободная фраза(т.́ не-URL кириллические токены из командысобранные в П.1)передаётся как **название темы**(`theme`)вместо текущего дефолта `materials[0].title`.
- Если свободного текста нет → `theme = materials[0].title`(как сейчас).
- Сборка названия: склеить кириллические токены из `command_text`(в порядке появления)пробелом;удалить служебные слова команды(«добавь», «тему», «в» ...)— либо обрабатывать как текст после ключевого слова до первой ссылки. Точный эвристик — на этапе реализации(архитектор)и согласуется в ТЗ.
