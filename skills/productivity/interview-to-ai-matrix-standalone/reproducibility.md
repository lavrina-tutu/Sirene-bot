# Устойчивость результата (воспроизводимость)

Отвечает на вопрос: «Если прогнать один и тот же процесс несколько раз — получится
ли одинаковая матрица?»

## Короткий ответ

Нет, не дословно. Модель вероятностна. При одинаковом входе:

- **оси матрицы (стадии и виды деятельности) — устойчивы** примерно в 90% случаев: разбиение процесса задаётся его описанием;
- **формулировки клеток — почти всегда варьируются** (синонимы, разный уровень детализации);
- **тип ИИ в очевидных клетках — устойчив**, а в пограничных (между ассистентским и агентным, между сотрудничеством и «нет») может меняться от прогона к прогону.

Поэтому для финального артефакта навык не полагается на один прогон, а использует
**протокол тройного прогона с согласованием**.

## Протокол тройного прогона (для финальных матриц)

Применяется, когда матрица идёт в презентацию, руководству или в продакшен, либо
когда пользователь просит «устойчивый / воспроизводимый» результат. Для черновика
достаточно одного прогона.

```
- [ ] Шаг A: Зафиксировать оси (стадии + виды деятельности) ДО заполнения клеток.
- [ ] Шаг B: Собрать матрицу 3 раза независимо на одних осях и входных данных.
       Сохранить как run1.spec.json, run2.spec.json, run3.spec.json.
- [ ] Шаг C: Свести прогоны в согласованную версию скриптом:
       python scripts/consensus_matrix.py \
         --inputs run1.spec.json run2.spec.json run3.spec.json \
         --output <имя>.spec.json --report <имя>.divergence.md
- [ ] Шаг D: Выгрузить согласованный spec в Excel (export_matrix.py).
- [ ] Шаг E: Показать пользователю оценку устойчивости и спорные клетки из отчёта.
```

### Почему сначала фиксируем оси (Шаг A)

Большая часть разброса — не в типах ИИ, а в том, что разные прогоны по-разному
дробят процесс на стадии. Если зафиксировать стадии и виды деятельности один раз и
переиспользовать их во всех трёх прогонах, разброс падает кратно, а согласование
становится сопоставимым по клеткам (одинаковая сетка).

## Как работает согласование (`consensus_matrix.py`)

Это «усреднение» для категориальных данных — голосование по большинству:

1. Каждая клетка каждого прогона относится к одному из 4 типов ИИ.
2. Для каждой клетки берётся тип, который встретился в большинстве прогонов.
3. Текст клетки берётся из того прогона, чей тип совпал с согласованным (предпочитается более детальная формулировка).
4. Стадия считается **критической**, если её отметили критической в большинстве прогонов.
5. Ответственный по стадии — тоже по большинству голосов.
6. Считаются метрики устойчивости.

## Метрики устойчивости

| Метрика | Что значит |
|---|---|
| **Устойчивость «как сейчас»** | Доля клеток, где все три прогона дали один тип |
| **Устойчивость «как будет»** | То же для матрицы «как будет» |
| **Спорные клетки** | Клетки, где прогоны разошлись |
| **Расхождения по осям** | Прогоны по-разному раздробили стадии / виды деятельности |

Как читать оценку устойчивости:

- **0.85 и выше** — матрица устойчивая, можно нести в презентацию как есть;
- **0.6–0.85** — устойчива в основном; спорные клетки вынести на обсуждение с владельцем;
- **ниже 0.6** — процесс описан слишком размыто либо много пограничных решений; вернуться к уточнению входных данных.

## Что повышает устойчивость

- **Фиксируй оси** перед заполнением клеток (Шаг A) — главный рычаг.
- **Опирайся на дерево выбора типа** (`reference.md`), а не на интуицию — меньше разброса в пограничных клетках.
- **Меньше ИИ — лучше**: консервативный выбор уменьшает «плавающие» агентные клетки.
- **Артефакт обязателен**: клетки с явным артефактом устойчивее абстрактных.
