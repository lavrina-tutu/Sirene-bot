# PFS Дедупликация — архитектурные решения (бриф 27.07.2026)

## Контекст
ProtocolFromSummary v1.6.1 — дедупликация задач/решений/блокеров/рисков перед публикацией в Confluence + фикс рисков.
Реализовано: Sonnet (§14+§15 код) + Opus (интеграция pipeline + промпты) + субагент (reasoning логирование). 162/162 тестов.

## Алгоритм дедупликации (принято Сашей)

### Источник истории
- Читать из той же страницы Confluence куда пишем (GET уже делается).
- Страница считается источником истины — Саша её обрабатывает вручную.
- Окно сравнения: **3 недели назад** — строки за этот период, строки старше игнорируются полностью.

### Задачи
- Алгоритм: **fuzzy match за 3 нед → если не нашлось → Haiku за 3 нед** (пакетный запрос).
- Дубль только если предыдущая задача **открыта** (`ac:task-status=incomplete`).
- Если предыдущая задача **закрыта** — это новая задача, добавляем без вопросов.
- При обнаружении дубля: пропустить + уведомить в TG («задача X уже есть, не добавлена»).

### Решения и блокеры
- Алгоритм: **fuzzy match за 3 нед → если не нашлось → Haiku за 3 нед** (единый алгоритм).
- Статус закрытости не проверяем (в отличие от задач).

### Риски
- Алгоритм: только **Haiku за 3 нед** (fuzzy не подходит — риск может перефразироваться).
- Haiku анализирует: похожий ли риск по смыслу + изменилось ли вероятность/влияние.
- Если изменилось хоть что-то → добавляем (риск эволюционировал).
- Если ничего не изменилось → пропускаем (дубль).

### Починка рисков (§14)
- `storage_xml.py::render_row` не передавал и не рендерил `risks` — баг с первой версии.
- Фикс: добавлен параметр `risks: list[str]` и секция `<h2>Риски:</h2>` после блокеров.
- Применимо ко всем трём layout: `2col`, `5col_aid`, `3col_content_last`.

## Логирование reasoning (добавлено 27.07.2026)

Для каждого дубля найденного через Haiku пишется:
```
log.info("dedup: дубль [тип] 'новый текст' → 'существующий текст' (reasoning: ...)")
```
Типы: задача / решение / блокер / риск. Тексты обрезаются до 80 символов.

Анализ логов:
```bash
grep "dedup: дубль" ~/.hermes/logs/hermes.log    # найденные дубли с reasoning
grep "dedup.*ошибка\|dedup.*failed" ~/.hermes/logs/hermes.log  # ошибки
```

Триггеры для правки промптов при ложных срабатываниях:
- reasoning содержит «версия/фаза/номер/этап» → уточнить `PROMPT_TASK_DEDUP`
- reasoning содержит «severity» без явного изменения → добавить few-shot пример в `PROMPT_RISK_DEDUP`

## Важные уточнения
- fuzzy И Haiku смотрят только за 3 недели — строки старше полностью игнорируются.
- Haiku вызывается одним пакетным запросом на всю встречу (не по одному элементу).
- Уведомление о пропущенном дубле идёт в TG-уведомление после публикации (не отдельное сообщение).
- Дедупликация **выключена при republish** той же встречи.
- Fail-soft: любая ошибка дедупликации → публикуем всё исходное, логируем WARN.
