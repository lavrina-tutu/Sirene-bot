# Status Snapshot — срез проекта

Инструмент создаёт markdown-страницу текущего состояния проекта после каждой FF-встречи.

## ⚠️ Только Exchange
Все встречи — только Exchange EWS. Google Calendar не используется. PM-блоки и pm_locked не реализованы в v1 (нет фоновых обновлений).

## Правила PM Warnings (из брифа 17.06.2026)

**HIGH 🔴 (действие на этой неделе):**
- Срок сдвинулся без «потому что» в summary
- Артефакт/задача не в context.md scope (scope creep)
- Критерий приёмки «✅» в card.md с Confluence-документом, но пересматривается
- Риск повторяется 2+ раза без митигации
- Ключевой ресурс на критическом пути отсутствует ≥1 нед. без замены
- Срок платежа < 5 рабочих дней или нарушен
- Обязательство вендора из context.md не выполнено

**MEDIUM 🟡 (решить в течение спринта):**
- Возможный scope creep (артефакт вне context.md, PM решает в заметках)
- Критерий согласован устно и пересматривается
- Action item повторяется 2+ нед. без прогресса
- Ресурс не на критическом пути отсутствует ≥1 нед.

**LOW 🟢 / инфо:**
- Устные договорённости без action item

## Правила секций (из брифа В1–В8)

- **Сделано** = глагол совершенного вида + субъект. «Почти готово» → В работе.
- **В работе** = задача + владелец. Без владельца → «не определён», PM назначит.
- **Блокер** = факт + кто + что нужно + срок. Без срока → «не определена» + Warning.
- **Решения** = устная договорённость с «договорились что X».
- **Устные договорённости** без action item → В работе, владелец «не определён».
- **Сверка с card.md** = только ключевые поля: даты, платежи, критерии приёмки, допущения.
- **Критерии приёмки закрыты:** с Confluence-документом — жёстко (любые правки = Warning HIGH), устно — мягко (крупные правки = Warning MEDIUM).
- **Финтрекинг** = только сроки платежей по договору. При упоминании в summary — проверить дату из context.md.

## Алгоритм работы

1. **Определить slug проекта** из запроса или по `meeting_title` (сверить с `Projects/*/card.md`).
2. **Прочитать входные данные:**
   - FF summary встречи (свежий файл из FF-источника / `Projects/{slug}/meetings/`).
   - Предыдущий срез — самый свежий `Projects/{slug}/snapshots/{slug}-snapshot-*.md` (или «нет», если первый).
   - `Projects/{slug}/card.md` — карточка.
   - `Projects/{slug}/context.md` — устав / контекст / scope.
   - PM-заметки из предыдущего среза (блоки `<!-- pm: ... -->`).
3. **Применить prompt-шаблон** из §11 ТЗ. Подставить переменные `{meeting_summary}`, `{prev_snapshot}`, `{card_md}`, `{context_md}`, `{prev_pm_notes}`, `{slug}`, `{meeting_title}`, `{YYYY-MM-DD}`.
4. **Сгенерировать содержимое** строго по формату вывода §11 (frontmatter + Warnings + секции + ссылка на предыдущий срез).
5. **Сверить с ключевыми полями** card.md / context.md (см. §9.7): сроки, платежи, критерии приёмки, допущения. При отклонениях — Warning по §10.
6. **Записать файл:**
   - Имя: `{slug}-snapshot-{YYYY-MM-DD}.md`
   - Путь: `~/WorkVault/Projects/{slug}/snapshots/{slug}-snapshot-{YYYY-MM-DD}.md`
   - Без перезаписи: если файл существует — добавить суффикс `-v2`, `-v3`, …
7. **Сообщить пользователю** путь к файлу + краткое summary (сколько Warnings и какого уровня).

## Правила для секций (кратко, полное — §9 ТЗ)

| Секция | Что попадает | Что НЕ попадает |
|---|---|---|
| Решения | «договорились», «решили», «согласовали» | гипотезы, обсуждения без вывода |
| Сделано | завершённые действия (сов. вид) + субъект | «почти готово», «100% но не проверено» |
| В работе | задачи с владельцем (даже устные) | без исполнителя → «не определён» |
| Блокеры | факт + кто блокирует + что нужно + дата | без даты → дата «не определена» + Warning |
| Следующие шаги | action items с владельцем И сроком | без срока → Открытые вопросы |
| Открытые вопросы | всё без срока/владельца | — |

## PM Warnings — пороги (кратко, полное — §10 ТЗ)

🔴 **HIGH:** сдвиг срока без «потому что», нарушение обязательств вендора, scope creep с эскалацией, риск 2+ срезов без митигации, ресурс на крит.пути отсутствует ≥1 нед., платёж < 5 раб. дней или нарушен, переоткрытие критерия с Confluence-фиксацией.

🟡 **MEDIUM:** возможный scope creep, мягкая фиксация критерия + пересмотр, action item висит 2+ нед., ресурс не на крит.пути отсутствует ≥1 нед.

🟢 **LOW/инфо:** устные договорённости без исполнителя, мелкие сдвиги в допустимом окне.

## PM-блоки
- После каждой секции в новом срезе — пустые `<!-- pm: --><!-- /pm -->`.
- При генерации читать прошлые PM-блоки как контекст, но в новый файл переносить пустыми.
- `pm_locked` в v1 не реализуется (см. §6 ТЗ).

## Что НЕ делать
- Не перезаписывать существующие срезы.
- Не использовать алиас `latest`.
- Не вытаскивать из summary дословные цитаты — переформулировать в action-формате.
- Не пытаться отслеживать полную стоимость проекта — только сроки платежей (§9.5).
- Не дёргать Jira — её нет, источник истины protocol + snapshot (§9.8).
